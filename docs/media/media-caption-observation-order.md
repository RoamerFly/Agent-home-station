# 媒体与后续说明的处理顺序

管理端版本：`0.24.1-media-caption-local`。

图片、视频或分享卡片进入后台观察后，后续短文字可能是同一内容的图注或补充。此前运行中复核只看到“收到图片”等占位文字，将后发短说明误判为替代请求，可在观察完成前取消下载/视觉分析，导致后续模型只针对文字回答。

修正：

- 媒体观察阶段继续接收消息，但不提前进行“任务是否过时”的模型复核。观察完成后，将真实观察与当时的后续会话资料带入主决策，并更新复核可见的原任务，避免复核仍使用占位文字。
- 将正在执行的原请求复核与“已生成但尚未发送的回复尾部”分开；前者使用独立语义和continue/cancel/delay契约，不能用替换旧文字的replace误取消整个媒体任务。
- 主模型根据完整内容决定回复或安静；图注不自动取消媒体，原请求者明确撤销/改变需求仍可在复核时取消。其他群成员不能用无关新话题撤销原发言者任务。未新增关键词分类器。
- 观察失败直接进入原有失败处理，不会被“等待观察后的复核”卡住；旧复核结果也不能覆盖新的观察上下文。
- 取消日志保留简短复核说明和实际依据消息编号，方便区分新请求替代、媒体读取失败与读懂后的安静。不是输出模型内部推理。

验证：合成回归覆盖“图片后跟短说明”、读取失败释放调度、其他群成员不能取消原请求，原有跨会话并行测试继续通过。额外提供显式开启的 TestLiveReceivedImageObservation，用现有联系人范围内的单条真实图片做下载与模型观察，不发送微信消息、不改真实会话记忆；实际图像和观察报告只保存在本机忽略目录，不提交仓库。
