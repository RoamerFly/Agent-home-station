# 翻唱的歌词、旋律与节拍对应

用户反馈的“唱错”是词曲节奏不对应，不能用音色、音频时长或ASR字面正确代替这项验收。

## 历史对照发现

测试群旧版采用一段较短的翻唱录音作为参考，使用`melody`模式与逐行歌词，YuE输出约一分钟；之后经过RVC换声。后来的私聊版本换成较长现场录音，使用`full`模式。长版准备时把多个ASR窗口直接连接，其中一处出现大段相邻重复。这使比较同时受到来源/编曲、参考范围、乐谱模式、歌词与乐句对应和随机采样的影响。

RVC主要影响音色，不能用它解释或修复“某句唱在错误旋律/节拍上”。旧版Comfy执行图未在当前进程历史中保留，不能把历史源码默认值冒充该次确切采样参数。私有任务、参考原件、YuE原始成品、换声成品和转换记录仍保留，未把真实歌词/聊天或原始音频提交到仓库。

## 本次调整

- 翻唱默认恢复`melody`，`full`仍可由Agent显式选择；默认原生女声及RVC明确授权条件保持。
- 精简`music_local_start`说明，避免把整份策略重复塞进工具说明。稳定音乐策略仍单独提供，明确同版重做优先复用同一已核对录音。
- 新增`lyric_timing_review`：以指定歌词依据的顺序报告粗时间范围、覆盖、间隙、重叠、逆序和相邻首尾重复。`music_reference_inspect`可传`lyrics_evidence_ids`在生成前读取组合诊断；不会静默删掉可能属于真实复唱的词。
- 移除最多十份歌词依据与一千份存储的任意配额，使三分钟歌曲可以采用十二个15秒观察窗；文件、来源和会话完整性仍验证。
- 字词比对仅证明提交词与依据相同，不证明有逐词时间戳或与旋律对齐。诊断明确返回`word_timestamps_verified=false`与`melody_alignment_verified=false`。

## 质量验证路径

对同一录音的同一乐段进行对照，先固定歌词、来源/范围和种子，再分别比较`melody/full`或文本引导强度，每次只改变一个因素。检查每句起止、停顿、音节数量与人声旋律的对应；换声只作为独立后处理。ASR跨窗重复要用更短、不重叠窗口和对应歌词版本核对，不能盲目连接，也不能因为重复字符串就自动删除副歌。

若同一参考乐段的符号转写已经错误，重采样音色或加女声标签无法修复；应检查乐谱提取结果或换取更清晰的同一演唱参考。当前诊断仍是粗窗口观察，并未交付强制逐音符/逐字同步演唱引擎；新的成品仍需听觉验证。本轮只分析历史录音与准备流程，没有新生成歌曲或自动发送对照音频。
