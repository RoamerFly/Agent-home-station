# 冲浪配文、关闭开关与本地歌曲复用

## 2026-10-29修复

一次主动短视频已取得微信接受回执，主模型也准备了配文，但后续通用未发文字复核取消了全部配文。通用复核只知道原冲浪指令与新消息，缺少附件已经发送的结构化证据。

配文现使用独立复核上下文：已接受附件的类型、标题、状态，以及已发文字、待发配文、新消息。模型仍可压缩、替换、延迟或因真实叫停/重复/错误取消，不固定生成配文，也不把元数据当视频画面。取消原因写入执行记录，便于区分模型决定与网络失败。

另修复冲浪后续唤醒清除`Surf`标记的问题。冲浪来源会贯穿后续唤醒、发送计划、媒体和文字补发；启动时可从旧唤醒父链恢复来源。关闭后不再启动相应唤醒或提交主动分享，已有不确定投递仍可核对旧回执，避免丢失已接受事实；不再创建补发尝试。普通用户当前请求、既有提醒和普通自主聊天不因这项开关全部关闭。

## 本地歌曲优先

听歌、原曲翻唱与参考做歌先用`media_recent(query=曲名,offset=0)`查询本会话已下载资源，核对原曲、歌手、版本、来源和`original_cached`。生成物另有`is_generated`和引擎字段，不能冒充原唱。已有匹配原件直接用于换声或参考，不再要求每个新曲名先联网。用户明确要求重新搜索、本地缺失或版本不匹配时仍可联网。

聊天保留期不再隐藏仍有缓存原件的目录项，也不阻止复用其原件；真正读取时仍核对内容哈希。只剩外部临时引用且无原件的旧记录维持原有保留行为。账号和会话边界不改变，跨会话由真实管理员通过已有索引和跨会话工具调度。

## 验证范围

合成回归覆盖关闭后的旧唤醒父链、开启时来源保留与身份清空、配文接收已发送视频证据、实际进入假发送器、旧缓存仍可检索以及会话隔离。

两项显式实模型检查均不发送微信：`TestLiveSurfAcceptedVideoRetainsCaptionUnlessStopped`中模型对普通互聊选择继续配文，对明确叫停选择取消；`TestLiveMusicUsesCachedOriginalBeforeOnlineSearch`中模型先查本地，复用精确原录音向合成后端提交一次，网络搜索为0次。这验证了本轮模型选择与调用链，不把合成发送器视为真实手机验收。

实模型测试通过环境变量显式运行，常规CI跳过：前者使用`WECHAT_SURF_CAPTION_LIVE=1`，后者`WECHAT_LOCAL_MUSIC_LIVE=1`，并设置`WECHAT_LIVE_MEDIA_ROOT`。所有真实配置留在本机。历史已取消配文不自动复活，避免过时分享或重复补发。
