# 本地 YuE 服务运行与故障恢复

Windows 本地验证使用两段服务：`6188` 鉴权桥接 → `127.0.0.1:8188` ComfyUI → YuE 模型。管理端在 Linux 中运行，与桥接通过 WSL 主机地址连接。主机地址变化后需调整网页中的桥接地址，不能使用 Linux 自己的 localhost 指代 Windows 服务。

运行 `scripts/Start-Local-YuE.ps1` 会启动缺失的服务和一个隐藏的 PowerShell 守护进程；已有 Python 进程仍在初始化时不重复启动。守护每10秒检查端口，缺失时尝试恢复，启动失败30秒后再检查。命名互斥锁避免同一工作区重复守护。它只恢复退出的进程，不会杀死仍存活但初始化缓慢的生成后端，也不自动重提生成任务。

状态在私有运行文件 `temp/yue-watchdog.json`，进程输出在 `temp/yue-{comfy,bridge}.{stdout,stderr}.log`。需要停止守护时创建 `secrets/yue-watchdog.stop`，守护随后退出；再次启用前移走该标记。

后续运行发现，临时开发会话启动的桥接、ComfyUI和守护进程会一起退出，不能把会话内守护视为可靠托管。现使用 PowerShell 7 执行 `scripts/Install-Local-YuE-Service.ps1`，为本工作区注册当前用户的 `WechatAgent-YuE-*` Windows计划任务，登录时启动、失败1分钟后恢复，无执行时间上限，不保存用户密码、不提升权限。任务通过隐藏守护拉起服务，已有任务时启动脚本优先复用。Windows用户注销/机器关机后本机生成仍不可用，云端部署需要另行托管生成服务；没有声称本机服务已具备服务器级高可用。

服务商页“完整歌曲生成”中的“检查本地歌曲服务”会从管理端的真实网络环境验证桥接鉴权与 ComfyUI 就绪情况，区分未启用、未配置、连接/鉴权失败、生成后端未就绪与就绪。这个检查不创建歌曲、不调用付费模型、不发微信。

生成前先做5秒有界就绪检查。检查失败不会创建本地生成任务或领取有副作用的操作记录；提交后结果不确定仍保留待核对，不能自动重复生成。没有有效生成任务编号时，工具不会再返回成功。桥接自己也会在新建任务前检查 ComfyUI，已有幂等结果不依赖后端在线。

2026-10-25 故障证据：测试群16:11及16:15附近两次 `music_local_start` 没有取得任务编号；检查时6188与8188均无监听，相关 Python 进程均不在运行。旧日志停在此前一次正常生成完成，不能据此判断退出来自人工关闭、宿主生命周期还是其他原因。恢复后 Windows 与管理端 Linux 均通过真实鉴权健康检查；10秒诊断歌曲实际生成完成，847269字节，未向微信发送。确认没有运行中的生成任务后，仅结束桥接做受控恢复测试，守护已自动拉起新的桥接进程，原任务记录保留。没有补发群消息，也没有把历史失败任务当作成功。

随后“忘情牛肉面”已真实生成60秒、5847732字节，桥接退出导致已完成任务无法查询，原音频未丢失。计划任务恢复后自动查询了同一个生成任务，准备并向原请求群交付一段语音，取得微信接受回执。没有重新生成；手机播放仍由用户确认。后置文字没有完成不应被解读为语音失败，管理任务结果会明确区分附件已接受与文字说明未完成。

YuE调用日志新增固定错误码，区分桥接离线、鉴权、ComfyUI未就绪、任务编号不存在/跨会话和提交结果未知；不输出任意上游正文或密钥。等待中任务保留相同任务编号，服务恢复后读取已有完成音频。这个恢复不需要再次启动模型生成。
