# 任务、工具会话与上下文优化检查点

## 任务与交付

生成完成后进入交付中，而不是直接标记整个请求完成。附件排队、语音分段回执、部分接受、全部接受、失败、未知结果分别保留；只有预期附件和后置文字全部取得所需证据才完成。交付对象绑定原请求、任务、账号和会话，重启读取原状态。已经产生交付记录的任务不能通过“恢复执行”再生成一遍；需要核对或恢复原发送记录。

用户的时长、交付格式、标题由模型作为工具参数给出；程序验证范围、权限、实际生成时长和文件可用性。默认完整分段语音，每条不超过60秒；需要文件时复用原音频，明确双格式则串行交付。仍有旧的音乐承诺检查器用于发现纯文本承诺代替工具执行，后续继续缩减此处语义启发式；不能宣称整个系统已没有关键词判断。

## MCP 生命周期

正常聊天按平台/账号/会话保持独立MCP连接。stdio进程初始化一次，同会话后续工具调用复用；HTTP保留会话头。工具发现缓存30秒，单Hub最多32个会话，5分钟空闲关闭。一次连接串行RPC，等待锁时可以取消，活动请求超时或传输失败会废弃连接，不自动重播副作用不确定的工具调用。后续新发现/调用可以初始化新连接。运行重载/退出会关闭所属连接。

stdio只继承基础运行环境和管理员明确配置的env，不继承其他服务商的任意环境密钥。Linux取消进程组；Windows取消进程树；其他平台只能保证结束直接子进程。预演和手动检查继续使用短会话，不能用预演结果证明常驻运行时的全部状态。

## 上下文

新的压缩结果必须是version=1的对象，具有有界的人物、话题、当前焦点、媒体、待办、偏好、更正字段。JSON标量、字段类型错误、未知字段和超量结果不会提交，也不会推进压缩覆盖位置；原始消息保留。旧版本已保存的同名字段摘要兼容保留，在下次成功压缩时升级。

所有模型接入方式都对近期历史和摘要执行同一字节预算，优先近期消息；摘要与原始消息分别标为资料，覆盖的旧原文不会再加载。预算是历史上下文UTF-8字节数，不是模型精确Token数，也不包含系统指令、当前请求和后续工具结果。真实模型使用合成记忆验证：20条压缩、25条原始记录保留、schema校验通过，没有读取真实聊天或发送微信。

## 仍需继续推进

素材转换链与多人引用指代的完整场景回归、异步插件取消/完成契约统一、可恢复归档与容量管理仍在持续目标内。现有硬性存储上限不等于已经实现自动归档。服务器完整命令仍以管理端系统用户权限执行，授权目录是文件工具边界和Shell起始目录，不是系统隔离沙箱。视频号实际理解受授权播放信息限制，详见 `channels-content-understanding.md`。
