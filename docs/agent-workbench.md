# Agent 工作台精简

2026-10-26，本机管理端版本 `0.20.0-agent-workbench-local`。

## 页面与设置

工作台以行为文档、持续任务和后台进程为主，角色、模型服务和手机执行端保留独立入口。已结束任务收进历史，不占用主工作区。仍沿用既有鲸鱼主题、明暗切换与移动端导航。

从 HTML 移除56个静态表单控件，数字输入由36个降至4个（模型输出及费用单价）；不是把旧控件隐藏起来。动态生成的冲浪权重和逐目标问候预算输入也已删除。

移除网页上的每轮行动步数、任务保存开关、任务续行次数、记忆开关/条数/天数、压缩阈值、发送节奏与故障重试细项、连续发言细项、手机轮数与时限、旧MCP预算、冲浪预算/层数/权重等调优项。保留身份与跨会话授权、主机权限、媒体发送类型、主动目标和安静时段，以及必要的模型/API/MCP/设备连接配置。

保存角色时启用角色、文字对话、已允许会话的群聊观察/自主接话和本地记忆；群与好友白名单、媒体发送权限、主动目标、主人身份、跨会话与主机权限继续单独落实。Agent权限保存启用通用行动、任务与会话读取。**页面打开本身不改配置，也不创建任务。**

既有发送间隔、记忆保留范围、上下文压缩设置、任务预算、手机时限和来源权重等兼容字段保留在后端配置。前端通过原设置合并修改，避免删除控件后把旧值、密钥或其他服务配置清空。未声称所有历史参数已从执行器移除：每轮30次工具调用是内部防止无限循环的上限，Agent可通过持久任务或后台程序处理长工作，旧的低行动数不再限制Agent运行时。既有主动调度预算及安静时段仍有效。

## 行动与修复反馈

新增只读 `music_service_status`，查询真实YuE桥接/生成后端健康，不提交歌曲。桥接离线错误提示模型读取项目指南、在正确系统节点排查，并区分诊断、修复、健康验证和生成任务提交。主人的行动请求要求说明实际动作、验证结果和剩余问题；不能把一次成功的目录检查当成完成修复。

实际本机运行节点、启动入口及主人相关授权只在私有指南/配置维护，不放入仓库。公网 `web_fetch` 保留其公网访问边界，本地服务使用专用状态工具或已授权主机命令。

## 验证边界

浏览器测试使用真实部署页面读取状态，拦截所有测试保存请求：14个页面、375/768/1440宽度及明暗主题无横向溢出、无JavaScript错误；旧控件确实不存在；角色/权限/MCP/冲浪保存内容保留原技术设置，密钥空更新不清除旧值。另验证草稿、版本冲突与滚动位置。

真实模型在隔离管理实例中读取实际共享指南及项目启动脚本，调用真实服务健康检查并给出结果；工具限制为只读，没有更改项目、生成歌曲或发送微信。故意限制读取范围，其他文档读取失败不代表生产环境没有相应权限。

本轮管理员另恢复了已有本机YuE守护任务，桥接与生成后端健康检查通过，并按用户要求向原群发送一条说明，取得微信接受回执；该管理员发送不作为Agent自主完成修复的证据，也不代表歌曲已生成。原生微信登录、历史记忆、模型与生成媒体保留；未构建Docker镜像或发布版本。

## 发送异常的自动恢复

媒体回执不确定不再只检查两次便永久搁置：按随机指数退避持续查询原任务，延迟出现的回执可完成同一条交付；已接受分段保留。原生明确标记retryable的失败可以继续对同一任务尝试，不再被网页的一次上限截断。原生禁止重放的未确认上传不会换新编号整份重发。

向模型提供当前会话的 `wechat_delivery_status` 和可信主人的 `wechat_delivery_retry`。部分语音回执长期不确定时，保存唯一恢复检查点交回Agent，带上原任务编号及接受段数，要求检查状态、排查并反馈；不重复生成歌曲。主人直接要求的持续任务属于原请求续办，执行前重新校验身份与会话，单独于主动问候的开关/目标/安静时段；普通主动任务仍遵守原约束。撤销主人授权会停止这类续办。

只等待未知回执的队列允许安全更新管理端，重启后保留并继续核对；不会为了完成更新而取消或重建这些原任务。此前因两次核对被停放、且未被用户取消的对应任务，在启用原有不确定结果恢复策略时恢复只读核对。接受回执、手机收件和播放仍是不同证据，不能把“正在恢复”记录成“已送达”。
