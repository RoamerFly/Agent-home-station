# 本地历史归档与容量

版本：0.11.0-history-archive-local。归档只保存在管理端私有数据目录，不上传Git或模型，不发送到微信。

## 保留和恢复阅读

记忆超过管理员设定的条数/天数时，先把将移出的正文和媒体元数据写入 `companion/archive/memory/<scope>/`，读回通过校验后再保存缩减后的 `companion/memory.json`。压缩摘要与近期上下文继续使用现有预算，归档不会自动回灌给模型。旧消息可以在“记忆管理→选择会话→历史记忆归档”阅读或下载JSON副本；这里的恢复是恢复阅读/导出，不是重新执行任务或发送。

活动日志保留最近7天、最多1000条。条数达到上限时按128条轮转，因此正常活跃窗口为873–1000条，避免每写一条日志就生成一个归档文件。被移出的完整日志先保存到 `archive/activity/<instance-scope>/`，再更新 `activity.json`。系统日志页底部可展开历史日志归档，不参与跟随最新日志刷新。旧版活动记录没有可靠账号字段，日志归档明确属于本管理实例，不能伪称按微信账号隔离；记忆归档则严格校验平台、账号和会话。

归档为不可变的gzip JSON批次，以解压后内容的SHA-256作为编号；同一批次重试不重复落盘。写入采用私有临时文件、同步、原子替换、读回校验。读取限制解压大小，检查类型、scope和摘要，不接受路径穿越或归档目录内的符号链接。它是本机压缩存储，不是加密存储。崩溃发生在归档完成、活跃文件提交之前时，可能短暂存在重叠快照，原内容不会因第二次写失败而被丢弃。

归档失败时不裁剪原记忆；日志保留未裁剪记录并显示存储错误。日志故障缓冲仍有20000条/32MiB上限，达到上限或磁盘不可写时不能承诺保存新日志，需要处理磁盘/权限问题。内存中日志可以继续增长，不能把此缓冲当作磁盘故障的无限容错。已被旧版本策略删除的正文无法凭空恢复。

“清除这个会话的活跃AI记忆”同时清除正文、关系备注和压缩摘要，但保留只读归档与微信记录，确认框明确说明这一点；归档不会因此进入模型。归档为当时的快照，媒体后续状态以较新的交付记录为准。

## 管理页容量

总览的“存储与归档”按需扫描活跃记忆、日志、任务/素材索引、媒体原件、归档和收件状态，显示字节/文件数及任务等记录上限。扫描不跟随符号链接，有时间和文件数边界；失败时显示未完成，不报告伪造总量。统计不包括外部YuE环境、模型、微信原生库及其媒体，也不等同于整个服务器磁盘占用或剩余空间。

本阶段不删除下载/生成媒体，不清理尚在使用的上传材料，不重置任务/发送幂等记录。归档降低活跃JSON体积，但会增加总磁盘占用，尚未实现归档自动过期和任务账本压缩；任务和附件索引的硬上限仍需后续完善。下载副本需要已登录管理员，读取不创建发送任务。

## 验证

合成数据测试覆盖保留期与条数轮转、文字/语音素材关联、重启读回、归档失败保留原文件、校验篡改拒绝、分页、跨scope/账号拒绝、路径和符号链接拒绝、清除摘要、带鉴权的只读JSON导出。真实浏览器在隔离测试服务中验证容量、记忆归档、日志正文与下载入口；不访问真实微信登录或外发。当前源码检查和本机部署结果以对应提交及CI为准。
