# 媒体关联、转换链与完整复用

2026-10-25，0.9.8-surf-control-local。

## 本轮修复

- 素材保留第一条请求与有界的最近请求关联：原请求编号、发言者、任务和简短原始需求。异步歌曲交付携带原请求，避免把内部交付说明当作用户原话。
- 媒体记忆携带请求人、原请求、父素材和实际缓存 MIME；恢复、回执更新不会清空已知信息。旧记忆只按精确会话/素材 ID 补齐已知元数据，不猜测缺失的历史原视频。
- 最近媒体焦点按同请求、同素材、同格式合并多个上传材料，防止一首长歌挤掉其他群友的素材；部分取得回执的附件也可成为焦点，但不能将其称作全部送达。
- 微信精确引用保留原卡片的 URL；引用自己发过的分享卡片无需已有缓存 asset_id。精确引用优先于最近媒体，随后由模型结合请求人和上下文决定素材，不新增固定自然语言路由。
- 公开视频提取音轨时保留已经下载的原视频父素材；音轨以 parent_asset_id 指向它。模型可以直接复用父素材为文件，不必重复下载或搜索。
- 同一份原音频的全部语音上传材料按顺序一起提交素材索引，后续完整复用不会只留下最后一份。每份上传材料最多300秒，由原生微信后台进一步分为不超过60秒的消息。
- 旧索引只有最后一份语音、但完整音频缓存仍在时，本地校验原文件并重建完整材料；没有完整原文件的旧记录仍保持证据边界。
- 模型选择复用与旧关键词“新资源”提示冲突时，使用有界语义校验，不因“再发一遍”含“发一”而强制搜新歌；明确要新歌仍不能拿旧曲替代。模型选择安静不会被已准备的附件强行改成回复。
- media_recent 增加精确素材、请求人（self 指当前发言者）、标题筛选。目录按模型结果预算返回完整 JSON，不截断成半份索引；目录不是所有历史文件的全集，旧素材可进一步筛选。

## 边界

素材仍限定当前平台/账号/会话。组内不同群友可以明确索要同一组内素材；请求人用于帮助模型理解，不是群内私有文件授权系统。其他群不能列出或复用。来源、格式、暂存、微信接受和手机播放是不同证据层级。

缓存索引仍有1000项、逻辑总量512MiB、单文件64MiB上限。新增请求/格式字段后索引 JSON 上限16MiB，读写采用相同限制；父视频计入总量，不删除已有素材腾空间。自动归档和容量管理仍在长期目标中，不能把硬限制当成已完成归档。

## 验证

- 合成故障/恢复验证：请求关联持久化、媒体回执更新、跨会话隔离、整组语音顺序、替换材料不会混入旧段、卡片引用来源保留、旧索引70秒音频完整重建。
- 三例真实模型、合成会话与模拟暂存：当前群友索要自己的原音频、引用另一位群友音轨后索要父视频、完整语音重发；均选中正确素材，最后一例返回全部两份材料，不再联网搜索替代曲目。
