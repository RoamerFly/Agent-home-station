# 管理后台重构 · 2026-10-27

当前采用六个主入口，默认进入覆盖24个环节的可编辑流程工作台；会话与执行回合再次独立。参见 [节点工作台与优化路径](node-workbench.md) 和 [会话工作区](conversation-workspace.md)。下文保留 0.26 初版设计的取舍背景，不能用其中的旧导航名称替代当前界面；节点属性、关联配置、会话详情与执行过程使用大弹窗。

## 目标与设计取舍

这是照看一个微信 Agent 的日常控制台。进入后首先回答：是否在线、刚才做了什么、现在需要处理什么。保持原生 HTML/JavaScript 与 Go 内嵌资源，不引入前端运行时和额外部署步骤。

使用项目级 UI UX Pro Max（官方上游 `28b3b8d`）与 Frontend Design。Skill 的设计系统检索返回了适用于管理台的简约布局、低装饰与可访问性建议，但页面模式仍偏营销网站；重试后的模式也不适合内部操作台。因此不采用其 hero/CTA 模板，以下为针对本项目制定的设计规范。

## 信息架构

| 主入口 | 子页面 |
| --- | --- |
| 总览 | 微信与 Agent 状态、用量和费用 |
| 执行回合 | 按消息/任务关联的流程、独立系统时段 |
| 会话 | 目录、聊天记忆、回复规则、手动发送 |
| 角色 | 人设、持续任务与工作文档、AI 网上冲浪 |
| 能力 | 模型与语音、工具、MCP、权限、手机探索 |
| 系统 | 微信登录、账号操作、密码、存储 |

旧 hash 地址继续有效。功能保留，通过分组和渐进展开降低同时出现的窗口与按钮数量。各类配置继续使用现有独立保存接口，不把未保存值静默写入服务器。

## 视觉规范

- 主题：海盐白与深海蓝；鲸鱼角色仅用于身份与首页的小幅插画，不铺满工作区。
- 色彩：浅色背景 `#F6F8FA`、表面 `#FFFFFF`、文字 `#172B3A`、强调 `#146D88`、边界 `#DCE5EA`、失败 `#B93845`。深色使用独立语义变量。
- 字体：系统中文字体搭配 Segoe UI；无远程字体依赖。标题 22px、正文 14–15px、辅助文字至少 12px。
- 布局：窄导航 + 单行页头 + 页内分组；内容最大宽 1560px；小屏使用原有可键盘操作的抽屉。
- 主操作明确，维护/实验/手动诊断默认折叠；不增加审批步骤或限制 Agent 能力。
- 普通面板使用细线与留白，不使用大面积渐变、重复标语或夸张投影。

## 执行回合

主列表一行只对应一个有明确标识的回合。摘要显示来源、首条消息、当前结果、步骤数、工具数、时间跨度。展开后展示发送结果与按时间排列的接收、判断、工具、发送步骤，可继续展开原始事件技术字段。

关联仅使用同一会话的消息 ID、明确的同回合补充消息关系，以及不冲突的发送 ID；不按时间相近猜测。没有可关联标识的历史系统事件按服务启动/日期归为独立系统时段，不能伪装成某个群聊的工具操作。筛选针对整个回合，匹配到工具异常时仍保留完整过程。

默认不跟随新记录。轮询只提示有新进展，用户载入时保留展开项、列表位置和页面位置；只有主动开启跟随最新才移动到列表顶部。分批渲染回合，避免大量历史步骤同时占用 DOM。

## 验收边界

用合成记录验证跨群隔离、补充消息关联、工具失败后恢复、发送回执更新、历史无标识事件，以及真实浏览器中的明暗主题、窄屏、筛选和滚动。升级仅替换管理端程序，不改变微信登录、权限、角色或历史数据。不发送真实微信测试消息，不导出镜像。

- 本机管理端版本 `0.26.0-round-console-local`，更新后微信原生连接在线；配置哈希一致。

“微信已接受”只表示取得服务端接受回执，不代表收件人已经播放或阅读。历史无标识的事件仍可查看，但无法补造缺失的回合关联。
