# 微信执行回合

工作站微信详细配置中的「执行回合」按接收消息显示卡片。卡片直接展示收到的消息和按时间排列的处理过程，长文字保留换行与全文；「单独查看」打开同一回合的阅读窗口。

## 逐次查看工具执行

每次工具调用分别留下开始、完成、失败或取消记录。同一工具连续调用也分别显示；只读调用发生重试时，保留失败、等待重试和后续尝试。记录显示实际工具名称、当前状态、尝试次数及已记录耗时，步骤数量或调用总数不替代这些行。

卡片自动分批补齐本回合仍保留的步骤，读取中显示状态，失败保留已加载步骤并提供重试。日期与「较早记录」继续用于选择其他回合。超出本机保留范围的步骤、升级前未保存的工具细节不能恢复成虚构记录。

工具调用完成表示该次调用返回，不代表后台生成任务完成或微信收件人已阅读。微信发送仍以原有投递回执为准；「微信已接受」不代表手机已播放音频。

## 消息来源与范围

主人查看执行回合仅投影该连接已获准接收、已经观察且仍可核对的消息。它不增加 Agent 的聊天记录搜索权限，也不把未观察的历史正文载入模型。撤销会话范围、清除来源、正文发生冲突或切换账号后，旧正文不再展示。

消息原文按当前原生账号、会话、发送者和已保存的来源核对。文字显示正文；语音、图片、视频等未记录可读正文时显示消息类型，分享卡片不直接显示原始 XML。工具日志仅保存结构化执行信息，不复制工具参数、结果正文、凭据或模型推理。

## 验证入口

- `python scripts/test_wechat_rounds_ui.py --help`：合成桌面回放，覆盖长消息、逐次工具调用、跨页过程、读取重试与账号切换。
- `python scripts/test_local_process_ui.py --help`：既有本机工具界面与执行回合回归。
- Go 的 `RoundCard`、`WechatExecutionRounds` 与工具观察专项测试覆盖持久化、消息来源和调用记录。

以上回归使用合成消息和临时资料目录，不向真实微信账号发送消息。
