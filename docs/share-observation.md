# 分享实际内容观察

2026-10-26，本机版本 `0.17.0-share-observation-local`。

## 问题与行为

此前 type=49 卡片仅微信视频号有实际视频读取。快手等普通分享只提取标题和简介，模型因此会问“视频里是什么”，没有打开作品。现改为统一入口：在授权会话内读取原链接，取得实际资料后再交给角色决定是否回应。

1. 微信视频号：保留已验证的原生短链和元宝授权解析路径。
2. B站普通 BV 页/b23 短链：复用公开播放文件解析；接收观察不受“一分钟以上发送链接”的交付规则影响。
3. 快手 `v.m.chenzhongtech.com/fw/photo/{id}` 与 `kuaishou.com/short-video/{id}`：保留原卡片的完整分享参数，仅在读取请求中使用，解析公开页中同一作品 ID 的状态和媒体。支持有界 Apollo 引用，拒绝把推荐作品当作当前作品。
4. 其他 HTTP(S) 链接：尝试实际网页正文、图片、视频直链及网页显式 Open Graph 视频。只返回标题、短应用壳或视频卡片未取得可验证媒体时，标记需要浏览器/登录/App，不按标题生成回复。

所有 HTTP 请求和跳转复用公开地址校验、DNS 公网校验、超时、大小和有限恢复机制；没有引入任意脚本执行、登录态复制、验证码处理或证书/代理修改。

“所有链接进入同一处理流程”不等于“任何网站均可读成功”。需要客户端渲染、登录、动态签名或 App 的作品目前可能不可读，后续由手机/浏览器执行端补充，不能把尚未实现的路径当作现有能力。

## 视频与记忆

- 取得视频实际字节，验证媒体格式和容器，均匀抽取最多六帧；音轨独立转写最多前180秒，明确显示实际覆盖范围。
- 画面与音轨任一成功可形成部分观察；两者均未取得时，保留未完成原因。
- 成功观察后卡片描述不再带“尚未观看”的矛盾前缀。对发布者说法保留未独立核实的边界。
- 允许记忆时缓存本会话原视频，关联原消息和发言者，后续可通过素材工具复用。缓存失败不抹掉已成功取得的观察。
- 视频观察持久化为文字时，分别为来源、画面和音轨保留预算，避免画面描述占满记忆而擦掉音轨。
- 实际内容不可读时，接收和失败状态进入日志及记忆；同步与后台模式均停止标题评论。
- `POST /api/companion/memory/{scope}/observe-share` 对指定原卡片重新观察并更新同一条记忆，校验账号、会话、发送方向和权限，不发送微信消息。
- 手动 `reply-share` 也必须先取得实际观察；只读到卡片不会生成补充回复。旧的卡片元数据刷新不覆盖已存在的真实观察。

## 验证边界

真实收到的一条快手分享，已通过原链接取得约12.7 MB的MP4，容器约169.6秒；配置的视觉模型取得六帧观察，百炼取得接近全长的音轨转写。测试为隔离诊断，无微信发送。原始消息、参数、媒体与模型输出仅保存于忽略的私有证据目录。

代码回归覆盖：确切作品身份、非法域名/URL、引用解析、实际正文与媒体提取、失败保留、同步/后台模式阻止标题评论、记忆刷新保留音轨、权限与手动观察范围。平台解析存在结构变化风险；未声称全部平台已真实验证。
