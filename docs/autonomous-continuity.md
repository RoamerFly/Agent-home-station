# 自主续聊与可续执行任务

版本：`0.30.0-autonomous-continuity-local`。

## 自主评估与实际发送分开

已授权目标继续使用 `companion.proactive_threads`；主动权限和安静时段仍生效。升级不会新增目标，也不会打开已关闭的网上冲浪。

- 不再用全局或单会话每日次数拒绝自主评估。旧的 `proactive_max_per_day` 和规则 `max_per_day` 保留兼容读取，不执行额度检查。
- `proactive_idle_minutes` / 规则 `idle_minutes` 现在是默认评估间隔基数，不再要求群聊先无人说话。领取评估时持久保存下一次时间，随机范围为基数的 0.5 倍至不足 1.5 倍。
- 普通群消息更新活动信息，但不推迟既定自主评估；该群正在生成或发送时，调度等待。未来计划不阻塞正常默认评估，既有计划资料会提供给模型；模型返回新的时间可替换旧的待评估计划。
- 模型可以接话、发现并使用已有工具探索新内容，也可以安静。安静不减少未来机会，也不会立即再次触发模型。
- 状态接口区分评估次数、安静、回复计划、模型失败和取得接受回执的轮次。接受轮次表示至少有一项实际接受记录，不表示该轮全部附件已完成或手机已播放。旧日志不追溯生成这些新统计。

## 模型自主计划

最终 `reply` 或 `silent` 可以返回：

```json
{"action":"silent","messages":[],"wake_after_seconds":7200,"wake_reason":"晚些跟进刚聊的新歌","wait_for_reply":true}
```

`wake_after_seconds` 为正整数秒；原 `wake_min_seconds` / `wake_max_seconds` 仅作为提示建议范围，不截断显式参数。实际整数必须可转换为 Go 的时间跨度。`wake_reason` 为不超过 1024 字节的计划说明，超长时返回通用重新评估说明。

计划持久保存，唤醒时带上计划说明和最新上下文；允许唤醒后继续安排后续。等待安静时段结束或服务短暂离线不会因为旧的 5–10 分钟有效期直接丢弃尚未执行的计划。原发言者已回复时可取消等待，群内其他人的插话不自动视为该人回复。

唤醒是新的自主评估，不继承原发言者的主人身份、原命令或服务器操作权限。原主人明确要求的后台任务仍由已有的持久任务机制保留授权并续办。已执行但重启中断的唤醒不会盲目重放副作用；发送和程序操作继续使用各自的持久状态及幂等机制。计划队列仍受存储容量约束，满时记录明确原因。

## 长任务、输出与观察失败

- `companion.conversation.task_timeout_seconds` 默认 `0`：继承 Worker 取消，不再统一 15 分钟终止整轮。可显式设置任务总超时，单次提供方/工具请求仍保留自己的超时。
- `max_bubbles` 为文本条数建议；不再因超过该值或超过 3 个媒体 ID 拒绝整轮。格式校验、未发送尾部修改、持久队列重启读取同步取消同类数量判断。
- 多条文本/附件仍进入既有发送队列，保留逐条动态间隔、当前权限复核、用户叫停和接受回执确认。媒体 ID 必须来自真实可用素材；不能编造。
- 媒体预读取失败交给主 Agent：包括已知失败状态、可用的部分观察和继续读取方法。模型可发现工具、重试或换方法，也可以诚实说明或安静。预读取失败不再直接跳过主模型；失败日志不标为“已理解”。
- 并发槽位、实际提供方请求大小、单条文字长度和持久文件体积仍是资源/传输边界，不宣称全部限制已经消失。

## 验证范围

合成回归覆盖：超过原每日额度后继续评估、群内活动不推迟计划、随机下一次时间与重启保存、长时间唤醒和再次安排、安静时段等待、不同发言者隔离、主人身份不继承、多条计划重启恢复、媒体失败送入模型，以及回复计划与真实接受记录分开计数。

`WECHAT_AUTONOMY_LIVE_ROOT` 可启用 `TestLiveAutonomousPlanningWithoutSending`：只对合成群聊调用当前配置的大模型，不读取真实聊天、不写入运行中记忆、不执行工具、不发送微信。该检查证明模型能产出自主计划，不证明长期群聊自然程度。
