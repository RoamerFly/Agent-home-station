# 不确定文字发送的持续恢复

开启“结果不确定时延迟核对并恢复发送”后，正式文字回复不再受一次补发上限或24小时上限限制。状态、补发次数、历史幂等键、连续不确定次数、下一次执行时间保存在本地队列，重启后继续。

每次提交未获得确定结果时，按设置的基础等待秒数进行指数退避并加随机量：第1轮为基础值到2倍，第2轮为2倍到4倍，之后翻倍；达到上限后每轮随机等待1–2小时。默认基础值120秒。日志记录已补发次数和下一次核对时间。

每轮先检查全部历史发送回执，任何一次已接受就结束；原生仍在发送则继续等待。再读取同一会话的同步消息，两次健康且完整的扫描未观察到对应发言，才允许再提交。回执查询或同步不可用时只等待，不将查询失败当作未送达。原生幂等键未知时复用同一键；确有不确定任务时保存旧键并使用新重试键。

本地模型记忆不能证明微信收件人已收到。该策略是用户授权的至少一次交付尝试；回执和同步都延迟时仍可能重复，不能提供严格恰好一次保证。微信明确拒绝、管理员撤销会话权限、用户取消任务仍会终止；关闭自动补发会保留待核对任务。已接受的语音或附件不会因说明文字失败而重发。过时的“收到/正在做”过程提示维持原有过期策略，避免任务完成后迟到。

后台任务的引用回复使用原始微信消息编号，任务跟踪编号仅用于日志与队列。明确的引用准入拒绝单独记录原因，不再误报成发送不确定。

## 历史消息复核

管理员明确要求逐条经过模型的历史收件可在持久化收件记录标注 `owner_model_review`。该标记跳过普通闲聊判断冷却和短消息聚合，不伪造@、不强制回复，仍受会话、观察权限、安静时段和预算限制。成功模型判断可以选择安静；已经完成并被微信接受的消息不重新排队。

## 模型知情与发送节奏

每轮正式文字补发前，向模型提供原文、未确认原因、补发次数、最近对话和已确认的附件。复核不能执行工具；模型可沿用、改写、延后，只有有理由的撤销/过时才停止。复核失败继续退避，不绕过模型机械重发。改写前的正文与幂等键保留，任何历史版本迟到的回执或同步消息都能终止后续补发。

机器人队列中的文字、过程提示、重发和媒体共用持久化的会话发送间隔。提交时预留间隔，确认附件完成后再次从完成时刻计算间隔；因此不会在语音刚确认后立刻提交说明文字。间隔沿用网页的随机等待设置，最低1秒。分段语音的录制时长与分段节奏仍由原生语音任务执行。这不能保证消除网络、回执或微信端拒绝。
