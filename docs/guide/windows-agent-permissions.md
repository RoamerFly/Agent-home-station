# Windows Agent 权限与受管项目修复

## 本次故障

2026-10-30 22:36（北京时间），Agent 调用 `server_windows_process`，以源码仓库根目录作为工作目录，收到“路径不在已授权工作目录内”。紧接着在当前会话的受管工作区执行命令成功。前一结果说明越界拒绝生效，不能推论 E 盘不可读或需要将整个仓库授权给 Agent。

已登记的 GPT-SoVITS、RVC、YuE 项目入口、解释器和公共模型均在 `data/managed-workspaces/public_workspace`；账号私有声线在该账号的 private workspace。`project_list`、`project_read` 返回精确路径，`voice_library_read`、`voice_library_prepare` 返回选定声线及文件。Windows 的通用长程序入口为 `server_windows_process`；命名语音优先使用 `speech_synthesize(voice_id,text)`。不依赖源码仓库根目录执行这些功能。

同次群聊收到的 `model_generation_failed` 是另一种状态。旧代码把模型的原始错误转为私聊状态报告时丢失了本地诊断，因此现有记录无法证明它由路径拒绝导致。新代码先保存模型错误诊断，再生成简短私聊报告。

## 权限矩阵

| 身份与调用 | 可访问范围 | 不可访问范围 |
| --- | --- | --- |
| 普通已授权会话 | 该账号、该会话的工作区；公共项目、模型和运行时只读 | 其他会话私有文件、其他账号、管理凭据、源码仓库 |
| 可信主人，当前会话 | 当前会话工作区及本账号公共工作区 | 其他账号、管理凭据、源码仓库 |
| 可信主人，单次 `global=true` | 本账号 private 与公共工作区，用于选定的私有声线和输出 | 其他账号、管理凭据、源码仓库；该权限不保存为会话默认值 |
| 命名音乐/GPU 后端 | 已登记运行时、模型和本账号输出；单独授权的注册表读取及私有网络策略 | 普通 Agent 命令不会继承音乐后端的额外能力 |

调用前按当前真实发送者、账号、会话、权限和任务状态重新核验；网页、聊天引用、模型摘要及昵称不能扩展权限。Windows LPAC 对子进程和文件挂载执行边界，目录工具仍按根目录核验。`gpu=true` 只对该次执行生效，不改变其他调用。撤权后持久任务不应继续使用旧权限。

## 修复顺序和验收

1. **诊断**：将实际 `server_windows_process` 参数与失败回执、同一回合成功的受管路径、项目登记清单对齐；模型失败保留提供商诊断，不把一个工具拒绝当成全部失败原因。
2. **引导**：Windows 工具说明、声线清单和共享工作区指南使用 `server_windows_process` 与受管工作区路径；越界拒绝给出 `project_list/project_read` 查找入口。历史共享指南只替换已知过时句子，保留用户自行编辑的其他内容。
3. **隔离执行器**：普通程序不请求 stderr 诊断时传入真正的空接口，避免带类型空指针引发崩溃；命名模型仍在受信后端保存有限诊断。
4. **权限回归**：隔离测试覆盖合法工作区读写、公共项目只读、外部文件读写拒绝、Unicode 参数、取消；管理测试覆盖主人单次 global、普通成员和撤权。项目清单的训练入口应落在受管路径，不以仓库根目录代替。
5. **本机启用**：先完成源码测试和本机隔离测试，再排空在途任务、备份、更新程序与项目说明；重启后核对登录、模型和记忆，再运行合成且不发送微信的能力测试。实际微信接收和手机播放分别记录。

保留源码仓库与凭据隔离。若未来确需让 Agent 修改某个工程，把明确挑选、可审计的工程副本登记到公共项目工作区；不得因一次路径错误把整盘或本程序的控制目录加入通用 Agent 根目录。
