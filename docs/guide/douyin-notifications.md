# 抖音互动通知的本机读取

入口为工作站「抖音 → 详细配置 → 互动任务 → 平台互动通知」。打开分区不会读取平台通知。先核对并绑定保存的网页登录账号；绑定操作只探测身份。每次读取或续读都需要明确点击「读取并标记已读」，因为当前官方网页的通知列表请求可能同时标记已读。

每次默认读取一批，可选择 1–5 批。这是单次浏览器操作的批量资源边界；抖音原生页面当前每批请求 `count=10`，实际通知数以平台响应为准，不能把批数乘以十当成已读取数量。返回实际读取批数、请求批数、去重后的本批通知元数据、平台后续标志及部分完成原因。有后续证据时可显式续读，不会自动读取全部通知。

续读通过官方页面的「点击加载更多」或列表滚动触发，保持原生请求及签名参数不变。请求必须匹配主页面、账号授权、通知组和上批返回的时间游标。续读会从首批重新加载并核对摘要链，剔除已读批次中的重复编号；前批发生变化时拒绝继续，要求从首批重读。重放前批也可能再次标记已读。

续读凭证仅存于当前工作站进程内，有效期十分钟，绑定主人身份、登录会话、抖音登录资料修订号和账号。浏览器开始本次续读前，原凭证即消耗。结果未知时也不能用同一凭证另取许可或改变批数重试。重启、过期、重新登录和撤权后旧凭证失效。每次读取的一次性许可同时绑定批数和续读凭证。

浏览器在翻页前再次核对已登录账号，并在交回结果前复核。检测到不同账号时停止读取，撤销原互动通知绑定和 Agent 通知读取许可，保留其他功能设置。中途撤权后不回传迟到正文。翻页核对使用页面可见的账号证据，已被平台接受的标记已读无法撤回。

聊天中的通知读取使用独立的 `app_inbox` 工具。主人需要在同一分区另行点击「允许 Agent 读取并标记已读」；默认关闭，账号绑定不会开启此权限。`action=status, app_id=douyin` 只查本机授权。`action=read` 还需显式提供 `allow_mark_read=true`，批数由 `pages` 指定，省略时为一批。工具不自动巡检。只有本机主人的直接聊天或可信续办可调用；微信等其他应用里的消息不能使用该入口。

工具续读凭证绑定原主人请求及来源修订，与界面登录会话的凭证互不通用，也不能用于另一条无关联请求。读取前保存无正文的持久检查点，同一操作重试或服务重启恢复仅返回 `read_not_repeated` 或 `unknown_not_repeated`，不再次触发网页读取。检查点不保留通知原文；结果未知时如实说明可能已标记已读，主人可另发新请求重新读取。通知结果和本轮引用通知的回复不进入普通下一轮模型上下文。账号授权、来源遗忘和主人身份在读取、后续模型请求及回复保存前重新核对。

本轮读取通知后创建的发布草稿或互动任务，会将通知账号的授权版本作为来源证明存入宿主任务。证明只有应用和版本摘要，不向目标应用、任务列表或模型状态查询暴露通知原文、登录目录及账号指纹。准备提交和实际外部操作前重新核对该版本；撤权、重新授权、暂停或切换登录资料后，旧草稿不会自动获得新许可。已提交任务仍可核对原回执，不因撤权重复提交。该校验也覆盖发布到另一应用的草稿，不能只依靠抖音自身发布许可的变化。

跨请求复用已登记成品时，宿主沿成品的原请求及父成品链查找通知读取检查点，并复核其中保存的授权版本。项目工具异步生成的成品使用原创作请求，查询结果的后续请求不能替换该来源。直播节目输入在首次检查、缓存复用及复制完成时执行同样的复核。通知证明只存于私有检查点，不增加模型默认上下文，不改写媒体及原成品编号。撤权保留本地成品和下载，阻止新发布及节目外发使用。旧版或结果未知的通知检查点缺少授权版本时，不从当前设置猜测旧授权；保留原作品并要求重新核对来源。

平台的可见文字与结构化编号、类型、时间分开展示。官方页面会分组及过滤通知，文字可能包含此前批次，不能按显示顺序逐条拼接成某个编号的正文。当前仅展示列表实际渲染的文字，不下载用户头像、附件或评论原件，也不把正文写入记忆。通知列表并不等于完整的评论区或私信。

平台游标停滞时停止并返回原因，不重复循环。后批控件未能加载时返回已读取部分和有效续读位置。单次浏览器操作目前有 45 秒总时限，每批等待八秒；深页重放或平台响应缓慢可能需要重新读取，不能据此宣称已覆盖全部历史通知。

Windows 验证使用真实 Edge 和合成回环页面，覆盖悬停入口、按钮与滚动续页、批数、跨批去重、前批变化、停滞游标和请求拦截；Station 接口和窄窗浏览器回放覆盖一次性许可、续读凭证及撤权。正式账号的真实通知字段、页面变体和平台标已读结果仍需单独验收。本轮没有访问正式账号、发送互动或开播。
