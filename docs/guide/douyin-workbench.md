# 抖音工作台能力与入口

工作台是独立 Windows 窗口，按已保存的普通抖音网页登录资料和分项授权工作。概览显示当前授权状态，并可直达以下分区。概览状态表示本机配置，不代替平台回执。

`douyin` 开发分支的左侧导航按“总览 / 活动 / 内容与创作 / 账号与服务”分组；“活动”内先列“执行回合”，再列“互动任务”。概览有“打开执行回合”直达卡片，执行回合按作品分组读取已保存通知及作品内容证据。2026-11-27 检查时，正在运行的正式工作站服务程序仍未包含该分支的执行回合路由与页面；分支代码与正式运行界面须分别验收。

当前 Agent 可用专用 `douyin_notice_reply` 工具为已保存通知创建限定回复的待提交任务。创建时必须在同一回合读完整件本人作品的简介及音画证据，并逐条核实通知目标、主楼和直接父评论；只接受主评论或直接回复本账号子评论。通用 `app_action` 的抖音回复仍被拒绝。专用任务的提交重核通知、授权、作品上下文及目标证明，浏览器点击前再核对目标文字；提交时不重新读取主楼及父评论关系。工作台按钮仅预填聊天请求，不会自动提交。真实平台逐条捕获、回复回执和手机端效果未验收。下文关于“回复发送关闭”的旧批次描述以此段为准。

| 分区 | 已接入的操作 |
| --- | --- |
| 概览 | 查看登录、服务和分项能力状态，直达各分区，并编辑抖音应用子角色。 |

| 互动任务 | 绑定并手动读取平台互动通知、单独允许 Agent 按主人请求读取通知；查看和管理已有点赞与评论回复任务的原任务状态。 |

“本人作品”的同步分批读取创作者管理页。只有平台分页与本地分批都读到结尾，目录才标记完整；同步中断保留上次完整目录供查看，并显示当前同步进度。每件作品的简介来自平台列表，图片语义和视频采样语义仅在相应读取授权和作品记忆授权有效、实际读取并成功保存后展示。同步页面不自动开启媒体权限，画面读取默认关闭，须由主人勾选。

点赞任务由主人在主工作站聊天中基于已读取的视频创建。抖音通知到目标评论及直接父评论尚未逐条核实，通用 `app_action` 暂不创建或提交抖音评论回复；升级前留下的回复任务可查询状态或取消，不能继续发送。其他应用的回复及抖音点赞任务不受此临时门禁影响。作品发布页的“制作作品”入口预填一条可编辑请求：Agent 先检查已登记项目工具并制作视频；项目工具已返回不可变成品编号时直接使用，只有生成家目录文件时才调用 `artifact_publish` 登记，再核对成品并用明确文案与可见范围创建抖音草稿。点击“带到主聊天”仅把文字放进聊天输入框，主人核对并手动发送；不会由入口发送聊天或投稿。执行回合对有有效作品编号的通知组始终显示“让 Agent 核对此作品资料与音画”，只预填指定日期和作品编号的请求；Agent 先用 `context` 顺序读取该作品已存证据，证据未完成或归属未核实时才用 `locate`→`prepare` 补齐，之后从首页重读到 `agent_context_read_complete=true`。画面页须显式请求；通知到目标评论及直接父评论未验真前不创建或发送回复。独立 Windows 工作台经受限的宿主消息把请求交给主窗口，浏览器预览在同一标签页返回主页面。项目工具入口也返回主工作站。发布任务仍按原请求提供提交、续办、状态查询和停止；创建流程绑定原请求、来源版本和成品证明，当前本机 HTTP 工作台接口只接受原任务操作，不能凭页面输入绕过来源核对。发布审阅只读原任务账本，Agent 的通用任务列表与状态查询不会带出草稿正文。

Agent 已接入只读 `douyin_rounds` 工具读取同一执行回合账本。`works` 按 `date` 列作品分组，用 `next_cursor` 续页；`notices` 必须提供 `date` 和 `work_id`，用 `next_before` 在该作品内续页（`work_id=""` 仅表示未提供作品编号的通知组）；`context` 必须提供有效作品编号，首读不传位置，随后用返回的 `next_cursor` 分页读取已保存的创作者作品文字与音画证据。HTTP 执行回合页面同样使用该游标。游标绑定日期、作品、通知授权作用域及作品记忆版本；若证据或作用域在页间变化，返回 `restart_required=true`，本页不带作品内容，调用方须丢弃旧页并从首读重建上下文。作品记忆版本按整个授权作用域变化，因此其他作品新增证据也可能保守要求重读。旧 `offset` 输入仍兼容，但返回 `snapshot_state=legacy_offset_unpinned`，不能据此认定跨页来自同一版本。Agent 工具另返回 `agent_pages_read` 和 `agent_context_read_complete`：后者只在同一回合按游标顺序读完该作品所有已存证据页、且音画覆盖完整时为真；新回合借旧游标续读、旧 `offset` 续读均不能据此认定完整。`limit` 默认 20，可在 1–1000 范围内指定。工具调用前后及 Agent 生成前重核本机主人、通知 Agent 授权、当前账号与作品记忆归属；作品记忆新增证据页允许同回合从头继续读取。`works`、`notices`、`context` 只读取本机账本，不访问浏览器或发送回复。`locate` 只在对应日期已有通知、本人作品记忆授权有效时，按 `pages` 和 `page_size` 逐页读取创作者作品列表；精确匹配作品编号后返回临时 `content_id`，未完成则按返回进度续办。`prepare` 只接受该通知作品的临时入口，按 `audio_pages`、`visual_pages` 分页读取音轨与采样画面；默认只读一页音轨，画面页须显式指定 `visual_pages`，可用 `audio_pages=0` 单独续读画面。两种证据均完成时 `context_complete=true`；已完成的同一媒体字段跳过重复处理，但保存的完整性不表示本次重新核实平台原件。`audio_complete` 是原音轨已读分页的连续性，`visual_complete` 是采样计划覆盖至结尾，不能称为逐帧理解；`reply_eligible` 仍为 `false`。

此前留存的真实账号记录证明过一次“仅自己可见”的 18 秒作品投稿。本次另在用户普通 Edge 已登录标签页查看了互动通知和对应作品的评论树：主评论卡片内嵌子评论，编号位于各自卡片的 `tooltip_<数字>` 后代；视频直达页使用 `[data-e2e="comment-list"].comment-mainContent`，通知打开的弹层使用 `#merge-all-comment-container`。打开通知面板可能触发平台标已读，但没有执行点赞或回复。这些观察尚未证明编号与平台评论接口的 `cid` 完全一致，也不代表工作台独立 Edge 登录资料已连接成功。原标签曾无法附着调试器；扩展新开标签后只读查看了一条回复通知和评论弹层，仍无法通过浏览器接口取得原始响应。新标签已关闭。真实回复、通知到目标评论的逐条对应与公开发布仍待验收。直播伴侣检查和 OBS 预览不表示抖音平台开播能力已接通。

`douyin_rounds` 的 `notice` 动作要求 `date` 和 `notice_id`，只返回本机同一授权范围内精确匹配的单条通知及未核实候选，不返回私有创作者账号摘要，也不据候选生成回复目标。`prepare` 的临时作品入口约 20 分钟有效；新一次 `locate` 会得到不同入口，未完成的音轨或画面观察可能从首段重读并重复产生模型费用。`can_resume` 只表示现有入口及观察游标下可续办；遇来源变化会返回须重新定位的状态。全量音轨和跨全时长采样画面仍须逐页核对 `context_complete` 与实际覆盖，真实平台未验收。

`relation` 是通知限定的只读关系探测：要求该日期、通知编号已保存且有可核对的详情或列表候选，目标 `target_path`/`target_id` 必须与已保存来源中的 CID 候选完全一致；详情已取得时使用详情候选并核对同路径列表编号，详情未观察或部分缺失时只接受结构唯一的 31 类列表候选；可选 `root_path`/`root_id` 也必须来自同一来源。31 类子评论通知的 `comment.parent_id` 只作为未分类主楼候选，精确读取目标 CID 后还须与目标行的 `reply_id` 一致；没有主楼候选时，仅在自然主列表中命中目标 CID 后从结构化目标读取主楼编号。它还要求当前创作者作品归属、本人作品和评论记忆授权，最多分别在该作品页自然返回的一页中定向核对目标、主评论和直接父评论，不遍历整件作品评论区。执行回合页面仅在详情或符合上述条件的列表含 CID 路径候选时显示“让 Agent 只读核对这条通知”，按钮只把指定日期、作品和通知的请求预填进主聊天。返回 `observed` 只证明目标候选与结构化评论相符；`root_state`、`parent_state` 与 `thread_state` 逐条说明主评论及直接父评论的只读核对状态，父评论由本人发表时只返回布尔值，不返回原始 UID。`pending` 表示该条评论未在自然加载页中出现，`busy` 表示独立登录资料正在使用。用户提供的通知列表、详情及同一目标的回复列表样本已核对字段对应；工作台内逐条关联仍待实测，所有结果 `reply_eligible=false`，不能触发回复。

已收到的真实 `/comment/list/` 样本显示主评论中有 `reply_comment` 子评论预览；只读探测会先利用自然返回的这层预览核对目标和父评论，预览未命中时才尝试该主楼自然加载的 `/comment/list/reply/`，不会靠遍历评论区发现新通知。样本仅在本机核对结构，仓库测试使用合成编号；后续 `/comment/list/reply/` 样本已核对主楼编号与直接父编号；点赞和空详情响应不会产生评论候选。新提供的 31 类评论详情把目标放在 `comment.comment.cid`，嵌套与顶层作品编号只要同时出现就必须相互一致，才允许候选入账；这些响应没有验证工作台独立浏览器的逐条捕获，回复发送继续关闭。

普通聊天中的 `douyin_video_check` 按已登记 `artifact_id` 只读检查当前主人的不可变视频成品，先复核来源与 SHA-256，再返回 MP4/WebM 容器签名、视频时长/尺寸/FPS、指定帧解码时间及指定音频片段的可解码状态。帧编号、音频起点和片段秒数、时间预算均可指定；默认只抽样第 0 帧与开头 1 秒。该结果是技术抽样，不检验内容含义或全片每秒播放。作品发布入口的聊天草稿现在要求 Agent 在登记成品后执行该检查，再创建“仅自己可见”的抖音草稿；入口本身不会投稿。

发布审阅的视频预览只从原 `job_id` 取本机已登记的唯一 MP4/WebM 成品，逐次复核主人、当前抖音连接、成品来源和 SHA-256；只读返回支持浏览器分段播放，不调用创作者中心或提交任务。视频默认不预加载，主人展开审阅后可手动播放，也可保留原下载方式。合成草稿已核对完整视频、Range 字节、无主人会话、旧账号和失效来源的拒绝；真实工作台播放观感尚待截图或用户操作验收。

公开项目 [douyin-mcp 的通知详情实现](https://github.com/yunsur/douyin-mcp/blob/ad31354e6723e86fc0ee397ad62d93f8cdeffd11/douyin/api_notice.go#L78-L100) 使用单条 `notice_id_str` 请求。被动捕获现严格接纳该形式，同时保留原有 `id_list`；用户已提供单条真实响应，现按 `notice_list_v2` 结构及嵌套评论/作品编号校验；其他通知类型仍待验。[同项目的子评论读取实现](https://github.com/yunsur/douyin-mcp/blob/ad31354e6723e86fc0ee397ad62d93f8cdeffd11/douyin/api_comment.go#L77-L115) 使用作品 `item_id` 与根评论 `comment_id`，但不证明通知候选字段就是本次目标评论。该项目的[评论发布实现](https://github.com/yunsur/douyin-mcp/blob/ad31354e6723e86fc0ee397ad62d93f8cdeffd11/douyin/api_interact.go#L182-L194)还要求同会话签名材料，不能把仅有 Cookie 视为写接口验收；本工作台保持原有浏览器会话操作链路，未做真实回复。

## 评论通知的回复范围

执行回合以本人作品收到的评论信息提醒为入口，不靠遍历作品评论区发现新请求。目标规则是只回复本人作品的主评论（顶层评论），以及直接回复本账号子评论的子评论；回复其他人子评论的通知不进入回复。判断必须逐条核实通知对应的账号及作品、目标评论编号、评论层级、直接父评论作者和原任务状态。通知读取器从原生列表响应保留通知编号、原始类型数值、时间、关联作品编号及白名单结构字段中的候选编号，整批页面文字仍单独展示；同一受控会话中自然发出的通知详情响应仅按已读列表编号逐条归并，并明确记录未返回或响应无效。另有只读目标评论核验函数，在上层已给出作品及目标 `cid` 后才观察该作品页自然发出的结构化列表响应；子评论根编号来自同条详情或自然主列表中命中的目标结构；目标不在该页即返回待核对，不翻页发现通知。接口路径及字段参考 [DouyinApiDoc 的通知详情说明](https://douyinapidoc.readthedocs.io/zh-cn/stable/source/API/api/) 与 [DouyinComments 的回复列表示例](https://github.com/alphaply/DouyinComments/blob/master/fetch_replies.py)，原为第三方线索，现已结合用户提供的评论列表、回复列表与 31 类评论详情校准只读字段；工作台独立浏览器逐条定位仍待验收。候选路径既不能把整批文字按顺序拼给某个编号，也不能把作品编号直接当作本人作品证明。因此执行回合保存无正文的通知元数据和候选路径，显示待核对，不创建或提交回复任务。用户提供的网页版截图及本次普通 Edge 查看中，“评论了你的作品”可对应子评论，提醒文案不能证明是主评论；“回复了你的评论”也没有直接父评论编号。先前手机端截图中的“首评”标签不缩小主评论的范围。

## 与微信分支集成时核对

抖音工作台入口、执行回合入口和渲染涉及共用文件 `internal/station/local_app_configuration.go`、`internal/stationui/static/local-home.js`、`internal/stationui/static/local-home.css`，后端通知入账还涉及 `internal/station/local_douyin_notice.go` 与 `internal/station/local_app_inbox.go`。本轮共用页面改动位于抖音 `rounds` 分组、作品音画续读请求、`publications` 创作与审阅入口及对应样式，以及互动许可和旧回复任务暂停提示；桌面宿主 `ApplicationWorkbenchDialog`、`MainForm`、`WindowTests` 新增 Douyin 专属纯文本草稿与项目工具路由，主页面只预填输入框或打开工具页。共用 `internal/apphost/publication.go` 增加仅供本机 owner 精确任务审阅的方法，`internal/station/local_app_publication.go` 注册抖音专属只读审阅路由；通用发布列表与状态结构保持元数据边界。共用 `internal/station/local_tools.go` 增加 `douyin_rounds` 的发现、分派与作品上下文源核对接线，实现在抖音专属 `internal/station/local_douyin_rounds_tool.go`；共用 `internal/station/local_app_interaction.go` 增加抖音评论回复的临时服务端门禁，其他应用交互路径仍按原逻辑。共用测试夹具 `internal/station/local_home_test.go` 另修正本机回环会话登录方式，原密码路由夹具保持原样。合并微信分支时核对这些文件中抖音专属分支及工作台分区变动，尤其保留微信原有执行回合路由与页面。本次新增的共用页面改动仅扩展抖音回合按钮对 `comment.comment.cid` 的路径识别，微信分支集成时核对该条件；未修改构建脚本。工作台能力说明位于本抖音专属文档。

本次续开发的共用文件改动涉及 `internal/station/local_tools.go` 中 `douyin_video_check` 的发现、分派与最终生成前的成品来源复核接线，以及 `project_comfy_register` 普通聊天分派和撤销媒体权限后原 Comfy 任务的查询/取消入口；`internal/stationui/static/local-home.js` 只修改抖音创作草稿、逐条通知的只读请求提示、执行回合作品音画 `next_cursor` 续页与重读提示，以及发布审阅的视频控件；`internal/stationui/static/local-home.css` 只新增该视频控件的桌面尺寸样式。视频预览服务端位于抖音专属 `internal/station/local_douyin_publication_review.go`。`internal/station/local_douyin_web_login.go` 只增加抖音关系读取器注入点；`internal/stationbrowser/douyin_notice_detail.go` 只扩展抖音通知详情的被动请求识别。后续与 `wechat` 分支集成时逐项核对这些共用接线和页面文案。
