# 抖音工作台能力与入口

工作台是独立 Windows 窗口，按已保存的普通抖音网页登录资料和分项授权工作。概览显示当前授权状态，并可直达以下分区。概览状态表示本机配置，不代替平台回执。

| 分区 | 已接入的操作 |
| --- | --- |
| 概览 | 查看登录、服务和分项能力状态，直达各分区，并编辑抖音应用子角色。 |
| 账号与授权 | 网页登录、应用开关、本人作品与媒体等分项许可、按需记忆来源授权。 |
| 内容浏览 | 发现获准内容后，读取首页和视频页文字、本人作品列表与单篇信息、公开视频评论、静音播放证据、音轨转写、采样画面和本人公开图文图片；按返回的进度续读或从头刷新。每项可单独填写字数、条数、张数、帧数或秒数；留空沿用已保存进度，新内容使用默认量，明确填写后从头读取并让后续页沿用该请求量。 |
| 互动任务 | 绑定并手动读取平台互动通知、单独允许 Agent 按主人请求读取通知；查看和管理已有点赞与评论回复任务的原任务状态。 |
| 执行回合 | 按北京时间日期查看已明确读取的互动通知元数据及核对状态，逐页查看较早记录。打开页面不会访问抖音或标记通知已读。当前无法从网页版通知核实评论层级及被回复者，回合均显示证据不足、不会回复。 |
| 作品发布 | 管理普通账号发布许可、打开创作者中心登录、查看和管理已有发布草稿及原任务回执。 |
| 直播与本机预览 | 检查本机直播伴侣程序路径、安装版本与运行状态，打开 OBS 本机预览。 |

点赞和评论回复任务由主人在主工作站聊天中基于已读取的视频或父评论创建；发布草稿由聊天中已登记的成品、文案与明确可见范围创建。工作台对这些原任务提供提交、续办、状态查询和停止入口。创建流程绑定原请求、来源版本和成品证明，当前本机 HTTP 工作台接口只接受原任务操作，不能凭页面输入绕过来源核对。

现有真实账号记录仅证明一次“仅自己可见”的 18 秒作品投稿。真实评论页面、点赞及回复、通知字段与标已读结果、公开发布仍待验收。直播伴侣检查和 OBS 预览不表示抖音平台开播能力已接通。

## 评论通知的回复范围

执行回合以本人作品收到的评论信息提醒为入口，不靠遍历作品评论区发现新请求。目标规则是只回复本人作品的主评论（顶层评论），以及直接回复本账号子评论的子评论；回复其他人子评论的通知不进入回复。判断必须逐条核实通知对应的账号及作品、目标评论编号、评论层级、直接父评论作者和原任务状态。当前网页版通知读取结果只有通知编号、原始类型数值、时间、关联作品编号和整批可见文字，不能把文字按顺序拼给某个编号，也不能把作品编号直接当作本人作品证明。因此执行回合先保存无正文的通知元数据并显示待核对，不创建或提交回复任务。用户提供的移动端截图说明界面上有主评论、回复作者和回复他人三种表现，但不证明网页版接口具有相应结构化字段；截图中的“首评”标签也不缩小主评论的范围。

## 与微信分支集成时核对

抖音工作台入口、执行回合入口和渲染涉及共用文件 `internal/station/local_app_configuration.go`、`internal/stationui/static/local-home.js`、`internal/stationui/static/local-home.css`，后端通知入账还涉及 `internal/station/local_douyin_notice.go` 与 `internal/station/local_app_inbox.go`。合并微信分支时核对这些文件中抖音专属分支及工作台分区变动，尤其保留微信原有执行回合路由与页面。未修改桌面入口或构建脚本；工作台能力说明位于本抖音专属文档。
