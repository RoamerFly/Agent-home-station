# 微信旧记忆库的独立接续

微信重新扫码后，本地连接编号可能不同。确认仍是同一微信账号时，可从「微信 → 详细配置 → 会话与记忆 → 从旧记忆库接续」读取原库并逐会话接入，无需复制旧登录或切换原生数据目录。

## 使用方式

1. 保留旧库原件，停止向该旧库写入，填写其绝对路径。单个微信来源账号自动识别，多个来源账号时再通过卡片明确选择。
2. 暂停目标连接，点击「查找旧会话」。此步只返回会话编号和符合条件的数量，不返回聊天正文。内部账号编号和摘要在「接续方式与来源核对」中按需展开。
3. 在会话设置中明确授予所需会话的历史读取范围，保持工作器暂停。预览不会新增任何授权。
4. 点击「核对此会话」，确认新旧资料属于同一个微信账号，再点击「确认接续此会话」。已有档案不覆盖；源库、主人、原生数据集、授权版本或本次进程所有权变化后须重新预览。
5. 在同页「已接续的旧会话档案」按页读取提炼记忆或原话。工作站记忆宫殿仍默认本机；跨来源查询需要另外明确授予相应方向与会话范围，不因接续而自动开启。

主人会话和 CSRF 保护的接口是 `POST /api/apps/wechat/connections/{connection}/memory-archive`。必填参数为 `source_database`；省略 `source_account` 时，从经过会话身份校验的元数据自动识别单个来源，多账号则返回 `choose_account` 和 `source_accounts`，不返回任何账号的会话内容。可选 `thread_id`；确认写入时须明确传入预览返回的 `source_account`、`digest` 和 `same_account: true`，不在写入阶段猜账号。仅管理员界面可提交路径，模型没有该接口。当前支持的单源 SQLite 快照上限为 512 MiB，单会话封存文件上限为 24 MiB；超出时保留原件并拒绝写入，需要后续分片接续，当前没有自动分片支持。

界面仅在最终接续前显示同账号确认，结果用留白卡片呈现。卡片入场动画为180毫秒，只使用透明度与位移；键盘操作及系统减弱动效偏好关闭该动画。不会循环闪动或动画大面积模糊。

## 原件和权限

源文件通过已打开的只读句柄和不可跟随旁路文件的 SQLite VFS 读取。非空 WAL/journal、符号链接、身份不匹配、未完成写入或来源摘要变化会阻止接续。空 WAL 和残留 SHM 不参与读取。目标档案保留源账号及 SQLite 摘要，读取时另核对当前主人和原生数据集。会话授权撤销、遗忘及更正继续受原读取屏障控制。

接续仅创建独立档案和必要的空读取/遗忘账本，不向普通会话上下文或实时记忆表插入旧原话。不会导入登录密钥、发送队列、主人身份和旧权限，也不会启用工作器、调用模型、发送、发布或开播。

保留的冷历史可以按需读取，但抑制、遗忘、冲突、不可靠文本、无可核对来源及无法证明事实来源版本的内容不进入 Agent 可读档案。没有完整证明的历史继续保留在原库，不伪造来源，也不等同于已恢复。

## 当前证据

2026-11-11 对已定位的旧库使用新读取器完成只读预览：5 个微信会话中 4 个有可接续来源，共 56 条原话、1 条提炼记忆，原库摘要不变。原库共 1,112 条事件，其中 699 条为助手回复、411 条为用户事件；很多早期事件缺少原生来源证明，不能把总事件数当可恢复的用户原话数。旧库有 38 条记忆，当前仅 1 条具备本次独立接续要求的完整来源证明。旧原件仍保留，补证继续待办。

## 用旧原生档案补充来源证明

旧管理库和对应的原生账号仍保存在同一套停止写入的 Windows 资料目录时，可以用候选包的 Python 3.13 和随包 `wx.exe` 生成可接续副本。输出路径应位于新建的私有目录，文件名必须未被占用。

```powershell
& $python scripts/prepare_wechat_memory_evidence.py `
  --native-reader $wx --legacy-root 'C:\Legacy\data' --account '<旧受管账号>' `
  --output 'C:\PrivateMigration\corroborated-memory.sqlite' --source-stopped
```

脚本使用原生 `profile messages` 离线读取同一快照，按页检查可用消息。旧记忆事件须同时匹配原生会话、分库分表的消息号、发送者、整秒时间、正文和 SHA-256，并有同一会话的原生入站记录与唯一服务端消息号。已撤回、遗忘、冲突、被抑制、改写或已有来源的事件保持原样。输出在原库副本上补充来源与原生快照摘要，保留原事件编号和记忆引用。原库、原生档案、控制账本和密钥的摘要在发布副本前复核。可以用 `--page-size` 和 `--page-timeout` 调节原生读取参数。

把生成的副本路径填入上面的「查找旧会话」即可查看可接续数量。实际接续继续按当前会话历史读取授权确认。输出含私人资料，只留在本机。使用本轮真实旧资料验证，读取 5 个会话的 480 条原生消息，补充 32 条原话证明。工作站读取器在新副本中核对出 88 条原话和 1 条提炼记忆，分布在 4 个会话。该副本目前已完成预览。

新增合成专项覆盖不同本地账号编号的预览/接续/实际档案读取、源摘要不变、零实时会话注入、授权版本变化、原生数据集替换、主人变化、遗忘、运行中拒绝、未确认拒绝、CSRF、非空 WAL 和取消。新增桌面浏览器专项覆盖大弹窗表单、账号间草稿隔离、逐会话确认、编辑源资料清除旧预览及重新打开草稿保留。真实资料目前只完成预览，尚未写入正在使用的候选实例；不能据此宣称全部旧聊天或记忆已接回。
