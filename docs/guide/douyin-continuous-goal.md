# 抖音工作台持续目标（2026-11-26）

仅在 `douyin` 工作树与分支推进。正式工作站的发行包、数据、登录资料和媒体不作为开发测试材料；微信工作树独立集成。每批代码通过定向验证后以中文提交并推送，核对远端 SHA。

## 1. 通知驱动的评论执行回合

1. 由已绑定账号的互动通知发现新请求，按作品编号分别列出通知及状态；作品编号缺失单列，原生编号本身不证明作品归属。分页不能把同一作品的通知误并到另一作品，也不能因新通知插入而漏页。
2. 在同一受限网页登录资料中取得可比较的通知账号与创作者账号摘要，逐条确认作品来自当前账号。仅保留派生摘要，不保存平台原始 UID、Cookie 或签名。
3. 针对通知编号定向核对本次评论的 `cid`、一级评论编号、直接父评论编号和作者。只有本人作品的主评论、或直接回复本账号子评论的子评论可进入回复；其他子评论排除。文案和候选字段路径不能代替关系证据。无法核实的回合保持待核对，不创建回复任务。
4. 每个作品建立独立上下文：创作者中心简介与状态、原视频完整音轨的转写进度、覆盖整段时长的分批画面分析及每段时间戳。记录媒体哈希、覆盖范围和缺口。画面采样不宣称逐帧观看；缺少所需上下文时暂停自动回复，避免用评论区文字冒充视频内容。
5. 回复沿用精确评论目标、原文版本、授权、节奏控制与原任务回执链；未知结果只核对原任务，不重复发送。

## 2. 作品制作与发布

复用工作站项目媒体工具、不可变成品登记、`app_publish` 草稿与提交回执链。抖音工作台提供创作请求入口、已有成品及发布任务的可见状态，创作请求可编辑且不自动发送。发布前展示视频、标题、简介和可见范围的可审阅结果。任何正式账号投稿都须遵守本聊天先前的“不要自行投稿”约束；授权前只用合成平台完成提交与回执验证。

## 3. Agent 工具验证

- 源码和合成回放：核对工具发现、授权、创作成品、草稿、提交、回执及取消/未知结果的原编号语义。
- 可选真实模型加合成抖音传输：使用本工作树忽略的独立测试配置与临时数据，观察模型自主选择工具；不使用正式账号或正式媒体。
- 真实平台只读验收：核对工作台独立 Edge 资料的登录、通知与创作者账号一致性、通知到评论树的逐条映射及视频上下文覆盖。普通 Edge 已登录标签页的 DOM 观察不能代替这一步。
- 真实外部动作：仅在具体账号、作品、文案、可见范围和接收效果可审阅后，按用户最终授权执行；记录平台回执，不以合成测试代替。

## 本轮进展与后续验收

执行回合已按作品分组，组内通知独立分页；通知入账另存同域创作者账号摘要。当前账号、通知组、创作者作品快照和记忆授权同时吻合时，可以读取该作品简介和已留存的音轨/采样画面证据。音轨与画面的完成标记分别依其实际分页连续性与媒体哈希，画面完成仅表示采样计划覆盖，不表示逐帧观看。内容浏览中显式读取的证据才会入账，打开回合页面不会自动抓视频。

针对主评论与直接回复本人子评论已建立严格的纯合成判定门禁，但原生通知详情到目标 `cid`、结构化评论直接父字段仍无真实样本校准，门禁尚未接发送；所有执行回合 `reply_eligible=false`。下一步复用已登录浏览器对平台原生请求的被动拦截，逐条取得脱敏结构化证据，再连接既有 `app_action` 原任务链。

作品发布页已增加可编辑创作请求和项目工具入口，带入主聊天时只预填、不自动发送。既有不可变成品登记、`app_publish` 草稿/提交/回执链具合成端到端验证。用户授权只读使用工作站现有 DeepSeek 模型配置后，本工作树真实模型加合成 Creator 的定向测试通过：Agent 自主调用 `artifact_publish` 和 `app_publish`，合成端仅一次上传与提交，按原任务查询到回执；视频由夹具预制，所以仍需验收 Agent 自主选择视频制作工具。工作台独立浏览器登录、真实平台逐条评论定位及正式投稿亦未验收。普通 Edge 扩展本次返回 `Debugger unattached`，只读核查未能继续；先前普通 Edge 截图不能代替独立资料验收。

测试夹具已改用本机站点的 `GET /api/session` 创建会话，旧独立密码路由测试仍走 `POST /api/login`。此共用测试文件 `internal/station/local_home_test.go` 也需在微信分支集成时核对。独立桌面 C# 编译通过；完整 `Build-Desktop.ps1` 在 Go 1.26 链接工作树缺少 `vcs.revision` 的核对处停止，未修改构建脚本或正式发布包。
