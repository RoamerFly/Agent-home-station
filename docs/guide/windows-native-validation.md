# Windows 原生后端验证记录

日期：2026-10-30。环境：Windows x64、.NET Framework WinForms/WebView2、Go 1.25.3、Rust 1.93.1 MSVC、Visual Studio 2022 C++。合成实例使用中文和空格路径，端口为独立临时回环端口。

## 本机验证

- 原生后台按 `components/native-client/source-manifest.json` 的固定提交与累计补丁构建，包含现有语音、分享与引用修复；并非直接用较新的上游发布包代替。使用 `--locked` 构建通过，保留上游许可证及媒体/协议/SILK 声明。
- Go 管理端从本项目已提交源码快照编译，无 CGO；未带入其他未提交工作。Windows 与 Linux 管理端均构建通过。
- `go test ./...`、`go vet ./...`、仓库凭据检查、3 项结构检查、28 个前端 JS 语法检查通过。
- 桌面控制器 43 项断言通过，包含原 WSL 启停兼容、排空失败/取消保护、Windows 原生配置、程序哈希拒绝、路径兼容和 Job Object 进程归属。
- `WECHAT_WINDOWS_NATIVE_PACKAGE=... python -X utf8 -m unittest discover -s scripts -p test_windows_native_smoke.py`：最终原生补丁版和 Go 服务在独立空数据根中实际完成两轮启动、管理鉴权、全账号排空、有序停止及冷重启。退出后两端口均关闭，登录资料与管理凭据保留。不扫码、不调用真实模型、不发送消息。
- 最终 EXE 直接显示内嵌管理页；空实例显示微信未登录、Agent 已停止、模型未配置。最小化/恢复期间同一组进程保持，重复打开 EXE 未增加另一组服务。
- UI 自动化操作关闭按钮时发生窗口状态变化，未将该次关闭记为通过。独立控制器已完成实际有序退出；另在空实例强制结束桌面所属进程进行异常退出测试，Windows Job Object 清理微信/管理子进程，端口全部释放。没有结束共享 WSL 或官方 Windows 微信。

## 能力边界

以上证明原生程序、桌面控制器与管理服务的组合运行，不证明 Windows 真实微信扫码和媒体收发已经通过。需要用户在新实例扫码后，按明确授权的接收方和用途另行验证入站、出站、微信服务器回执及手机播放。没有以本地队列或模拟响应代替真实投递证据。

本轮不自动迁移已有 WSL 账号、聊天记忆、任务、素材、私有模型及歌曲。原部署与原桌面入口保留。音乐服务的 Linux 隔离和运行环境仍是单独迁移工作；Windows 基础聊天原生化不等于唱歌链路已经原生化。程序包不包含真实聊天、账户资料、浏览器状态或模型。

## 自动检查与复验

Windows CI 从固定源码与补丁编译完整便携包，运行桌面断言、Go 停止管道/只读任务探针测试和实际空实例两轮启停；Linux CI 继续执行完整 Go、JS、Python 与源码检查。真实扫码和投递不进入自动 CI。

构建与使用见[桌面程序](../../desktop/windows/README.md)。验证原始日志和合成空实例保留在本机 Git 忽略的 `temp/` 中；仓库仅记录结论与安全合成测试代码。
