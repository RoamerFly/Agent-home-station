# 运行构成、权限与迁移

本页描述源码结构和部署方式。实际权限以当前管理配置与调用者身份为准，资源占用应在目标机器现场测量。

## 服务边界

默认Windows启动器调用WSL用户服务：`wechat-bot-native.service`负责原生微信连接和消息/附件能力，`wechat-bot-api.service`提供独立发送入口，`wechat-bot-web.service`承载网页管理、Agent循环、记忆、持续任务、工具分发与后台轮询。WSL锚点仅保持本机发行版运行，不处理聊天。

YuE是按需启动的可选服务：Windows的ComfyUI负责模型推理，`scripts/yue_bridge.py`负责鉴权、工作流和任务状态。TTS、ASR与文本模型使用已配置的云API，不因此启动本地大语言模型。ADB/安卓模拟器、RVC和外部MCP只在相应功能启用并使用时参与；默认YuE原生女声不加载RVC。

## Agent权限及自修复

工具的发现、权限过滤和执行在`internal/admin/`，服务器读写与进程实现位于`internal/agenthost/`，通用联网/MCP位于`internal/mcptools/`，原生微信封装位于`internal/linuxnative/`。这些适配层由本项目维护，上游模型、ComfyUI和协议客户端是独立组件。

- 工作区工具保存和读取Markdown记忆；聊天记忆与媒体目录提供按会话的持久数据。
- 主人身份配置允许相应会话中的主机读写、命令、后台进程和跨会话操作。身份按微信ID核对，群昵称不作为授权。
- `host.mode=full`的命令以服务操作系统用户执行，WSL中的`/mnt/c`、`/mnt/e`可通向本机盘符；Windows隐藏执行端使用当前Windows账户。它不是安全沙箱，不自动提权为管理员。
- `server_read/edit/write`、`server_exec/process/windows_process`使Agent能够阅读项目、修改工具源码、测试、构建、启停程序。但修改Go源码后必须编译和有序更新管理服务才会生效；工具schema不会因模型一句话而改变。Python桥接修改也需要相应进程重载。
- 普通成员可聊天及安排自己的无害提醒；不因此取得主人的主机命令、任意文件读写、跨群读取或转发权限。

自主执行循环不再使用任意每轮行动数配额，但具体模块仍存在输入载荷、协议、提供商、资源或历史实现边界；不能声称“所有工具完全没有限制”。例如主机短命令有超时，长期工作应使用可持续进程工具；歌曲后台交付仍有历史重入检查。默认值和续读方式见工具schema。

## 迁移与桌面形态

Go管理端可编译为Windows或Linux可执行文件，前端已内嵌。不过当前微信原生运行在Linux，Windows本机启动依赖WSL；仅拷贝一个管理端exe不等于迁移完整系统。部署还须保留数据根、会话数据库、配置、任务/操作记录，以及服务路径。微信会话能否在不同主机继续使用取决于协议端和账号校验，不能保证无需重新登录。

可以增加桌面壳，内嵌现有管理网页，并统一展示启动、停止、日志、资源路径和健康状态。建议先保持核心服务协议稳定：桌面壳管理WSL与可选YuE Worker；Linux服务器仍直接运行服务。Python/CUDA/模型作为独立资源，不能为一个exe把十几GB环境与所有历史生成物绑进主程序。当前仅有bat/PowerShell启动器，没有交付新的桌面安装包。

## 精简优先级

1. 数据根、程序、模型/运行时、临时文件分层；用清单登记已有YuE环境，避免重复拷贝。
2. 旧程序回滚副本保留少量已验证版本；过期调试转码和构建产物提供可预览的清理功能。原曲、用户选定声线、聊天和已生成歌曲不作为临时文件自动删。
3. 音乐Worker空闲卸载模型；按需启动/停止，主聊天服务不为做歌长驻GPU内存。
4. 把分散的持续任务与交付恢复归一到任务状态/副作用记录，减少重复规则；工具返回真实结果，模型据此选择下一步。
5. 网页以会话、执行回合、工具/权限、运行状态为主要入口，减少同一设置在多个页面出现。

桌面壳改善本机操作，不会降低YuE模型本身的计算需求，也不替代真实音频与消息投递验收。

0.31.7已交付四类任务的共享结果路径，并为旧程序回滚文件提供校验和保留策略；本机清理了203份已核对的过期回滚程序，释放约3.15GiB。当前程序、正在运行版本及近期回滚副本保留。临时媒体、旧RVC环境及用户产物未自动清理，不能把本轮改造称为整个目录已清空或全面整合完毕。
