# 公共工具生命周期与本机预览

工作站聊天 Agent 使用 `station_tool_status/start/stop/restart`；这些入口与项目工具页面共享实现。新安装的可执行工具包按目录发现并进入同一控制器。未绑定执行器的迁移模板返回 `not_available`，不能把解释器存在当成业务可用。

项目工具页面从公共工具包目录读取「公共工具」，由工作站自己的目录、配置和生命周期控制器管理。微信宿主的安装记录不再作为公共工具的回退来源。工具已在微信内启用时，其工作站版本仍需独立安装。「应用内工具」按应用列出专属能力，微信的历史媒体、搜索、分享和音乐投递配置在此查看，实际设置仍在微信控制台管理。微信组合音乐包 `music` 留在应用范围，独立的 YuE 和 RVC 属于公共工具。

## 从工具目录接入

将符合工作站协议的工具包解压成 `publictools/工具名称-用途/plugin.json`。打开或刷新“项目工具”，工作站读取配置的工具目录和包清单，识别工具名称、ID、版本与权限。Windows 外部工具包支持宿主协议 1 的 `mcp-stdio` 入口，包内各文件须与清单摘要一致。两个文件夹声明相同新 ID 时不安装其任一版本。内置工具继续使用随程序固定的清单。

1. 已配置的公共工具目录会在工作站启动和扫描时自动登记兼容工具包。宿主校验文件清单与摘要，配置齐全的工具进入按需待命。
2. 工具可以启动、停止或重启。目录扫描会保留主人主动停用的工具状态。普通成员要等工具空闲后才能停止或重启。
3. 更新外部工具时，替换目录中的包，再点击「扫描 / 重载」。工作站等待当前任务结束并核对权限和配置兼容性，再切换快照。与工作站内置声明不匹配的发行工具继续使用现有版本，待对应工作站版本更新。

目录发现与生命周期已通用化。具体业务能力仍由工具宿主的能力适配提供，第三方程序需要提供符合协议的入口和对应的调用适配。示例 Python 包位于 `templates/plugins/python-stdio`，可独立验证注册与隔离启动。

### 本机配置目录

首次启用或启动已安装的外部工具时，工作站在 `data/publictools/<工具ID>/` 创建缺失的 `config.json`。文件由 `config.schema.json` 的非敏感默认值生成。目录或配置已存在时，保留原件，启用、启动与重启时读取并校验。

```json
{
  "values": {"language": "zh"},
  "secrets": {}
}
```

`values` 和 `secrets` 的字段由工具包声明。工具包只提供配置声明，真实凭据在本机配置。初始文件不填入密钥，也不从现有数据库导出密钥。若需要手动填入密钥，`config.json` 会包含敏感信息，打包工具时只从 `publictools/<工具目录>/` 取文件。已有宿主密钥在文件省略时保留。启动校验失败会报告需要检查的配置路径，文件和上一份有效配置保留。配置成功后，宿主仍保存相应版本，供已经登记的任务核对。

迁移到另一台机器时，可先复制工具目录和该工具的数据目录，再安装并启用工具。仅保存在原宿主私有数据库的凭据需要随数据库迁移或重新填写。

### 共用视觉配置与余额

工作站的公共媒体识别首次接续微信旧宿主已经保存的视觉配置。已有工作站配置优先。桌面微信处理图片和视频画面时，在自身检查会话及来源后调用工作站公共视觉宿主，微信工具页面从公共工具栏目进入工作站设置。账号内的视频号登录及投递留在应用内。

公共工具详情可向 DeepSeek 官方查询余额。阿里云视觉详情中的「财务凭据」接受同一计费账号下获准执行 `bssapi:QueryAccountBalance` 的 RAM AccessKey。财务凭据单独保存在 `data/publictools/media-understanding/aliyun-billing.json`，由工作站宿主持有。「查询余额」读取阿里云账户的现金余额和可用额度，保存或清除设置时不发起查询，也不会调用模型。费用中心链接可直接查看账户财务信息。

## 独立 OBS 本机预览

可在 `data/publictools/registrations/station-obs-preview.json` 登记本机 OBS 程序的绝对路径 `executable` 和小写 SHA-256 `sha256`。该文件只由主人部署流程写入，不接受 Agent 提供启动命令。

OBS 安装目录的 `config` 必须指向本工作站的 `data/publictools/obs-preview/config`（可以用 Windows 目录联接）。仅配置独立的 `StationPreview` 配置/场景；普通 OBS 用户配置保持独立。WebSocket 端口和密码仍通过项目工具的 OBS 配置接口保存。不同 OBS 版本可能分别读取 global.ini 或 plugin_config 的 WebSocket 配置，应以实际连接验证为准。

启动参数固定为便携模式、独立实例、指定配置/场景及内置插件；不带开播、录像、虚拟摄像头或屏幕采集命令。启动后核对实际监听 PID。停止仅结束工作站自身启动的 OBS 实例；外部自行运行的 OBS 不由此杀进程。工作站正常退出会关闭受管预览进程。尚未登记独立 OBS 时，继续支持连接主人已打开的 OBS。

OBS 的 WebSocket 在 IPv4 通配地址监听，但工作站客户端使用 127.0.0.1 和密码认证；这不等于一个仅绑定回环地址的服务。ComfyUI 的严格回环监听检查保持不变。

## 验证含义

音乐桥可在主人的本机 `windows-music.json` 中指定 `comfy_registration`，引用已经登记的 YuE/ComfyUI 后端。音乐服务校验登记及 Python/入口摘要，用独立端口、账号内 input/output 启动自己的 Comfy 子进程，等待健康后启动桥接；停止音乐服务同时关闭其子进程。没有登记时保留原先外部服务模式。它不再依赖旧构建目录里偶然留下的后台进程，也不复制模型。

标准 `WithRVCBackend` 构建同时打包音乐 supervisor、IPC/HTTP 客户端和三份 YuE 工作流，并逐文件记录摘要。RVC 校验兼容旧版仅 RVC 的清单，也逐项校验新增的音乐控制模块。

生命周期通过表示状态可读、启动完成、停止完成；不代表全部格式、模型、外部提供商、生成质量或微信投递均通过验收。一次性语音后端启动执行配置/资源就绪检查，不创建空闲常驻推理进程。没有执行后端的模板保持不可用，不能伪造启停成功。

目录清理应核对运行进程和登记引用，保留源码工作树、私有资料、模型和正式产物。旧构建/缓存按主人约定移入待删除目录；同盘移动不释放磁盘容量。全量目录报告和真实数据验收文件只保存在本机，不提交仓库。
