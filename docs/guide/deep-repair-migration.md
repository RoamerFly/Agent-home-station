# 深度修复：数据迁移、验收与恢复

本轮继续使用现有 SQLite 和原生微信后端。所有迁移、真实数据核对和程序更新先在本机完成；不发布 Release、Docker 镜像或远端版本。管理页上的发送回执仍只表示服务器接受，不能代替手机播放或人工听感验收。

## 来源与回复的约束

- Store 持久保存来源实例。原生消息编号、服务器编号、发送者、会话、时间和正文身份共同参与核对；Trace 只用于串联调用。
- 重试幂等；同文不同消息分别保留。同编号身份冲突隔离原事件及相关派生信息，保留原文，不猜测日期。明确修订需要原版本依据。
- 每个待发气泡保存自己的回复对象、锚点、来源版本、素材与审校状态。已接受分段先回读原幂等键，不因后续更正重复发送。
- 助手旧话不作为用户生活事实；图片上传者、被拍摄者和物主分别表示。其他成员的背景消息不能转移原任务或命名声线的归属。
- 同群已核实的第三人文字可作为关于该作者的证据，触发跨人物复核；跨人物图片需要引用关系。模糊亲属称谓保留受话者不确定性。
- 更正、遗忘、修订与来源隔离使当前上下文、摘要、向量、工具结果页及待发计划失效。记忆查询从读取开始捕获版本，不能在保存旧结果时重新标记成新版本。
- 管理更正创建独立、有权限与来源的更正事件，不能冒充一条历史微信消息。原事件、修订和更正记录同时保留。

## 迁移前预演

1. 保存当前源码工作区的变更清单和哈希；不覆盖既有未提交工作。构建产物记录 HEAD、未提交源码补丁哈希和二进制哈希。
2. 设置持久的 `data/admin/memory-update-hold`，排空所有账号在途任务。标记存在时不恢复自动处理；原生登录可保留用于只读核对。
3. 对 SQLite 使用一致备份或停机后复制，不能在写入时只复制主库而漏掉 WAL。备份保留配置、原生登录状态、任务与媒体回执；模型及素材原件原地保留。
4. `source-audit` 只读输出来源异常，核对原生记录、旧记录和备份。报告与实际聊天原文仅保存在本机私有目录，不随源码提交。
5. 在隔离库执行 `quarantine --review <review.json>`。review 中包含预期 scope、事件 ID、修订和正文哈希；提交前比较，任何不一致均中止。
6. 原始记录保持不变；核实的原生消息以稳定来源身份重建。导入使用实际原时间，不把导入时刻当作用户刚刚提及。管理员更正按独立来源保存。
7. 重复预演，检查幂等、事件数量、消息时间、正文哈希、来源链、调度状态和数据库完整性。

CLI 示例（`--dir` 是 companion 数据目录，含 `memory.sqlite`）：

```powershell
go run ./cmd/wechat-memory --dir <isolated-companion-dir> --action source-audit
go run ./cmd/wechat-memory --dir <isolated-companion-dir> --action quarantine --review <private-review.json>
go run ./cmd/wechat-memory --dir <isolated-companion-dir> --action verify
```

写入修复工具必须取得独占维护租约；Web 或其他 Store 正在使用数据时应拒绝写入修复。只读审计不修改数据库。管理接口的来源隔离仅在 Agent 停止时允许，并与启动/配置更新共用操作锁。

## 本机更新顺序

1. 完成确定性测试、真实配置模型的合成评估、Go/vet/JS/仓库检查、Windows/Linux 构建和合成浏览器/桌面检查。
2. 保持处理暂停，核对所有账号排空及原生待投递计数为零。按所有权停止本项目服务和桌面壳，不使用按进程名称批量结束的方法。
3. 取得停机一致备份，验证 SQLite `integrity_check`、备份清单和哈希。保留旧程序及各运行时，替换前核对新包补丁和二进制哈希。
4. 在正式库执行已预演、经版本条件保护的修复。程序和数据均需校验通过才能进入下一步。
5. 启动新程序，保持 `memory-update-hold`。通过鉴权只读检查登录、配置、任务、素材、原文、记忆、来源隔离和回执；不发送真实微信测试消息。
6. 检查新版本的回复依据与审计配置。合成测试报告、备份与恢复说明齐备后，经现有 `/api/runtime/memory-activate` 完成数据库校验并恢复处理。

未达到质量门槛时保留暂停状态，修复后重测；不能将“编译通过”写成整体上线验收通过。

## 恢复规则

接受新写入前失败：保持暂停并停止已启动的新进程，将同一份一致备份中的程序、数据库及对应配置一起恢复，校验后启动旧程序。不要把新库与旧 WAL 混合。

接受新写入后失败：暂停处理，保留新库及 WAL，导出诊断和一致备份，由兼容版本修复。不自动回切旧 JSON 或用旧库覆盖新增消息。

原始来源隔离可以核查，但不可通过重新导入或删除屏蔽边界让已遗忘资料自动回流。管理员需要修正隔离判断时，应单独审计版本和来源，不能批量清空记忆。

## 回复依据与诊断

会话详情和执行回合中的“回复依据”展示触发者、回复对象、来源版本、引用和媒体。普通回合默认只保留结构化元数据；高风险及故障回合的实际输入输出快照默认保留七天，可在记忆设置中关闭或调整。

快照不保存凭据、认证头或模型隐藏推理，过期或来源失效后不可读取。快照是本机私有排障资料，不属于源码测试夹具。命名声线检查的是请求、任务、模型资料、产物元数据和交付的绑定，仍需分别记录实际试听和手机播放结果。

语义审核通过独立结构化调用使用当前配置模型，预算不继承短聊天的输出限制。管理员可通过现有鉴权配置接口保存 `companion.grounding`：

```json
{"max_tokens":8192,"timeout_seconds":120,"reasoning_effort":"high"}
```

这些数值是可配置初值；零值使用初值，非法参数明确拒绝。官方 DeepSeek 使用 JSON 输出和推理模式，兼容服务仅发送标准 JSON 参数，实际能力以该服务返回为准；JSON 不支持、超时或输出截断时不会悄悄改用普通聊天审核。审核用量包含提供商报告的推理消耗，审计只保存最终结论及实际配置。[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[推理参数](https://api-docs.deepseek.com/guides/thinking_mode/)

模型在途、计划重审、私聊及媒体投递同样保留最初证据版本和权限。遗忘、更正或撤权后暂停未执行部分，不通过换幂等键或补签当前版本继续发送；已接受部分仍只读对账。工具已完成但证据随后变化时，继续位置与已完成动作分别记录，不自动重放。旧版缺少完整证明的私聊待发草稿需要重新规划。
