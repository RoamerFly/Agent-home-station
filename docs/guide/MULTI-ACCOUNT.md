# 多账号管理与重新扫码登录

管理页“设置 → 微信账号”列出当前原生登录与其他已保存账号。顶部选择器决定本页管理的账号；地址中的 `account` 参数保留选择，可分别打开多个标签页。切换管理账号不会暂停其他小号。

在账号卡片点击 **绑定大肥鱼**，即可把这个微信账号关联到本机的大肥鱼。第一次绑定时创建她的稳定编号。其他账号需要逐个绑定，成功后卡片显示“已绑定大肥鱼”。账号间的聊天、任务和读取权限仍各自独立。

点击 **解除绑定** 可以随时断开关联。仅移除账号会暂时停用绑定，恢复账号后绑定随之恢复。彻底删除账号会解除该账号的绑定。即使所有账号都已解绑，下次绑定时仍能接回同一条鱼。

新增小号后，点击“扫码登录此账号”，在手机上完成确认。已有账号可点击“重新扫码登录”；过期或失败后可重新生成二维码。登录只作用于选中账号，不退出其他账号。二维码和状态查询始终携带账号上下文。未结束的同一登录操作复用原二维码，避免重复提交。

新小号沿用创建时的模型服务配置、密钥和人设作为初始值，之后独立修改；不复制原账号的群聊规则、私聊名单、历史记忆、发送记录、持续任务或服务器高权限。首次登录后配置回复规则，并在工作台启动该账号的 Agent。已启用账号在管理端重启后分别恢复工作，每个账号有独立 Worker、收件进度、记忆和交付状态。

移除小号会先停止该账号的 Agent，再退出微信。选择 **仅移除账号** 会保留资料，可在已移除列表恢复，重新登录后按需启动 Agent。选择 **同时删除数据** 会清除该账号的配置、记忆、任务和私有工作区；已移除的小号也可以单独删除数据。

Windows 桌面在服务停止后清理该账号的原生缓存和托管的微信资料。若程序异常退出，下次启动服务前继续。外部挂载目录和手机上的聊天记录保留。独立部署需先正常停止 Web 和原生服务，再运行 `wechat-admin desktop-clean-accounts <原生数据绝对路径> <主账号ID>` 完成相同的离线清理。主账号保留为本机服务入口。

原有账号及其原目录保持不变。新增账号配置位于管理数据目录的 `accounts/<账号标识的SHA-256>/`，收件状态位于原状态目录的 `accounts/<SHA-256>/`。私有 `accounts.json` 仅保存注册索引，不存会话密钥；这些文件和目录均禁止提交。一个次要账号配置损坏时显示错误，保留原文件，其他账号仍可使用。

微信昵称、群名和备注优先用于会话、账号、目录、日志及任务展示；尚未同步时保留可辨认的状态或标识。标识在详情或提示中可查看，路由、授权、记忆归属仍使用稳定 ID，重名不会混为同一账号。

管理登录、密码和 CSRF 校验共用一个管理端身份；未知账号或互相冲突的请求上下文直接拒绝，不回退到主账号。程序更新需等待所有账号结束当前工作；等待微信登录的 Worker 可以正常收尾，不清除登录资料。

验证范围：Go 测试使用合成原生服务验证两个 Worker 同时运行、单独停止、独立记忆、二维码归属、持久注册索引、全账号更新收尾及共享鉴权。`scripts/test_accounts_ui.cjs` 使用合成账号与日志检查切换、请求范围、扫码入口、中文昵称、明暗主题和窄屏，阻止真实写入与发消息。真实第二个微信号仍需要使用者扫码后验证微信侧持续在线及消息收发。
