# 自主冲浪的分享决定与记录

2026-10-25，0.9.6-surf-outcomes-local。

## 为什么有时没有分享

冲浪机会是一次真实探索机会，不保证每轮发送。模型可以分享、收藏、只浏览，或判断内容不感兴趣、不适合当前群。工具失败、来源未核实、重复主题、权限与安静时段则属于程序执行或发送限制。旧版本会把不同结果压成“选择安静”，历史记录也缺少细分原因。

本次检查的两轮实际轨迹：第一轮取得候选后选择收藏，没有继续读取；第二轮一个音乐源超时，本地歌曲工具失败，后来成功读取一个视频页面，最终未分享。第二轮没有留下模型的细分原因，不能断言是网络失败直接导致沉默。原始对话、群标识和接口返回保留在本机私有目录，不进仓库。

## 行为调整

- 冲浪与普通主动续聊区分：适合当前群的新内容本身就是分享理由，不要求群里先有人提问或正在聊相同话题。
- 优先深入具体候选并准备真实图片、音乐、视频或播放卡片。单源失败可以换候选或形式；冲浪优先现成网络内容，不顺手启动本地歌曲生成。
- 拿到候选但未读取就笼统安静时，最多增加一次可拒绝的探索提示。明确不感兴趣、不适合、收藏均立即尊重；调用预算耗尽不再提示。程序不会替模型选择内容，也不强制分享。
- 仍检查真实来源、媒体句柄、重复话题、白名单、安静时段和发送权限。文本介绍继续在附件接受后发送。

## 可观察结果

`surf-history.json` 在原有记录上兼容新增 `reason` 和 `tool_failures`；收藏也保存选中的候选 ID。模型只输出固定结果标签，不存储内部推理过程。

| 结果代码 | 含义 |
| --- | --- |
| surf_bookmarked | 已收藏，暂不分享 |
| surf_not_interested | 模型对候选不感兴趣 |
| surf_not_suitable | 模型判断不适合当前群 |
| surf_browse_only | 已读取后决定暂不分享 |
| surf_candidates_only | 只查看候选列表，没有继续读取 |
| surf_tool_failed | 有实际工具失败记录，模型未完成本轮分享 |
| surf_candidate_not_selected / surf_candidate_not_verified | 没有具体候选或尚未核实 |
| surf_duplicate_source / surf_duplicate_topic | 来源或主题重复 |
| surf_content_prepared | 内容准备好，尚不是发送成功 |
| surf_share_accepted | 微信已接受至少一条对应分享，不代表手机播放验证 |

源读取失败与后续工具失败分别展示；出现个别失败不等于整轮失败。历史缺失的细分原因不补编，页面提示旧记录未保存细分原因。手动刷新浏览轨迹保留展开项和阅读位置，不触发新的上网或分享。

## 本次验证

Go 全量测试、vet、相关回归与静态 JavaScript 语法检查通过。隔离的真实模型检查从多源发现开始，模型自行选择 `web_media_download`，准备了实际 B 站长视频播放卡片，历史状态为 `prepared`、原因为 `surf_content_prepared`；微信发送数为零。这验证到真实内容发现、模型选工具、来源核实和卡片准备，没有向群里发送测试内容，也没有验证该次手机端播放。
