# 群成员目录一直显示“正在查询”的修复

2026-10-27，管理端版本 `0.26.1-catalog-recovery-local`。

## 原因

该群的目录 GET 已在约 32ms 内成功返回 HTTP 200，但本地成员缓存为空。前端在设置 busy 后调用 renderItems，空数组分支因为 busy 为真而不更新提示；成功分支又只为非空列表设置完成提示。因此请求结束、按钮恢复后，文字仍停在“正在查询目录”。

此前“刷新群聊”同步的是群目录，并不保证所有已知群的成员名单已同步。原生服务已有独立的 `/groups/{id}/members/refresh`，管理端尚未接入。

## 修复

- 查询成功时明确处理空数组：普通目录显示无匹配项；群成员解释为本地名单未同步或搜索无匹配，不声称群里没有成员。
- 新增“刷新当前群成员”，通过现有受保护目录同步接口发起指定群的原生成员刷新，完成后重新查询同一个群。
- 群成员刷新校验 CSRF、群 ID 和现有回复授权；不改变群规则、登录状态，不发送消息。其他同步正在运行时不会把它冒充为当前群的成员刷新。
- 查询使用独立请求快照、取消信号和版本号。切换群、类型、搜索条件或退出登录后，旧响应无法覆盖当前结果。
- 目录 GET 使用 12 秒服务端超时；网页 15 秒停止等待。分页失败保留已加载的结果，错误保留可安全显示的实际原因。

## 验证

- 原生成员刷新后，同一群目录读取约 29ms 返回 5 位成员；真实网页也显示 5 位成员并结束加载。只核对数量，不导出成员信息。
- 原生固定刷新路由、权限与 CSRF、同步任务冲突、空页与错误分类的 Go 测试。
- `scripts/test_catalog_ui.cjs` 使用合成目录和刷新操作验证空页结束加载、指定群同步后自动查询、分页失败保留、切换群取消旧请求、超时结束加载；不写真实配置或发送微信消息。
