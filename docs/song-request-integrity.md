# 歌曲请求、参考原曲与歌词依据

所有创作和翻唱都经过 YuE；启用角色歌声后，再对 YuE 输出进行 RVC 等已配置的本地歌声转换。没有绕过 YuE 的直接换声入口。

- `original`：用户要求创作新作品，模型可以写词和选择风格。
- `cover`：用户要求唱已有作品，包括普通生日场景的生日快乐歌。取得真实原录音作为 `reference_asset_id`，使用原歌词与符合原曲的风格；只有用户明确要求时才改变演绎风格。风格、参考模式、时长和种子由模型选择。

实际提交前，由模型独立分析当前请求属于原创、翻唱或不应新建任务。与拟提交模式不一致时，把差异返回原模型纠正；程序不把请求硬改为另一种模式，也不靠曲名关键词表决定。语义判断仍可能出错，因此需要保留真实模型回归与实际试听。

## 歌词依据

`music_reference_inspect` 可实际转写原曲片段（每段最多 60 秒），或通过 `supplied_lyrics` 登记当前用户正文中确实提供的原词。返回 `lyrics_evidence_id`。参考翻唱须提交 `lyrics_evidence_ids`，歌词必须与这些依据按顺序一致，允许加入段落标签和调整空白、标点，不能加入新词。

证据保存在私有数据根的 `music-lyrics/`，绑定音频 SHA-256、范围、来源和转写时间。ASR 文本始终标为候选，不能宣称已经人工校对。旧生成任务自行编写的歌词不会自动变成可靠原词。

模型可联网查找多个歌词版本，再调用 `music_lyrics_compare`：工具实际读取候选网页，验证歌词出现在正文中，用半全局编辑距离把该ASR片段对齐到候选歌词的对应段落。相似度至少88%、差异不超过本段12%且最多12个字符，才生成 `web_aligned_asr` 修正依据；较短或差异大的片段拒绝自动修正。保留原始ASR、修正来源网页与片段范围，不用整首网页歌词替换短片段。相似度不能证明歌手/编曲版本相同，仍由模型核对版本；不确定时继续查其他版本或重新转写。

同一公开 B 站录音的音频哈希与来源 URL 均一致时，可以复用其 ASR 候选，减少不同群重复猜词。用户提供的歌词、私有上传音频和群聊历史不通过这个机制共享。`available_lyrics` 只返回匹配的候选与来源，不返回其他群身份或聊天。目录最多保存 1000 条；满时拒绝新增，不删除仍被任务引用的记录。

## 恢复与交付

YuE 桥接在私有任务记录中保存实际提交的歌词、风格、种子、参考模式、时长和参考音频哈希，不仅保存文件名。后台管理接口可把人工准备且已完成的 YuE 任务关联到 24 小时内的真实歌曲请求：`POST /api/agent/recover-music-message`，参数为 `message_id` 与可选 `prepared_job_id`。该接口需要管理员登录和 CSRF，固定使用原请求的接收方；同一请求或歌曲不会重复安排。模型不能调用此管理接口。

补发默认完整拆分为微信语音，只有用户明确要文件时才另发文件。生成完成、附件准备、微信接受和手机播放是不同证据，不能相互替代。群里普通闲聊不代表撤销旧任务；取消仍由模型判断，并需指出实际使旧任务失效的新消息与原因。

YuE 会重新合成音乐。原录音、原歌词和合适风格能约束结果，但不能保证伴奏、旋律细节和歌词演唱逐字无误；音色效果也必须试听，不能把工具成功当作质量通过。

## Windows 本机后台

当前本机已安装 WSL 用户服务时，可运行 `scripts/Start-Local-Admin.ps1` 保持一个隐藏的 WSL 前台会话，并启动已有的 native/web 服务。这样在退出临时 WSL 命令后，用户服务管理器和开发实例仍有持续会话。脚本按工作区标记复用进程，不重复启动；只在账号未认证时请求恢复保存的连接，不清理登录资料、不发送消息、不安装 Windows 开机任务。实例路径、发行版与用户可通过参数调整。Linux 服务器继续使用其正常服务管理，不需要此本机辅助进程。
