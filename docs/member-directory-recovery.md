# 群成员名称查询排查与恢复

2026-10-25 17:09机器人测试群的`wechat_read`调用失败后，模型回复“成员列表没连上”。旧日志只有通用失败文案，没有HTTP状态或参数分类，不能据此精确判断当时是瞬时连接、参数、取消还是目录状态问题。

本次排查：原生微信群成员接口HTTP200，返回2位成员；通过同一管理端配置和实际原生接入的`wechat_read(kind=members)`也返回2位成员。随后用独立临时记忆调用真实模型，模型实际选择成员工具、读取同一群并生成回答。没有向微信发送验证回复，没有修改原群规则或重开登录。

改动：

- 原生目录GET遇短暂传输中断可补试一次；不补试任何发送或账号写操作。父请求已取消则及时停止，区别于微信断线。
- 固定错误码区分取消、超时、读取鉴权、资料不存在、失效分页游标、无效响应和后台拒绝；系统日志和模型都得到相同准确原因，错误不携带任意上游正文、凭据或路径。
- 成员查询限定真实群会话；工具明确先省略cursor、下一页只能用返回的next_cursor，避免把0或页码当游标；群内称呼优先roomDisplayName，再用displayName，唯一用户名仍保留。
- 参数错误或分页失败不会被改成空名单或假装成功。尚未同步的群成员资料仍明确显示缺失；群目录同步并不保证所有群成员名片已加载。

验证包括合成断连后的GET恢复、HTTP错误分类、群/私聊边界、日志原因保留、真实原生目录和真实模型无外发预演。历史具体失败原因仍无法从原日志恢复，后续相同问题可由新分类直接定位。
