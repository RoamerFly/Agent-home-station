# 上下文传递与歌曲请求修复

版本 `0.31.6-song-quality-local`（包含0.31.3修复及后台调用链补修）。

## 成品时长与听感核对（0.31.6）

实际发现180秒请求只提交90秒参考，YuE生成约93秒后仍被交付。`max_duration`在上游节点中是上限，模型可提前输出结束符，不能把请求值当作成品时长。此前女声条件已传入但成品仍呈男声；提示词生效不等于听感符合。

- 翻唱默认原生文本引导为2，允许`text_guidance_scale`显式调整0..100；把独唱性别明确置于有效风格开头。它加强条件，不构成女声保证。
- `min_duration_seconds`默认目标90%，可显式调整（0允许短预览）。桥接v7实测时长，明显不足保留输出并返回`generation_duration_shortfall`，不循环、填静音或拉伸补时长。
- `music_local_status`返回`generation_result`，区分实际秒数、请求秒数、时长验收和声音观察。已配置百炼时，从成品前、中、后三处各取15秒真实音频交给Qwen3.8-Omni-Flash观察主唱/歌唱/失真，按音频哈希缓存；失败明确报告，不冒充听过或检查通过。观察资料交回Agent判断，抽样模型结论不等于全曲人工试听。
- 管理员可显式采用新的已完成YuE成品重新交付原请求；以新任务编号幂等，不覆盖旧歌曲、旧任务和旧回执。普通恢复仍不会凭同一消息盲目重生成。

合成回归覆盖原生参数传递、过短成品拒绝、SSE观察完整性、持久配方和重复采用幂等。实际新成品约180秒，前中后片段音频观察为女声；最终手机听感另行验收。原始录音、实际歌词、模型听感原文和真实消息不进入仓库。

## 核对结果

管理员报告的最新具名歌曲请求被实际提交为original和male，任务与YuE保存的配方一致，未包含参考音频或参考哈希。这解释了男声参数和重新作曲路径，不是一次已正确准备的参考翻唱。

检查时对应会话没有压缩摘要或已压缩消息。因此不能归因于压缩遗忘。历史模型HTTP请求体未完整留存，无法还原当时所有字节或证明模型关注了哪些句子；以下问题从相同源码路径可复现：

- 原生工具提示里同时存在“已有歌曲应翻唱”和“music生成是原创演唱”的矛盾说法。
- 原生function calling重建system时，使用了过早保存的baseSystem，丢弃后追加的资源需求与来源处理提示。
- 男声参数只检查枚举，没有验证是否来自用户明确要求；original模式也没有拦住本次明确具名歌曲的误路由。
- 一个长历史媒体观察可能占满历史输入预算，导致前面的短对话一起被排除。

## 当前数据流

```text
接收消息和真实发送者
  → 会话权限及原始请求
  → 读取会话记忆；必要时压缩旧前缀，原文保留
  → 系统基础设定＋角色＋当前能力策略
  → 压缩摘要＋按时间排列的近期历史（长记录标记节选）
  → 工作区指南索引与会话MEMORY节选（明确标记，可继续读取）
  → 当前消息、引用、最近媒体来源（当前请求完整，放在最后）
  → 按需工具发现与原生function calling
  → 工具结果、用户新补充；必要时整理旧执行记录
  → 模型继续决策；系统策略始终单独保留
  → 工具参数校验、真实执行、持久任务与投递
```

系统规则不是压缩记忆的一部分，不能依赖模型从旧聊天回忆。历史男声/原创配方是已发生的事实，不自动成为下一首歌的默认值。

## 修复

1. 歌曲规则集中在 `internal/companion/policies/music.md`，嵌入程序，并在每个具备歌曲能力的请求中作为system策略提供；消除相互矛盾和重复的大段规则。原生与非原生工具路径共用。
2. 调整baseSystem捕获位置，原生路径保留资源需求指导。
3. 所有歌曲默认native女声。模型提交male时须引用当前用户明确要求男声的原文；没有依据返回可修正错误，不静默改参、不开始生成。原唱性别不是请求依据。
4. 本次这类具名演唱请求误用original时，提交前返回需要真实参考的cover错误；明确原创仍支持，不把生活主题一律认成固定作品。
5. 翻唱生成风格自动加入“保持原曲调和原歌词”，参考模式默认full，显式melody仍保留。歌词与同源依据校验不变；实际参考哈希随任务保存。桥接的实际工作流与持久配方也使用同一有效风格，避免只改聊天提示而未传到模型。
6. 长历史文本按上下文预算逐条节选，保留时间、身份、记录编号、媒体来源与截取标记。原始记忆不变，当前请求不经过历史节选逻辑。工作区节选按UTF-8边界，并提供节选标记。
7. 每回合首个模型调用记录 `model_context_prepared`：系统/输入字节数、实际历史条数与节选数、是否有摘要/工作区/当前请求、可见工具数和策略版本。诊断不保存提示词、消息正文、Key或工具参数。
8. 同一发言者在执行中补充的文字同步给歌曲意图校验，避免模型已看到“这次用男声”，工具仍只检查最初请求；其他发言者、其他会话及媒体观察不构成例外授权。
9. 删除所有自动聊天兜底文案：无结果/超时结束语、被@后的固定招呼、资源失败拼接句、未看视频的固定替代回复、强制冲浪的标题链接替代发送。资源失败与观察校验结果交回模型组织最终回复，模型选择安静不被程序改成发言；模型本身失败只记录异常，不生成替代台词。交流策略要求内部核验不要复述进聊天；执行、权限与回执校验仍保留。

## 后台调用链补修

0.31.3的直接调用与隔离模型测试没有覆盖真实微信后台的generationTools包装层。后续检查发现该层没有透传AutonomousActions、ContextPrepared和ObserveFollowups，导致底层自主模式没有生效、上下文诊断缺失，执行中新补充也没有进入底层意图校验。

0.31.4透传这三个可选接口；是否启用自主能力仍由内部权限实现决定，包装层不自行授权。新增真实后台调度回归：在默认调用数为1时，由模型连续选择35次合成分页读取后自行完成，验证诊断上报与补充事件仍能到达内部工具。

歌词依据/参考素材的本地参数错误现在以安全的具体原因返回模型，不再被抹成“工具连接或执行失败”。YuE状态错误也实现统一安全反馈接口。原音频、歌词对应关系和真实投递校验保留；修复不创建歌曲、不重放旧任务、不发送聊天。

## 联网鉴权与日志入口

搜索调用在后台通过配置的API Key设置Bearer请求头；不把Key放入网址、浏览器链接或模型参数。搜索服务接口与实际搜索结果页是两类地址：日志和冲浪页面将服务接口显示为不可点击的服务标签，内容网页仍可打开。直接在浏览器打开搜索接口不携带后台鉴权，出现missing key并不能证明后台搜索也失败。

搜索客户端拒绝空Key请求，HTTP 401单独标为认证失败；成功调用记录HTTP 200。通用网页读取收到搜索服务地址时返回专用工具使用提示，不向该接口发送无鉴权的网页GET，也不把全局Key注入任意公开网址。其他来源的401、DNS失败、播放资料缺失和媒体类型不符仍按实际原因报告，不能统称为“联网不可用”。

本轮用本机已有Key实测官方搜索返回HTTP 200和实际结果；未复现用户提供的request_id，不能据此断言该单次错误的唯一来源。没有更换Key，也未向聊天、仓库或测试输出暴露凭据。

## 验证边界

合成测试覆盖男声误参、具名误原创、明确原创/男声例外、原词原录音绑定、有效风格幂等、原生指导保留、执行记录整理及长视频不挤掉短偏好。

隔离真实模型测试加入旧male/original历史，以合成录音、歌词和生成服务验证新请求选择female/native/cover及参考依据。测试不读取生产任务存储、不真实生成歌曲、不向微信发送。

以上是参数、上下文传递和工作流验证。YuE按音频提取旋律/和弦后重新合成，女声标签和保真提示不构成音色、逐音符旋律或手机播放的质量保证；新的实际成品仍需试听验收。未修改旧任务配方或重发已送达的旧作品。

## 参考片段识别与上传

0.31.5修复长前奏被当作短翻唱主体的问题。下载成功、ASR取得后段歌词，并不代表源音频开头就是演唱；生成时长短于前奏时，完整参考的开头可能仍是人声休止。

- music_reference_inspect返回实际ASR窗口与候选区间，提示核对演唱、伴奏和口播，标题仅作为来源线索。
- music_local_start新增reference_start_seconds和reference_seconds。默认起点来自本次提交且匹配原音频的歌词依据，默认长度采用目标时长及已观察范围。显式0和显式时长按原值处理；单段600秒是现有YuE工作流范围，更长目标可分段。
- 管理端先在本机截取192kbps AAC片段（完整原曲不转码、不覆盖），核验实际长度，再上传片段。完整原曲保留。请求和任务保存原曲哈希/起点/时长，桥接配方另存上传片段哈希与pretrimmed标记，避免二次从70秒截取一段本来只有60秒的上传文件。
- 桥接v6支持片段；旧桥接会返回升级提示，防止悄悄忽略定位参数。桥接保存实际准备时长与哈希；源文件不足显式请求范围时返回原因，不静默截短。

验证包括合成音频真实FFmpeg截取、范围越界、显式0、音频绑定的默认选段、片段上传与幂等、桥接避免二次裁切。现有录音的真实ABC提取检查与歌声质量分开记录；原曲和生成物的实听仍是独立验收，不凭配方宣称音色/旋律已经通过。
