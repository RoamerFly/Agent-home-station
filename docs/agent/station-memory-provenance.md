# 工作站跨来源请求的持久证明

工作站通过 `app_memory` 读取微信或抖音来源后，在向模型返回资料前，把来源和授权版本写入原用户事件的工具检查点。记录绑定本机主人、鱼身份和原事件修订，只包含来源元数据；检索词、摘要、正文、临时引用和分页状态均不写入该检查点。

- 微信证明包含实际连接、账号、会话、授权修订与时间戳、数据库实例和 RecallEpoch；封存档案同时保留档案与可见性指纹。
- 抖音证明包含来源范围、私有账号绑定、配置修订和存档 generation。私有绑定显式序列化，恢复后仍与实际连接核对。
- 未写完、未知版本、主人不一致或指纹不符的记录会阻止恢复，不能当作无跨来源查询继续处理。

## 恢复与成品

同一原请求的模型重试先恢复证明并核对来源，再准备模型。恢复证明不会恢复正文或旧引用；需要内容时仍由本轮主动查询。已完成请求再次通过聊天提交接口取回结果时，也会核对当前来源。已经保存的可见历史不因撤权删除，但不能通过重试重新取得已失效的跨来源回复。

后台本机任务在读取结果和继续生成前核对原请求证明。撤权、更正、遗忘、账号或数据集变化使等待任务停止；后台不会凭旧聊天正文继续调用模型。

成品保持原 ID、原件和父成品链接。在登记、读取与打开前后核对原请求及父链上的证明。换一个请求派生成品不会去掉父来源的限制。检查失效后保留磁盘原件，不返回新的下载或读取结果。大文件复制过程继续使用已有的本机来源和家目录栅栏，外部记忆的数据库检查放在操作边界，避免逐缓冲区重复打开来源库。

首版跨应用查询结果仅供本人私下读取。原请求使用了跨来源资料时，文本作品不能公开发布；成品或其父来源使用了跨来源资料时，也不能借其他应用的发布授权公开上传。此限制独立于目标应用的发布权限。

## 本阶段范围

本阶段为新发生的工作站 `app_memory` 查询提供持久证明，并接入原请求恢复、本机异步结果、成品父链和作品发布边界。不会替旧查询补造当时未保存的证明，也不宣称旧成品已经完成来源审计。

工作站已增加下述明确关联请求入口。微信原生引用消息关联续办、跨应用明确转发，以及生成器运行中每个外部调用的完整来源矩阵仍需接续实现。普通对话不会因恢复机制预载其他应用资料。

新增合成专项为 `TestMemoryEvidence*`，覆盖重建宿主与 SQLite 后恢复、抖音私有绑定往返、微信遗忘屏障、撤权后重试受阻、原任务停止、父成品来源保留、文本与成品公开发布阻止、异常检查点和普通聊天兼容。没有使用真实账号内容、外部模型、真实平台发送或开播。

## 工作站明确关联继续

具有持久跨来源证明的回复显示「关联继续」。点击后在输入框上方显示关联提示，可取消且保留草稿。关联只作用于本次新发送；失败时按原请求编号重试保留已保存关联，不能改成另一个原请求。下一条普通消息不自动关联。加载聊天历史只核对本机证明元数据，不读取应用记忆正文。

`POST /api/local/chat` 可附带 `continue_request_id`，服务端在当前管理员会话和 CSRF 校验下，将其解析为同一主人已完成的真实原请求。新的请求保存原事件修订、实际来源和证明指纹，不能从工具参数、昵称或正文自建关联。原请求不具备当时的持久证明、未完成或已失效时，提示重新选择或主动查询。

首轮模型只知道主人选择了关联；不会带入原回复正文或检索结果。`app_memory` 的 `linked_sources` 仅列此关联的来源元数据，后续按 `search/read` 主动读取并取得本轮新引用。原临时引用和分页游标不恢复。后续原请求增加的来源不会自动扩大已建立的关联范围。

关联链保留每个原事件版本，并在工具执行、最终回复、重试和成品读取时核对；原请求更正、遗忘或原资料撤权使后代关联失效。链采用迭代遍历并拒绝成环。成品即使只来自关联、没有再次查询，也保留原来源证明及私下读取限制。

原事件来源和工具证明从 SQLite 的精确可见事件修订读取，不要求原请求仍在近期聊天快照中；跨主人、冲突、屏蔽和旧版本仍会拒绝。这里只取证明元数据，不把旧聊天正文装入模型上下文。

新增专项为 `TestMemoryLink*`、`TestLocalRequestSourceAndEvidenceSurviveRecentPruning` 和 `scripts/test_station_memory_link.py`。覆盖正常引擎先目录后查询、下一轮零继承、旧引用拒绝、关联链更正、来源替换、重试绑定、主人会话与 CSRF、宿主重建、关联成品、生成中撤权，以及 375 像素下关联/取消/重试。全部使用隔离合成数据；真实微信引用续办仍未在此入口冒充实现。
