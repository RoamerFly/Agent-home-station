# 消息判断与发送节奏

实时群聊按现有规则进入角色模型；恢复上线后的未读先按会话汇总，结合不同成员的原始时间与后续对话统一判断，不逐条追答。详见[离线未读汇总与任务收尾](unread-conversations-and-task-history.md)。已移除工作循环的同会话冷却、角色接话判断间隔，以及按回复预算推算的判断次数上限。短消息合并仍保留原消息身份；模型可以选择安静，不以间隔长短代替判断。

权限、安静时段和已有会话触发规则继续生效。发送预算只约束实际发送，不再提前阻止模型理解新消息。发送器保存每个气泡的正文、目标和幂等键。微信明确报告可重试失败时，发送器随机退避后重试原文。回执未知时只核对原操作和已提交的历史键，直到收到明确结果。

旧配置中的 `cooldown_seconds` 和 `companion.decision_interval_seconds` 在读取本地配置时被忽略，管理页面和返回配置不再包含这些选项。正常保存配置后旧字段自然消失，不需要修改私有登录或重建配置。

恢复此前被冷却跳过的消息时，先按配置中的积压时间窗口查找原消息，排除已有模型结论、已发送、已有交付计划或已开始工具的记录。暂停并收尾工作循环后备份持久队列，仅将明确跳过的原条目重新排队，保留原 ID、发言时间、来源及已记录收件标志。恢复标记 `historical_review` 会传给模型：结合后续聊天判断是否仍需回复，已取消、已得到回答或过时话题可以选择安静。不得将历史消息伪装为新消息或强制回复。

回归覆盖连续普通群消息均调用模型、达到实际发送预算后仍可判断、旧配置迁移以及恢复标记不会把普通群聊变为被 @。真实恢复结果以本机活动记录、逐条模型结果与微信接受回执分别核实，不将重新排队视为已经回复。

## 在发送中更正请求

群里的一首歌分成三段时，原请求者在第一段之后说“发错了，不是这首歌”即可中断剩余投递，无需再次 @。取消落库后，原生发送器会跳过尚未认领的段。如果第二段已经进入微信提交阶段，程序继续核对它的回执，第三段取消。已接受的段保留回执。引用一个已发分段可以定位其父任务；同一人有多项候选且无法区分时，先暂停候选并询问。

换歌建立独立的新请求。明确续发已取消的歌曲时，指定原任务，由发送器核实哪些段已接受、哪些段尚未提交，以新操作提交缺失部分。仍有在途或未知段时等待原回执。

## 按任务读取资料

普通聊天在本会话内决定是否回应和调用工具。长工作笔记、其他会话和插件文档按需读取。群内管理员查其他会话时，默认私聊交付给请求者。已读资料不足时可先交付有依据的部分，并在执行记录查看覆盖数。手动诊断在管理页发起，使用已保存的候选与有效来源，不触发发送。

## 离线回归口径

固定的 ordinary-group-v1 夹具包含六条合成群聊，使用相同的角色、工具目录和当前消息，统计实际模型调用边界的输入估算值。基线 5b2d683 共 41,123 Token；精简后共 25,187，平均从 6,853.8 降至 4,197.8，约减少 38.8%。每个样本均为一次主模型调用。该数据用于检测提示词和上下文回归，不代表真实账户账单。

历史材料部分可读的用例经正常工具循环选取八条来源，六条成功、两条失败。回合记录实际覆盖数并通过模拟微信端提交部分总结。媒体中断使用本地模拟微信状态与原生 SQLite 仲裁测试分别验证取消和分段提交的顺序。微信服务器及手机播放不在本轮验证范围内。
