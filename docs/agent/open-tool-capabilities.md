# 工具能力暴露与按需读取

版本：`0.29.1-adjustable-defaults-local`。

**工具默认值只是起点，不是能力上限。Agent可按聊天需求动态指定精度、范围、分页、批大小、分辨率、分析预算和执行时间；不得把默认值静默当作固定限制。** 此原则已写入项目AGENTS.md及运行时共享指南tool-defaults.md。

## 本轮问题与改动

旧视频入口只有自动概览：均匀取6帧、转写开头最多180秒，没有可发现的精读入口。模型说“只能取得6帧”反映的是工具接口缺失。现在保留低成本概览，同时提供 `video_inspect` 让 Agent 根据用户需求读取真实连续帧、指定片段和后续音轨。

| 方法 | 原来的能力缺口 | 当前行为 |
| --- | --- | --- |
| `video_inspect`（新增） | 自动6帧之后没有继续读取的接口 | 实际帧数、连续帧/抽样帧分页、真实时间戳、任意音轨起点、模型分析预算与问题参数 |
| `observeVideo` / `videoAudioRange` | 概览被当成全部能力；音轨只处理前180秒 | 概览返回精读方法与本会话原件编号；后续音轨可从任意时间续读 |
| `parseVideoDuration` | 超过1小时直接拒绝 | 不再按视频总时长拒绝；仍校验有效有限时长 |
| `server_list` | 只列200项且无法续读 | 字典序分页，返回 `next_offset`、`total`、`complete`，可读后续全部目录项 |
| `server_read` | 超过1MiB的文本整份拒绝 | 流式计算完整哈希，按字节页读取；可用 `expected_sha256` 检测版本冲突，保持UTF-8边界 |
| `server_search` | 最多扫描2000文件、100命中；大于1MiB文件跳过 | 流式逐行搜索、命中分页；取消/超时有效，无法读取或异常长行明确计入未完整覆盖 |
| `workspace_list/search` | 只回30份；文档总数达到256后拒绝 | 全部文档可分页发现，解除256份数量配额；单文档仍校验UTF-8、容量与版本 |
| `media_recent` | 只显示最近12项，内部5400字节截断 | 保留旧快速数组；显式 `offset=0` 进入全素材分页，返回 `items/total/next_offset/has_more`；移除1000份索引数量配额 |
| MCP `Hub.List/serverList` | 8个服务、40个工具上限；忽略服务端下一页 | 解除数量配额；跟随真实 `nextCursor`，验证游标循环，保留权限过滤 |
| MCP 会话缓存 | 所有 `tools/list` 请求共用第一页缓存 | 仅缓存无游标的第一页，有游标的请求真实读取对应页面 |
| `discover_tools` | 每次只返回前8个匹配，无法发现后续结果 | `offset/limit` 分页；按需把当前页真实schema提供给模型 |
| `VisionWithBudget`（新增） | 视频精读沿用768 Token短聊天预算 | 详细分析独立预算，默认4096；可由工具参数调整，不更改共享客户端和普通聊天设置 |

MCP的工具目录分页遵循 [2025-06-18版官方协议](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-06-18/server/tools.mdx) 的 `cursor/nextCursor`，游标由服务端返回，不能自行编造。

## 视频精读调用方法

先从初始观察、`media_recent` 或当前会话的真实消息取得来源。三种来源只能选择一个：`asset_id`、`message_id` 或公开 `url`。

```json
{"action":"info","asset_id":"工具实际返回的素材编号"}
```

这会返回实际解码帧数、平均帧率、分辨率、媒体时长。逐帧使用 `step=1`，帧编号从0开始：

```json
{"action":"frames","asset_id":"工具实际返回的素材编号","start_frame":0,"page_size":24,"step":1,"question":"按时间顺序总结人物动作与画面文字","analysis_tokens":4096}
```

每批输出真实 `frame_indexes`、`timestamps_seconds` 和分析。继续调用时使用 `next_start_frame`；`complete=true` 表示从本次起点起的后续范围读到末尾，只有从0开始并保留所有已读页，才能判断完整覆盖。`step>1` 是主动抽样，返回 `coverage=sampled_frames`，不能称为逐帧读取。

默认page_size=24、batch_size=8、max_dimension=960，Agent均可动态调整；已移除单页64帧及本地视觉客户端8图硬限制。按批解码、分析并立即释放临时帧，避免把整页图片一次堆入内存。实际字节载荷或提供商要求失败时会返回原因与未读位置，可调整批大小/分辨率继续。timeout_seconds默认240，显式0不添加本地截止时间，仍尊重上游取消。若某批模型请求失败，已成功批次保留，返回未读位置与原因。大结果被保留为 `result_id` 时，先用 `tool_output_read` 续读完整反馈。长任务用 `agent_task` 保存来源、已读范围和下一页起点。

```json
{"action":"audio","asset_id":"工具实际返回的素材编号","start_seconds":180,"duration_seconds":90}
```

音轨默认请求90秒，Agent可以指定更长的duration_seconds，由工具按audio_chunk_seconds（默认180，可调整）处理完整范围；PCM片段若超过8MiB传输预算会分段并返回实际片段大小及原因，不静默缩短请求范围。audio_timeout_seconds默认60，显式0继承上游取消。next_start_seconds用于部分完成后的续读，requested_range_complete表示本次所需范围完成，video_audio_complete表示已到整个音轨末尾；若实际音轨早于画面结束，会返回 `audio_track_ended_early`。转写权限关闭、没有音轨、解码失败或提供商不可用会明确失败，不把画面观察当成听过音轨的证据。

## 文件、目录与素材的续读

```json
{"path":"运行节点上的已授权绝对目录","offset":200,"limit":100}
```

上例用于 `server_list`。`server_search` 增加 `content` 搜索文本，offset指匹配行数；遇到 `has_more=true` 继续下一页。搜索基于实时文件系统，目录变更后应重新核对；异常长行、非UTF-8或无法读取文件会报告 `skipped_files`，不能声称已经完整搜索。

`server_read` 的offset/length以字节计；显式length可以大于默认输出长度。仅在JSON转义后的结果无法装入1MiB保留结果传输封套时拆页，并返回requested_length/effective_length、原因与next_offset；连续读取必须使用返回的 `next_offset`，可传上次完整 `sha256` 为 `expected_sha256`。读取期间文件变化会拒绝混用两个版本。`workspace_*` 的offset以文档计，`media_recent`以匹配素材计。

## 保留的执行边界与可替代路径

- 账号、会话、真实发送者、服务器授权根目录和外部工具权限仍逐次检查；读取资料不能授予新权限。
- 数据格式校验、哈希/版本冲突检查、发送幂等与动态延迟仍保留，避免损坏文件或把不确定发送当成未发送。
- 单次网络下载最大64MiB、已有素材缓存512MiB和索引16MiB、单份Markdown64KiB、原子编辑器1MiB/新建文件64KB、传输与输出预算仍是当前资源边界。超过单次载荷可拆分；可信主人也可使用已授权的 `server_process/server_windows_process` 与项目程序处理原文件。不能把这些单次接口边界说成整个Agent不会读取或处理。
- 图像提供商可能有自身的模型、上下文、输出和格式要求；`analysis_tokens` 是请求参数，实际可用范围以提供商响应为准。
- 本轮没有实现所有站点的登录/解密能力、无限磁盘、无限模型上下文或无限单请求内存；原始资料仍需能实际取得。

共享工作区有 `tool-reading.md` 与优先适用的 `tool-defaults.md`。它解释分页、逐帧、音轨续读与持久化检查点；工具schema按需发现，避免把所有参数说明常驻模型上下文。

## 验证证据

- 合成2秒、12FPS视频：精确读取24帧，跨13帧/11帧两页，真实时间戳严格递增，没有重复旧图片。
- 已配置真实视觉模型：同一合成视频分4个模型批次读完24帧。真实模型返回非空分析；没有读真实群聊、修改活跃记忆或发送微信。
- 合成181秒音轨：默认概览180秒，再从180秒继续读取1秒，证明没有总180秒截断。
- 大于1MiB中文文本、216目录项、215命中、超过2000个文件的搜索、257份Markdown、35份文档分页、14个素材分页。
- MCP60个工具分两页发现、重复目录请求的游标页缓存隔离、错误循环游标拒绝；9个已配置服务接受。
- Agent原生function调用模拟：读取两页工具schema，再真实执行合成目录中第12个工具，证明后续匹配可发现并调用。

合成调用、真实模型分析和微信投递是不同证据。本轮没有向任何微信会话发送测试消息。更新只替换本机管理服务，保留微信登录、私有配置、历史记录和已生成媒体，不构建或导出Docker镜像。


## 可调整默认值的验证

- 合成96帧视频中指定一页80帧、每批20帧，实际分4批解码和分析，跨过旧64/8限制；批次临时帧及时清理。
- 本地视觉HTTP契约测试接受12图请求，普通聊天预算不变；当前配置的真实视觉模型也以每批12图、共2批接收24帧并返回分析。其他提供商可接受的数量以真实响应为准。
- 指定240秒音轨范围、200秒片段时完整处理240秒；片段请求600秒超过PCM传输载荷时明确分段，仍处理完整范围。
- server_read显式读取40000字节，超过默认16000；超传输封套时保留可继续的起点与明确原因。
