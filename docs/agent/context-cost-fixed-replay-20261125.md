普通群聊 12 条时间线记录按 JSON 字段累计，最大的是 `source` 4,970 字节／约 2,058 token，占该历史包字节的 37.8%；随后是 `source_event_id` 1,008／336、`temporal_precision` 888／429、`participant_relation` 570／234、`user_text_state` 444／192、`at` 420／228、`message_sender_id` 408／198。`text` 只有 396／180。这里按每行的键和值独立估算，不是提供商逐字段账单；字段内容没有写入结果。`source` 的重复结构是后续投影视图优化的主要候选，但消息 ID、来源和修订仍须可追溯。

这 12 行的嵌套 `source` 均含 `account`、`body_hash`、`event_id`、`instance_id`、`integrity`、`message_id`、`received_at`、`revision`、`sender`、`thread`；`source.event_id` 与顶层 `source_event_id` 在夹具中 12/12 相等。该等值关系只能作为压缩时的守卫条件，不能推断所有真实记录也相同。

这组夹具使用真实 Admin 工具注册表，但权限、历史和请求都是合成的。工具盘点场景首轮有 7 个工具、定义共 4,307 字节；正式私聊历史记录的首轮有 9 个工具、6,462 字节，两者**不是同一个分母**。正式记录没有逐工具大小字段，因此不能把合成工具排序当作当时 9 个工具的精确清单。原任务续办夹具的首轮没有带入 `conversation_context`，该数值不用于判断真实任务能否恢复历史。两次快照均只产生一次假模型请求，工具调用和后续轮数的收益需要单独回放。

## 重跑

在本仓库工作树中创建两个**可丢弃的独立源码快照**，用同一脚本与 Go 环境运行。脚本会短暂写入合成测试文件，完成或失败后删除；结果文件放在忽略的 `temp` 目录。

```powershell
$repo = (git rev-parse --show-toplevel).Trim()
git worktree add --detach (Join-Path $repo 'temp/cost-eefe7cf6') eefe7cf6
git worktree add --detach (Join-Path $repo 'temp/cost-c95e13b7') c95e13b7
python scripts/probe_context_cost_fixed.py --source-root (Join-Path $repo 'temp/cost-eefe7cf6') --output (Join-Path $repo 'temp/cost-eefe.json')
python scripts/probe_context_cost_fixed.py --source-root (Join-Path $repo 'temp/cost-c95e13b7') --output (Join-Path $repo 'temp/cost-c95.json')
```

后续优化版本用相同名字长度的独立快照和上述夹具再跑一遍，并分别报告相对 `eefe7cf6` 与 `c95e13b7` 的变化。已稳定的当前工作树也可显式传入 `--allow-current`；脚本会短暂加入测试文件，因此不要在其他人同时修改源码时运行。正式请求只用于补充自然流量的匿名趋势，不与合成夹具直接计算节省比例。
