# 可识别的账号目录与私人声线

账号权限依据真实稳定账号 ID，不依据昵称或物理目录名。原来 64 位目录名是账号 ID 的 SHA-256，提供稳定隔离，但不便人工识别。
现在控制目录的 `workspace-directory` 保存已选定的可读目录名；改昵称不会自动移动运行中的文件。
新账号使用可读账号 ID 加短标识。已有旧目录保留兼容读取，只有完成校验迁移后才切换。

每个账号目录下：

```text
pri_workspace/
└─ 可读账号名--短标识/
   ├─ account.json       # 稳定账号与目录绑定；不含登录态或模型服务密钥
   ├─ account.md
   ├─ WORKSPACE.md
   ├─ voice-library/     # 按角色名建目录；catalog.json 是全库索引
   │  └─ 角色名/
   │     ├─ role.json    # 角色及其引擎版本索引
   │     ├─ weights/
   │     ├─ references/
   │     └─ previews/
   ├─ global/            # 管理员全局笔记与任务
   ├─ conversations/     # 群聊/私聊独立工作区
   ├─ assets/            # 本账号素材原件
   └─ music/             # 本账号歌曲任务与产物
```

公共 GPT-SoVITS、RVC、YuE 源码仍在 `public_workspace/projects`，公共基础模型在 `public_workspace/models`。
公共角色库使用相同结构，例如 `public_workspace/models/voice-library/曼波/weights/`。一个角色可有多个引擎或训练版本，网页分别显示角色数与版本数。
私人声线不能放入公共模型目录。管理员在任何已授权会话中可用 `global=true` 读取当前账号私人声线；普通成员不会因此获得访问权。

`voice_library_prepare` 对已迁移的私人声线校验后返回原有文件路径，不重复拷贝模型；旧控制目录归档仍支持准备到 global，方便渐进升级。网页语音库使用同一账号内的索引和文件。

## 迁移操作与校验

`scripts/rename_account_workspace.py` 默认只生成只读计划。执行前先 drain 管理进程、确认没有运行中的生成/发送任务，然后停止管理与音乐 worker，保持原生微信在线。明确提供工作区、当前账号管理目录、消息状态目录、账号 ID、目标名称及私有备份位置后才能 `--apply`。

迁移逐文件校验复制私人声线库，并将账号目录在原卷重命名。只重写运行状态 JSON 中以旧根目录开头的路径和指定任务命令；聊天正文、摘要文本、歌词、上传原件和生成媒体字节保留。冻结的 YuE 检查点若需要修改则中止通用迁移，先处理配对摘要，防止破坏恢复校验。迁移保留稳定素材 ID、账号 scope、任务和回执。

新服务启动并核实语音库、音乐服务、项目目录和登录态后，才能删除已逐文件验证相同的旧声线副本。原始训练项目目录不属于这次清理范围。

`scripts/organize_voice_library.py` 默认预览角色整理计划，`--apply` 才迁移。文件保留原名；冲突时依据内容身份区分，文件下载 ID 保持不变。公共 RVC 配置与权重一起归入角色目录，配置原字节及任务指纹保留，运行时仅用已登记哈希解析迁移后的同目录文件。

`account.json` 中的账号和 scope 必须匹配；不能将其他账号的现有目录当作当前账号使用。目录名不改变音乐 broker 的账户绑定：请求头仍由服务端依据真实账号生成，带可读名称的目录从身份元数据核验 scope。

## 摘要压缩

摘要先解析为受约束的结构，再统一序列化并按实际内容长度校验，避免缩进或 Unicode 转义形式触发误判。修复模型会收到具体字段/长度错误，成功后才提交摘要与覆盖位置；格式持续不合格或并发修改时保留原始历史。
同一会话按快照和压缩锁处理，其他会话可独立压缩。原始消息仍可通过历史查看，不会因压缩被删除。
