# 离线未读汇总与任务收尾

版本 `0.34.0-unread-conversations-local`。

## 三种执行回合

- 实时消息：收到新微信消息后判断，短消息可以按现有会话规则合并。
- 未读汇总：恢复上线时先读取保存游标之后的完整事件分页，再按各自群聊/私聊汇总尚未处理的消息，交给模型综合判断。不同发言者属于同一段会话，不逐条追答；已处理记录不重放，已开始工具的中断工作继续遵循原动作记录。
- 任务续办：由之前明确保存的检查点、程序或工具结果触发，不是新入站消息。普通续办不强制回复，模型可以继续、保存等待、完成或保持安静。

未读消息包含真实消息 ID、发言者/昵称、原发送时间和正文；模型同时获得当前时间、时区和整段未读。媒体仍走实际读取，观察结果与原消息关联。原始时间单独显示，接收/执行日志时间仍表示后台实际发生时间。未读正文从历史上下文中去重，不把整段汇总写成某位成员的新原话。引用、发送身份、会话授权与动态发送间隔继续有效。

首次安装没有旧游标时仍从当前尾部开始，不擅自补答整个微信历史。积压恢复遵循已有恢复窗口和真实存储/服务边界；无法取得原消息时保留待查状态，不声称已经读过。

## 持续任务

业务完成与回复被微信接受分别记录。文字和媒体都进入交付核对：仅发出“收到”不能让仍在等待外部结果的任务完成；模型已产出结果但等待发送回执的任务继续显示为等待交付。

确认结束的任务从活跃 `agent-state.json` 任务映射中移除，保存在私有 `archive/agent-tasks/` 中用于回执、幂等与历史核查。页面和默认 `agent_tasks` 工具仅显示活跃任务，历史需主动打开，旧任务不会因为重启自动变成新的请求。未知或失败回执不能伪装成送达。历史中较早版本的“执行完成”可能没有交付回执，保留原说明，不能由归档推断已收到。

后台诊断程序归属于发起它的父任务。程序结束后把真实结果写回父任务，不携带原用户目标再次独立聊天或生成歌曲。独立提交的后台程序仍可以由原会话取得结果。后台结果明确标记为背景资料，不触发“必须再次搜索/下载媒体”的资源规则。

## 验证

合成回归覆盖跨两页、两位成员的104条未读只进行一次判断，原话/原时间完整保留，子消息同步完成，重启不重放；另验证旧发送期间的新停止指令、交付未知不清理、确认后移出活跃表、重启/账号隔离、进程结果归并父任务、后台结果不强制重新找歌。测试不发送真实微信消息。
