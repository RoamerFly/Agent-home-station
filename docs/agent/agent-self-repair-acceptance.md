# 自主修复和本机程序启停验收

这次验收使用生产 Agent 的模型决策、服务器文件工具、持久化任务和微信私聊反馈。测试请求由已认证管理端提交，明确标记为合成验收请求；不能据此声称验证了真实微信入站触发。

## 实际验证

- 独立报价项目先复现两个故障，再由 Agent 读取 README、修改业务源码并运行测试：满 100 元免运费的边界，以及报价文案把分误显示为元的问题。测试文件保留原始哈希，另有独立验证程序检查 16 种情况。
- 本机真实文件 `scripts/agent_probe_service.py` 最初含有 `args.prot` 属性错误。Agent 使用 `server_edit` 将其改为 `args.port`，修复文件实际落在 Windows 项目目录。
- Agent 通过 Windows PowerShell 启动本机 Python 程序；独立观察器验证了 Windows 可执行文件、实际脚本路径、进程 PID 和回环 HTTP 健康响应。之后由 Agent 请求关闭，再检查进程退出和端口释放。复测对应的状态文件包含 `started → shutdown_requested → stopped`。
- 操作笔记写入私有会话工作区。测试反馈只发给主人私聊，并分别检查微信服务端接受记录；服务端接受不等同于人工确认阅读。

## 测试暴露的问题及修复

1. 普通聊天的短输出预算也用于工具调用，导致修复已执行但后续决策被截断。Agent 工具轮使用独立的 4096 token 输出预算，普通聊天配置保持原值；主人任务在模型轮失败后保存状态并退避继续。
2. 任务检查点可能丢掉之前实际执行的结果，造成“已经关闭却报告没关闭”。现在保留原始目标和最近的真实工具执行结果，跨轮继续时一并提供；命令退出码和超时状态都保留，不能用工具外层调用成功代替命令执行成功。
3. 已允许的好友私聊不再要求 `/ai` 前缀；文件传输助手继续保留显式前缀。受保护的补办接口只能读取真实入站身份和正文，并检查旧跳过原因，不能任意伪造消息或重放已处理消息。

## 可复验入口

在已有主人、任务和服务器执行权限下，管理端提供以下带登录和 CSRF 验证的接口；接口不会自行提升执行权限：

- `POST /api/agent/repair-tests`：创建隔离测试项目并交给生产 Agent。
- `POST /api/agent/repair-tests/{id}/followup`：第一轮验证通过后提交第二个故障。
- `POST /api/agent/repair-tests/{id}/lifecycle`：提供已授权目录中的程序和说明路径，安排实际文件与进程验收。
- `GET /api/agent/repair-tests/{id}`：读取测试哈希、独立验证、笔记保存和任务状态。
- `POST /api/agent/recover-private-message`：按真实消息 ID 补办旧前缀规则跳过的私聊。

本机诊断程序仅监听 `127.0.0.1`，不接触账号、模型或微信数据。常规回归可运行 `python -m unittest discover -s scripts -p test_agent_probe_service.py`，它使用独立子进程验证启动、健康检查、关闭口令和实际退出。

本次证明的是受控真实文件修复和真实 Windows 程序启停，以及生产 Agent 对应的执行链。没有将它扩大为任意业务故障均能自主修复的保证；真实微信入站仍需单独验证。
