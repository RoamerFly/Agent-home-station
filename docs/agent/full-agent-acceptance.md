# 自主工作权限与实机验收

当前权限以 [受管工作区](managed-workspaces.md) 为准：每个账号有独立私有目录，每次请求按真实微信账号、会话和发送者派生文件及执行范围。普通成员可使用本会话文件和只读公共项目；可信主人可修改公共项目，并以单次全局调用统筹本账号其他会话。文件工具、Shell及子进程均受系统隔离，旧配置中的宿主根目录不能扩大实际挂载范围。

Linux使用Bubblewrap，Windows使用隐藏LPAC执行器；管理服务凭证与控制文件不挂载给Agent。当前音乐执行迁入受管Linux环境，项目通过清单发现。下文早期实测记录曾使用迁移前的宿主Windows/WSL执行路径，仅保留为历史事实，不能作为当前仍可访问整机磁盘或运行宿主PowerShell的授权。

## 工作能力与配额

- Agent 工作轮不消费工具调用次数额度，主人持续任务不消费主动问候次数额度；不再用任务执行轮数结束续办。
- 后台程序不再限制为 4 个并发、200 条历史记录或最长两小时。`server_process` 缺省 `timeout_seconds=0` 表示不设执行截止时间；可显式设置正数超时，也可以取消。权限撤销和管理服务关闭仍会停止受管程序，不会在重启后盲目重放。
- 任务历史不会因超过旧的 8 MiB 门槛拒绝保存或重启；较长调度不再限于一天。输出分页、消息大小、文件冲突检查、幂等发送及操作系统和服务商本身的限制仍适用。
- `agent_clock` 提供实际时间。`agent_task` 保存检查点、到期时间与父子任务关系，并返回真实存储文件 `admin/agent-state.json` 和 `due_at`，供核对磁盘任务。定时任务应按用户要求设延时，发送动态间隔由发送链路处理，避免重复追加。
- `wechat_send_text` 支持当前和其他已授权会话，使用稳定请求键防止重复。排队不等于接受，随后用操作回执核验；发送失败与参数错误应给模型具体可操作的本地错误原因。
- 文件、程序与任务工具通过原生 function calling 提供，其他能力可动态发现。插件和 MCP 目录以实际连接为准；Codex 平台专有能力不能直接复制为机器人 API，需要相应的独立服务。

## 迁移前的本机历史实测

以下测试发生在受管工作区改造前，通过已认证管理端的模拟微信请求提交，明确标记为模拟入站；后续使用生产模型、真实工具、本机真实文件、真实服务与微信私聊发送。没有伪造微信原生入站包或回执。当前隔离、跨会话附件及音乐兼容性分别以受管工作区文档的新验收记录为准。

1. 在 YuE 项目的独立 `app/temp/agent-live-acceptance` 目录准备有故障的 `probe.py`。Agent 先实际运行并看到 `lost duration for 60: [55]`，随后自行读取源码，将分段步长 60 改为 55，只改该测试文件。Windows Python 运行四个内置检查通过，并写出 `execution-result.json`（`platform=win32`、`verified=true`）。主验收再独立检查 0–500 秒共 501 个输入，时长完整、分段均不超过 55 秒。
2. Agent 检查真实 YuE 队列为空，执行关闭，核实 6188/8188 无监听，再重新启动。独立观察器记录了两端口均关闭，以及重新监听后 ComfyUI 和认证桥接健康。最终服务与守护恢复运行，模型、已有歌曲和登录数据保留。
3. 首轮定时任务虽实际落盘并被调度，但“仅允许其他会话”的发送限制导致未完成。修复当前会话发送和具体错误反馈后，又发现旧同文请求影响计时理解，增加新请求接收时间与来源标识。
4. 最后的独立测试要求从本条新请求起等满 60 秒，只私聊发送“你好”。Agent 保存等待任务，到期执行；实测约 85 秒后提交发送，随后取得原生 `accepted` 状态和服务端消息编号，并完成任务。等待回执时保存检查点再核实，没有另起请求重复发送。这不是秒级精确定时，调度、模型和随机发送间隔都会增加延迟。

测试的原始对话、工具记录、任务编号、回执、观察文件和本机配置保持私有，不提交到 Git。以上证明受控任务的实际执行，不能扩大为所有故障均能修复、所有工具连接均已验证或人工确认已阅读。

## 管理端验收接口

受管改造后的代码验收项目位于当前账号、主人私聊会话的 `scratch/repair-tests/<id>`。故障复现、单元测试和独立评分器都通过同一Bubblewrap执行器；导入被修改模块及其子进程时，管理配置、宿主文件和其他账号数据仍不可见。当前该评分执行后端为Linux，其他平台或隔离缺失时返回不可用，不回退宿主Python。普通Agent的Windows LPAC程序能力另行配置，不能用早期Windows历史验收代替现有评分器兼容性。

旧路径的验收记录仍保留，但不会直接执行。新项目创建、测试写入和摘要检查使用会话根下的`os.Root`，拒绝外部链接、路径越界和冲突覆盖；Linux非阻塞打开避免Agent创建的FIFO卡住控制面。执行期间持续检查主人和执行权限，撤销时取消沙箱。执行器失败与“成功复现了测试故障”分别报告，前者不会自动安排修复任务。

合成专项已在本机Linux验证：父进程及其Python子进程均无法读到测试宿主文件、另一账号目录和管理控制文件；运行中的评分器在权限撤销后停止。测试同时覆盖原有故障修复、第二阶段追问和16个独立检查。Windows执行了记录身份、旧路径拒绝及文件冲突检查；Linux完成外部符号链接和FIFO检查。未因此向真实微信会话发送消息。

- `POST /api/agent/owner-requests`：提供 `recipient`、`text`、稳定 `request_key`，提交已配置主人的模拟微信对话。需要管理端登录和 CSRF；不提升原有权限。同键同文不会重复创建，同键异文拒绝。
- `GET /api/agent/capabilities?owner=...`：查看按当前主人实际权限生成的工具目录和服务身份。不会返回 MCP 环境变量或认证配置。
- `scripts/Stop-Local-YuE.ps1`：仅在队列为空且端口进程属于当前项目时停止服务与守护；检查实际进程身份后操作。启动脚本清除停止标记并恢复服务。
