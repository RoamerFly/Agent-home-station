## 环境与版本

- Windows amd64，Go 1.25.3，Intel Core i7-11800H；Linux amd64 程序以 `CGO_ENABLED=0` 交叉构建，在现有 Ubuntu-New 本机环境执行隔离模型测试。
- SQLite 驱动：`modernc.org/sqlite v1.38.2`，Go 模块校验和由 `go.sum` 固定；驱动许可证见 [BSD 声明](../licenses/modernc-sqlite.txt)。传递依赖及版本见 `go.mod`，不包含额外数据库服务、CGO、模型文件或第三方运行时。
- 旧实现基点：`08e3e87`；该版本的测试基线曾通过。上下文对照使用同一组历史、同一提示包装与同一估算器，分别配置旧字节上限及新 Token 选取预算，避免把计数方法变化算成节省。

## 上下文与存储性能

| 指标 | 合成测量结果 |
| --- | --- |
| `context-v2`，5 组长历史 | 同一估算器：基线 46,116，新选取 19,356，下降 **58.03%** |
| 10 个无关会话、400 条历史 | 固定会话写入 p50 4.4092 ms，p95 20.0549 ms |
| 100 个无关会话、4,000 条历史 | 固定会话写入 p50 4.9412 ms，p95 34.3678 ms |
| 无关会话增长 10 倍 | 写入 p95 比值 **1.714**，满足不超过 2 倍的验收线 |
| 独立 100 次写入分配基准 | 4,204,682 ns/op；157,729 B/op；949 allocs/op |
| `write-volume-v1` | 100 条合成消息共 33,223,712 WAL 字节，平均 332,237 字节/条；仅此写入量实验关闭自动 checkpoint 以计量 WAL 增量 |

首次扩容实验 p95 比值为 2.595，发现事件词项删除缺少按事件索引；补齐反向索引后才得到表中合格结果。没有降低质量或性能阈值。写入仍包含当前会话的兼容快照，存在进一步减少每会话快照写入量的空间；此次已移除无关会话导致的整库序列化放大。

Token 是明确标记的文本估算，未冒充模型 tokenizer 的精确结果或真实账单节省。提供商报告的输入、输出与缓存用量仍是费用依据。日预算在每次维护/嵌入调用前检查，最后一笔提供商事后报告可能超过当时余额；额度不足保留进度。显式重建不受自动额度静默截断。

构建体积：旧 Linux Web 基线为 20,728,709 字节；含 SQLite 的 Linux Web 为 26,740,774 字节，增加 6,012,065 字节（约 29%）；Windows Web 为 27,242,496 字节。本机可执行文件留在忽略的 `dist/`，不随源码提交；此处是默认本机构建，不是压缩发布包大小。

## 故障、迁移与浏览器

合成回归覆盖：相同正文不同事件、跨归档批次无原消息编号的身份保留与重试幂等、完整长原文、正文修订、批量 12 条阈值、无效来源不推进游标、预算延期与重启、遗忘后禁止重新提取、在线 SQLite 备份、迁移预演不启用、遗留中断 staging、不修改未知数据库、注入写失败后内存计数回滚。子进程直接退出并绕过 Close 后，已提交 WAL 仍可恢复；限制 SQLite 页数制造 SQLITE_FULL 后，来源事件与内存会话状态均保持事务前结果。

浏览器使用临时服务与不可发送的假原生后端：记忆来源、固定、遗忘后原文召回受阻、配置保存、375px 移动视口、无页面异常均通过。原控制台 19 个页面、2 个主题、5 个视口检查通过；会话页按需历史、对话框焦点恢复与并行压缩回归通过。真实微信测试发送为 0。

本机更新采用 [迁移与恢复流程](memory-engine.md)。源码检查、完整 Go 测试、vet、静态 JavaScript、仓库检查、Windows/Linux 构建及对应 CI 的最终状态以 PR #38 和交付记录为准，不以本文件代替远端检查结果。
