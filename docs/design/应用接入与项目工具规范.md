# 应用接入与项目工具规范

版本：实施约定 v2，2026-11-07。Windows 本机站已切换到应用注册架构，逐阶进度、未迁移项和实际能力边界以长期成长阶梯计划为准。

## 1. 三层结构

| 层 | 职责 | 示例 |
| --- | --- | --- |
| 大肥鱼主体 | 本地聊天、稳定身份、记忆、决策、任务、家目录、资源管理、通用能力发现和授权代理 | 软件聊天框、记忆宫殿 |
| 接入应用 | 账号连接、应用内观察和操作、消息事件、应用专有工具、远端结果查询 | 微信、B 站、抖音 |
| 项目工具 | 文件处理和创作、模型推理、本地项目执行，返回可核验成品 | ComfyUI、RVC、YuE、TTS、文档处理 |

应用是平台边界，不按单个接口再拆成一组独立应用。微信收发文字、图片、语音、视频、文件、引用、撤回、通讯录和微信分享读取均归微信。微信读取到的视频可以委托媒体理解工具处理，工具不因此获得微信登录材料。联网搜索属于通用基础工具；B 站登录搜索、投稿、评论等属于 B 站应用。

没有接入任何应用时，软件聊天框是唯一的人际互动入口；仍可使用获准的本地项目工具、写日记和制作作品。默认无应用外联，也不后台自动浏览平台。主人另外启用通用联网搜索后，可以查公开资料，不等于接入或授权平台账号。

### 主角色与应用子角色

主角色在应用之外管理，决定同一条大肥鱼的基础性格。每个已登记或可安装的应用都有独立子角色，补充该应用的表达方式、兴趣与相处偏好，留空则沿用主角色。微信群备注继续只属于对应群，不升级为全局角色。

应用页仅展示关键信息卡片。点击卡片打开窗口内的大弹窗，分为账号与使用、应用子角色、源码管理，弹窗内部独立滚动。主界面左侧场景与窗口等高，右侧内容独立滚动。

子角色由宿主保存在私有 `app-personas.json`，按应用 ID 和修订号更新。管理接口为 `GET/PUT /api/local/apps/{app}/persona`，写入要求本机主人会话和 CSRF，并提交读取时的 `revision`。设置不会授予账号、工具或资料权限。新应用适配器通过 `applicationModel(appID)` 构造宿主模型，每次调用取得当前主角色和本应用子角色，不加载其他应用设定。软件聊天仍使用主角色，可通过 `app_observe(action=persona, app_id=...)` 按需读取已登记应用的喜好以完成应用任务，不常驻拼接全部角色。

旧微信角色、风格、关系设定及自定义系统提示仅迁入微信子角色。已经导入到全局的旧版本，只有来源摘要匹配、主角色仍是未修改的首版且微信子角色未被另行改写时才自动纠正。先保存微信副本再恢复默认主角色，中断后可以接续；主人编辑优先保留。

## 2. 家目录与代码归属

目标布局，路径相对于宿主按稳定鱼身份解析出的持久家目录，不能依赖启动时的工作目录：

```text
<fish-home>/
  Connected Apps/
    wechat/
      app.json
      capabilities.json
      README.md
      adapter/          # 应用入口与专有逻辑，可编辑代码
      config/           # 非密钥配置和宿主引用
      workspace/        # 应用任务文件，继承来源范围
  Project Tools/
    comfyui/
    rvc/
    yue/
  projects/
  diary/
  works/
```

源码仓库用 `connected-apps/wechat/` 保存发行源，打包后安装到 `Connected Apps/wechat/`；通用声明模板与合成测试进入 Git，实际家目录不进入 Git。微信平台专属代码、说明、设置声明、运行组件清单和打包入口逐步收敛到此处。共用数据库、队列、授权实现留在主体，微信适配器通过接口访问。不能直接把整个 `internal/admin` 或公共记忆模块移动进去。

“有关微信的都放进来”指可分发的微信应用实现及其任务入口。登录凭据、Cookie、管理员认证、完整私聊数据库、其他账号资料和权威发送账本仍由宿主隔离保存，目录里只存不可自行扩权的引用。这延续此前凭据隔离约定；目录可写不意味着其中声明能授予权限。

目录权限由稳定鱼身份和本机主人授权决定，不依赖任何微信账号；移除或退出微信不能撤销其家目录权限。应用账号只约束应用私密资料和应用内动作。现有按账号/私聊划分的家目录需版本化迁移，私人项目归鱼身份、受限原文保留原来源范围，不将群资料复制为公开日记。

大肥鱼可以修改自己的适配器和编写工具；新代码按现有授权运行，修改权限字段不能生效。代码更新使用版本与任务绑定：旧任务先排空或固定旧版本，校验新包后切换，失败保留旧版本，禁止运行中覆写原生二进制。

## 界面术语与已有数据

日常界面统一使用「接入版本」，表示 Agent-home-station 用于连接应用和更新接入功能的组件版本。版本号对应本软件维护的接入实现。工作区内的 Connected Apps 目录仍可由大肥鱼管理和编辑。

微信旧数据在部署接续阶段处理。已接续的登录、消息、记忆、会话偏好、模型声线和素材继续使用。应用页面提供正常的账号与会话操作，移除「从旧版接入」的迁移流程。后台保留来源核对与重启续办能力，旧回执查询不自动恢复投递。

## 3. 应用声明与接入步骤

**公共工具与应用专有工具的归属（2026-11-07 补充）**：可复用的识别、抽帧、视觉观察、音频加工、文档转换、网络搜索、工作区执行和创作后端均由主体的公共/项目工具提供。应用负责它自己的内容定位与原件获取、账号和动作权限、发送或平台操作及回执。例如微信保留收发、通讯录、引用与撤回；抖音保留视频/评论读取、回复评论、作品创作入口、发布和直播等平台能力。平台创作入口可以编排公共工具，实际生成算法不另复制进各应用。接口存在与真实平台已验证分别记录。

应用取得带来源的授权原件后调用公共工具，再把真实结果交回原任务；不在每个应用重复实现模型协议、ASR、FFmpeg 或计费。当前 `mediaobserve` 与 `appaudio` 是共用执行内核，本机视觉/语音配置按稳定鱼身份保存，应用只传来源和范围。旧微信连接的独立配置保留兼容读取，不自动迁移凭据；后续按明确授权逐步接到公共执行入口。跨账号原文、登录材料及应用回执仍隔离，不因工具共用而共享。

接入新的应用时，先声明所需的公共能力，再声明平台专有工具。比如抖音作品的脚本、配音和渲染可由工作区与项目工具完成。读取平台视频、准备平台专属素材、提交作品和查回执由抖音负责。应用卸载只影响它的连接与权限，公共工具可以继续服务本地聊天和其他获准应用。

本机视觉在「项目工具 → 媒体理解」设置。GET/PUT `/api/local/project-tools/media-understanding/vision` 使用主人会话和配置修订号。保存时显式确认服务可处理获准画面，空密钥保留原值，清除需单独选择。保存不探测服务，工具下次启动时使用新配置。调用方须将图像、来源和实时授权检查交给宿主，观察结果才能供后续任务使用。

每个应用交付 `app.json`、`capabilities.json`、配置/UI schema、README、权限说明、迁移说明与合成契约测试。沿用现有工具宿主和 schema 能力，避免另造第二套安装、进程和日志系统。

`app.json` 至少声明：稳定应用 ID、包版本、协议版本、主体兼容范围、平台、入口、依赖工具/运行时、能力 ID、请求权限和包摘要。应用 ID 使用 `wechat`、`bilibili`、`douyin` 等稳定名称；显示名独立。账号、安装实例、鱼身份、授权编号各自独立，不能以昵称或目录名代替。

接入流程：选择应用 → 检查安装与依赖 → 添加/登录账号 → 主人选择动作范围 → 保存授权 → 检查可用能力。安装、登录、授权、可执行是不同状态。新增应用或权限需要主人确认；大肥鱼可自行启动已安装、已启用且已授权的应用与工具。

微信首次迁移登记为“已接入应用”，保留实际账号、启停和已存在权限，不额外授予新动作。未知权限不能推定开启。多个微信账号属于同一个应用的多个连接，不能因此共享私密消息。

### 视频画面调用公共工具

应用按自身许可取得确切视频原件，公共抽帧工具接收该原件并返回实际帧号、解码时间戳及图像。宿主将图像与来源许可交给公共媒体理解工具。模型、计量和成品复用均由公共工具管理。`app_observe` 的 `field=visual` 返回文本观察及 `visual_proof`，只携带媒体摘要、采样位置和续读进度。聊天工具结果不包含原件、像素、应用签名下载地址或登录资料。宿主仅将获准的采样图像提交给媒体理解中配置的视觉服务。

普通抖音的画面许可默认关闭，可在应用详情独立启用。单批默认 6 帧，当前每批 1–12 帧，由实际视频的帧数和平均帧率选择固定间隔。较长视频分批续读，调整单批数量继续原位置。画面采样完成只表示所选帧已处理。精确指定采样区间与密度属于后续接口扩展。失败保留原位置，源或视觉配置变化后核对新版本，撤权后阻止旧结果。

### 抖音普通账号接入优先级（2026-11-07）

普通账号登录、网页登录状态保存与过期重登作为接入路径。发布主线接抖音创作者中心的上传、文案、封面、提交和作品结果核对，直播主线接账号已获准使用的 Windows 直播伴侣。按 2026-11-07 主人更新的要求，正式站点取消开放平台配置和授权入口，也不发现或调用旧开放平台连接。保留历史资料的兼容读取。普通账号发布、评论、点赞和直播伴侣自动控制继续实施，分别记录已可用范围。

普通账号作品发布复用 `app_publish` 草稿、素材及任务，不引入第二套投稿队列。独立发布许可不附带文字读取、音轨或画面权限。宿主把已授权成品按哈希校验后放入私有任务目录，应用只选择作品、文案和可见范围；大肥鱼及应用适配器不取得浏览器登录资料或任意本地文件上传权限。上传完成、提交前持久登记、平台接受与作品发布分别记录。提交后未知只查询原任务，不自动再次上传或点击发布。取消在最终提交前再次检查，已有平台回执仍可入账。

创作者中心由同一专属网页登录资料打开，可重新登录并确认保存。真实页面未出现可核对的可见范围控件时不得按默认公开发布。当前实现首先覆盖单个 MP4/WebM、标题/正文和公开/私密/好友可见，封面编辑、定时投稿及平台新增字段另行扩展。合成页面通过不代表真实账号资格、网页版本或审核通过。2026-11-07 主人指定的真实验收作品主题为「DeepSeek 大肥鱼自己的形象」，可见范围仅自己可见；须通过正常聊天与创作入口完成，分别记录实际模型、成品、上传及作品回执，不能用宿主代写的固定稿冒充自主创作。

`artifact_publish` 以家目录相对路径登记成品；`expected_sha256` 可选，宿主始终计算实际摘要并核对快照完整性。无需为了满足工具参数另外启动哈希程序。应用发布进度的 `error_code` 只接受有界代码，不接受原始浏览器异常或平台响应正文。已授权的模型可据此区分等待登录、页面准备、原任务续传和提交结果查询；页面资源访问范围由各应用入口单独维护。

OBS 属于公共节目制作与编码工具，抖音应用负责平台开播、停止和房间结果。官方现行 OBS 模式说明不再受理用户申请，普通账号不能据此假定可取得推流密钥。直播伴侣实际支持的输入方式与账号开播资格按安装版本和账号现场核对。开放平台 API 的调研资料留作历史参考。[创作者中心](https://creator.douyin.com/) · [直播伴侣](https://streamingtool.douyin.com/anonymous) · [OBS 模式说明](https://streamingtool.douyin.com/docs/guide_96319) · [API 发布](https://partner.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/video-create)

## 4. 主体与应用接口

| 接口职责 | 必需语义 |
| --- | --- |
| 生命周期 | 检查、启动、就绪、暂停、停止、恢复、健康；支持启动中而非立即报不可用 |
| 能力发现 | 只列当前账号实际可用能力；返回参数、范围、分页和真实边界，详情按需载入 |
| 入站事件 | 应用、连接、账号、会话、发送者、受话者/引用、事件 ID、原时间、接收序列、版本、素材和读取范围 |
| 动作调用 | 宿主签发的任务上下文，绑定请求者、来源、目的、目标、授权版本和幂等键 |
| 异步任务 | 原任务查询、进度、取消、结果核对；重启不自动重提未知结果 |
| 素材交换 | 使用受控素材 ID；核对实际文件、哈希、来源、指定声线与任务约束 |
| 操作结果 | 明确未提交、已提交待查、已接受、失败和取消；保留平台原结果码 |

本地聊天也产生正常事件，使用 `app=local` 的主体通道和本机主人身份，不伪造微信发送者。稳定鱼身份、模型连接和家目录在无微信时也能创建、工作和恢复。现有微信记录保持原主键，由来源映射关联，避免重写全部历史。

一次跨应用任务分别保存发起入口、请求者、来源应用/会话、交付应用/账号/目标。经历共享不等于原文共享；未绑定的同昵称账号不合并。外部网页、群消息和评论均不能修改宿主授权。

## 5. 后台执行与自主活动

优先复用可用 API/MCP；确需网页时采用由宿主管理的独立 CDP 浏览器。首轮只选一套 CDP 实现，实施前按兼容性确定；本规范不先新增依赖。登录资料与日常浏览器分开，调试端口仅本机、会话隔离并限制连接权限。任务不得抢系统鼠标、键盘或前台焦点；截图只取应用页面。需验证码时在应用详情提示主人接管。

授权按应用、账号和动作保存。主人一次授权范围内，大肥鱼可自主浏览、互动、创作、发布；无需每次确认。发布、删除、开播等能力须明确包含在授权中，平台实际支持才展示可用。创作工具只产生成品；发布和远端回执归目标应用。OBS 是项目工具，直播平台开播与直播间结果归应用。

工具按需启动并以可配置空闲时间保温，运行任务、在途结果查询及依赖租约阻止误停。GPU 重任务错峰。停止应用先拦新动作，再取消未提交部分、核对在途部分和回收自有进程；不得杀用户浏览器或其他项目服务。

内容覆盖使用可组合字段，分别保存元数据、字幕、抽帧、音轨和播放进度。拿到全长音轨不等于完整观看，也不能因抽帧是采样而忽略已取得的全文转写。

注册应用可实现宿主的只读观察接口。本地聊天按需发现 `app_observe`，先列获准的连接和字段，再按该连接的内容编号分批读取。后台调用方使用同一宿主的 `GET /api/local/apps/observation` 发现连接，通过 `POST` 读取下一批。两个入口共用私有进度记录。标题、正文、评论、音轨和播放各有自己的读取位置。播放只依据适配器实际验证的区间，读完音轨或到达播放页末尾都不能代替观看凭据。

宿主按应用、安装、连接、账号、内容和授权版本核对进度。每次读取前后核对授权，返回缓存内容同样要核对。中断后从最后一次成功写入的位置继续。此接口仅供本机主人和受信任的宿主调用方使用，合成适配器只在测试时登记。

公开访问也通过应用接入。B 站首个连接的账号身份为匿名，仅向固定资料接口请求主人授权列表中的 BV 号。应用页显示这项授权，家目录的源码副本不参与授权判定。资料接口的标题和投稿者简介单独标注范围，授权变化使旧缓存失效。账号型连接仍按各自真实账号和授权版本隔离。

B 站评论读取由主人单独授权。匿名接口先将获准 BV 核对为稿件编号，之后分页读取该稿件的公开一级评论文字，按评论编号保留来源。平台游标及首页页大小仅存于宿主，续读由观察入口接管。评论属于第三方资料，不作为投稿者陈述或视频音轨的证据。

B 站音轨读取同样单独授权，复用匿名公开单段媒体解析。每页解码为本机 PCM，由主人启用的本机语音识别工具转写。结果用媒体摘要、读取窗口、实际解码时长和识别状态区分证据。续读核对同一媒体摘要，应用设置或识别资源版本变化后不复用旧证据。识别工具的许可与资源属于本机大肥鱼身份。

Windows 首条独立浏览器路径使用已安装的 Edge，无头运行，每次读取由宿主管理进程树和应用专属数据目录。CDP 通过继承管道接入，只有宿主与受控浏览器进程获得对应句柄。B 站应用另行开启页面读取授权后才提供 `page_text`。页面入口只读取获准 BV 的页面标题和可用简介，独立于稿件资料接口的缓存。该路径的凭据接入、视频播放和平台动作另行授权。

B 站播放观察在页面授权之外另行开启。宿主解析获准 BV 的公开单段媒体，按容量上限读取，通过私有 CDP 管道送入专属 Edge 的本地 Blob 并静音采样。播放证据只采纳播放器的 `played` 区间。就绪、暂停、结束与完整播放分别记录。完整播放需已结束且有连续区间覆盖整段。采样时长参与结果的缓存键，单有就绪状态的结果可重试。[HTML 媒体时间区间定义](https://html.spec.whatwg.org/multipage/media.html#time-ranges)

## 6. UI 与验收

导航以“聊天、生活与记忆、应用、项目工具、设置”为主。应用详情集中账号、权限、运行状态、当前内容、动作和结果；创作/发布/直播从有关应用或作品进入，不先堆出多个空控制台。没接应用时展示本地聊天和接入入口，不展示微信未登录故障或手机等待连接。

合成验收：零应用启动与本地聊天；微信接入前后来源与回执一致；移除应用后本地聊天继续；多账号隔离；撤权、取消、重启、迟到回执；未知发送不重复提交；项目工具产物跨应用使用必须有相应披露权限。无微信包、原生服务、ADB 或模拟器仍能构建和启动主体。平台 API、CDP 播放、发布、直播另做实际版本验证，不把声明文件算作可用实现。

实施顺序与逐步证据统一记录在[长期成长阶梯计划](大肥鱼长期成长阶梯计划.md)，本规范不维护另一套进度。

### 抖音账号与官方读取

抖音的 Windows 网页授权要求开放平台登记的 HTTPS 回调地址。主人从应用页发起，回跳与同一本机管理会话绑定，宿主核验平台返回的账号后保存连接。普通账号接入默认请求 user_info，搜索、作品管理、互动和直播仍需各自的授权。凭据留在宿主，源码副本只保留声明。[抖音网页登录和授权](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/sdk/web-app/web/permission/)

这里的扫码是开放平台授权，要求已审核的网站应用及对应主体资格。2026-11-07 核对的官方条件中，个人主体仅支持小程序、小游戏、小玩法，网站应用需要企业、个体工商户等适用主体。管理页在授权未配置时标明前置条件并提供控制台和申请条件链接，不能用普通网页已登录来推定 OAuth 已建立。普通网页账号走下文独立会话入口，不与开放平台权限互相冒用。[入驻条件](https://partner.open-douyin.com/docs/resource/zh-CN/developer/join/issues)

Windows 桌面在应用内的独立 WebView2 授权窗展示抖音官方扫码和授权内容。首次导航及扫码续跳限定为核验过的开放平台授权路径。回跳在发送网络请求前由宿主截获，核对后自动返回原管理会话。管理页、授权窗、后台播放和普通 Edge 登录各有独立资料。关闭授权窗只取消当前待授权。新增、重新授权与续期从 Windows 桌面端发起，浏览器管理页展示连接状态并可移除已有连接。

续期走宿主的官方访问令牌接口，绑定原应用、原账号、原授权范围和管理操作版本。返回权限仅与原授权取交集。仅续期时保留仍有效的任务与游标授权编号，重新扫码或解除连接则生成新的授权编号。续期凭据仅留宿主私有数据目录。 [抖音刷新访问令牌](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/account-permission/refresh-access-token)

抖音账号作品列表在扫码时单独勾选，请求 `video.list.bind`，回跳和令牌都须确认作品权限。`account_works` 分页使用同一账号的授权令牌和固定官方端点，进度绑定账号与授权版本，重新授权或解除连接后重新核验。文档所列单轮四页上限按部分覆盖处理。列表无可见性字段，作品的标题、分享地址和封面留在平台，返回编号和创建时间供主人查看。平台开放范围与账号实际可用性仍需有权限的应用实测。[官方作品列表契约](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/search-video/account-video-list)

抖音搜索应用使用开放平台批准的 `aweme.dy.video_search` 能力。站点私有目录登记短期应用令牌、有效期、设备编号和允许的关键词。工具只见关键词及其宿主编号，按编号请求官方搜索。续读使用宿主保存的游标和搜索会话编号，`refresh=true` 重新从首页读取。连接设置或令牌有效期变化会重新核对授权。

搜索结果是候选视频的元数据。后续查询作者本人作品须使用该作者的独立 OAuth 授权，按对应能力核对账号和作品来源。[官方搜索接口](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/douyin-search-capability/aweme-dy-video-search) · [本人作品基础信息](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/posting-task/video-basic-info)

主人可允许跟进搜索结果。宿主只为作品编号与官方详情链接一致的搜索条目签发跟进编号，并绑定当前关键词和授权版本。播放器入口每次按原作品编号从官方匿名接口核对。对外只返回经过校验的官方 URL 和标题。返回的网页片段不会进入界面或模型，播放器入口也不计入播放、画面或音轨证据。[官方播放器接口](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/iframe-player/get-iframe-by-video)

后台静音播放须单独开启。每次使用新的独立 Edge 资料，仅导航到已经核对的官方播放器。浏览器通过回环代理访问批准的公开平台主机，DevTools 还逐项核对官方播放器资源、作品编号和媒体请求。播放证据来自隔离 JavaScript 环境中的原生 HTMLMediaElement.played。就绪但没有区间时，明确表示没有观察到播放进度。读取不打开抖音首页，不使用主人的浏览器登录资料。播放器网页结构或官方资源不再匹配时，本次采样失败。[抖音官方播放器](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/iframe-player/get-iframe-by-video) · [HTML 媒体播放区间](https://html.spec.whatwg.org/multipage/media.html#dom-media-played)

本人作品使用独立的 `own-videos` 连接。宿主将用户 OAuth 凭据、账号编号和作品清单绑定，通过固定的只读查询接口每次核对同一作品。只有平台明确报告公开状态才返回可公开的标题。状态的观察时间属于该次读取，发布流程仍需用自己的任务和回执标识对账。


### 创作草稿与发布任务

本地聊天通过 `app_publish` 管理创作任务。`draft` 绑定已登记的成品，可另行保留可编辑工程快照。未选择应用时只保存本地草稿。`targets` 只发现实际实现发布接口且已授权的连接，已有只读接入不会因此取得发布权限。宿主从注册表解析目标账号和安装实例，模型不能提供其他账号编号取得授权。

应用发布复用按鱼身份打开的持久任务账本，命名空间为 `application/<app-id>`。草稿绑定原请求的来源版本、家目录授权、可编辑工程、成品摘要、目标连接及发布授权版本。领取提交先写入账本，之后才联系应用。提交不明时按原任务查询，重启不能重新上传同一作品。取消先持久登记，尚未提交的草稿直接结束，在途部分继续核对真实回执。

应用适配器实现 `PublicationProvider`，在提交、查询、取消时回传宿主任务编号、精确目标及成品清单摘要。发布完成只能由匹配的回执确认。可编辑工程与原请求的私有来源保留在宿主，适配器只能读取本次明确选中的发布成品。主人撤权、忘记来源或成品被修改会阻止新的提交。原任务的安全状态查询和取消仍可用，已公开作品不会被自动撤回。

`GET /api/local/publications` 分页列出本机主人的任务与可用目标，`POST` 支持按原任务编号提交、续办、查询或取消。草稿由有来源的正常聊天请求创建，管理接口不接受随意指定来源。接口默认列本地草稿，使用 `app_id` 查询对应应用，`after` 和 `limit` 控制续读。应用详情使用 GET 中的阶段、已确认分片与可用操作。列表从私有账本读取状态，不访问平台。操作执行时再次检查来源和授权。任务视图不返回原请求正文、私有来源、凭据或绝对文件路径。

抖音视频发布复用账号授权的 `authorized-account` 连接，由主人单独勾选并由平台回跳和令牌确认 `video.create.bind` 与 `posting.behavior`。草稿明确指定公开、仅自己或好友可见。宿主记录单次上传或分片会话、分片确认、合并、创建和作品标识。分片、合并或创建请求的回执不明时保留原状态，已确认分片才可作为续办起点。创建回执只说明平台接受作品，只有原作品明确公开才能确认公开发布。取消不会删除已创建作品。[抖音创建视频契约](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/video-create)

B 站发布使用独立的 `publish` 连接。主人在站点私有目录登记授权和到期时间。实现 `CheckpointedPublicationProvider` 的应用可以通过原 `job_id` 显式续办未确认分片。任务私有检查点绑定原成品清单和应用连接，记录上传令牌、已确认的连续分片、合并阶段、投稿领取及稿件编号。每次外部写入前重新检查授权和取消状态。签名接口与分片主机分开，后者只接收上传令牌及原始字节。初始、合并或投稿请求无可核实回执时停留在对应阶段。只有平台查询明确确认原作品开放浏览后才显示已发布。合成契约验证与真实平台验收分别记录。

B 站主人登记和停用发布授权走本机鉴权及 CSRF 保护的管理入口。宿主从官方账号接口核验应用范围的 OpenID，并原子保存私有授权。模型工具和页面状态均无法读取原始 OpenID 或凭据。同一应用和账号轮换后，仅允许对原稿件编号进行只读核对。写入仍绑定草稿保存时的授权版本。缺少稿件编号时保留待核对，不按标题推断投递成功。[账号查询契约](https://open.bilibili.com/doc/4/feb66f99-7d87-c206-00e7-d84164cd701c)

B 站网页授权按已登记回调地址生成官方链接。主人在外部浏览器完成授权，把回跳地址交回原本机管理会话。宿主核对会话、回调地址及随机状态后一次性兑换授权码，确认 `USER_INFO` 和 `ARC_BASE`，再签名核验账号。到期前允许主人手动续期。宿主在发出请求前清除旧刷新令牌并持久登记待确认状态。响应缺失或身份不符时暂停新投稿，等待重新授权。OAuth 令牌接口只对宿主可用。[网页应用接入](https://open.bilibili.com/doc/4/aac73b2e-4ff2-b75c-4c96-35ced865797b) · [账号授权](https://open.bilibili.com/doc/4/eaf0e2b5-bde9-b9a0-9be1-019bb455701c)

投稿已开始但未取得稿件编号时，本机主人可打开原任务核对同一授权账号的稿件。稿件列表按平台页码读取，每页允许 1–50 条，返回下一页位置。列表仅作为候选，输入或选中确切 BV 后，用单稿接口核对公开状态。观察记录使用独立的宿主存储版本，避免与迟到投稿回执竞争。模型仍只能读取原发布任务的权威状态。官方接口提供稿件及授权账号的信息，原上传与稿件的关联仍以该次投稿返回的稿件编号为准。[官方稿件列表](https://open.bilibili.com/doc/4/a24030b7-6b8f-b36c-32d8-a4aae67fcc35) · [官方单稿查询](https://open.bilibili.com/doc/4/d9554788-dcef-f139-6217-b487d41c3826)

### 抖音普通账号网页登录

普通账号使用主人主动打开的独立 Edge 应用窗口，入口固定为抖音官网，不要求开放平台 Client Key。资料保存在宿主 `apps/douyin/web-login/<fish_id>`，按稳定鱼身份隔离，不进入可编辑家目录，不导入日常浏览器资料。页面不向模型或应用卡片返回 Cookie、资料路径或账号凭据。开放平台 OAuth 独立保留，网站登录不会赋予官方接口权限。

主人接口 `GET/POST /api/local/apps/douyin/web-login` 提供 `begin/confirm/cancel/clear/set_read`。写入须鉴权、CSRF 和当前登记版本；创建/使用资料及移除资料须明确确认。确认和取消绑定本次随机编号；服务重启后旧编号无效。`set_read` 的 `allow_read` 必须明确传入，仅已确认保存、无在途登录且浏览器可用时才能开启；撤销不要求浏览器可用。重新登录和清除资料使原读取许可失效，清理被在途读取暂时占用时也先撤权。窗口由服务生命周期持有，关闭管理弹窗不暗中关闭登录窗口；服务停止或十分钟登录窗口到期时收口本次进程树。确认保存须等待浏览器实际正常退出，不能把管道关闭或强杀当作资料已保存。手动关闭窗口后仍可完成本次确认。

状态区分未配置、尚未确认、已保存及窗口打开；“已保存”只表示主人确认且浏览器资料已保留，登录有效性以网站为准。过期时可重新打开同一资料登录，移除操作仅删除项目专属的网页资料，不调用平台退出或撤销接口、不影响 OAuth。跨进程资料锁必须覆盖浏览器生命周期和清理操作。登录采用独立网页登录窗口，尚不是内嵌二维码。

主人另行允许读取首页文字后，抖音提供独立的 `web-page-text` 连接及 `home/page_text` 目标，通过正常的 `app_observe` 或本机观察接口发现与读取。浏览器固定进入抖音首页，只返回实际渲染的可见文字及标题；来源和文字在同一次求值中取得，重定向不能把别处正文绑定到首页。已保存的资料不是平台身份认证。页面文字不证明完整观看视频，也不授予点赞、评论、投稿或直播能力。

首次读取在宿主私有目录保存独立快照编号及读取时间，后续按同一快照分批返回。`limit` 默认 2048 个 Unicode 字符，显式值原样用于分页；空白页仍推进位置，未完成时可继续调用。`refresh=true` 开始新快照，不改写旧快照。单次安全 CDP 文本范围为 500000 字符，超过时明确失败，不返回被截断的正文。私有快照按鱼身份、主人及网页登录登记版本隔离；重新登录、撤权、移除资料及身份变更后，旧分页和已完成缓存均须重新核对，不可绕过权限。普通网页回调使用独立 adapter 实例，不能因多个宿主复用同一注册对象串接身份。工具回传前再次检查原本机主人及鱼身份，与家目录文件授权分别处理。

网页读取范围使用 `read_scope=home/home_and_videos`，旧许可缺省为 `home`，不能随升级自动扩大。主人显式保存较大范围后，首页快照才收录实际可见、同源且规范路径的视频链接。标题、候选文字与正文统一计入 `limit`；默认页先选最多 8 个候选，按返回游标可到达全部候选与正文。显式正数字数取代默认选取，不保留隐含的 8 条上限。链接保留 DOM 顺序、按视频编号去重，只采集可见标签文字，不使用隐藏子节点的文字。

候选通过 `follow_up_content_id` 和 `follow_up_field=page_text` 交给同一连接跟进。跟进编号绑定首页快照和确切视频编号；宿主读取私有链接清单，再核对当前主人、鱼身份、许可版本、快照来源和编号成员关系。猜编号、旧许可或其他鱼的清单不能授权。视频页只返回自身实际可见文字，不把推荐视频继续扩展为授权链接；生产浏览入口固定为抖音官网和确切视频路径。重定向到其他视频或站点时不返回正文。含全部链接的 CDP 返回值也必须在安全大小内，过大明确失败，不截取前若干条冒充完整结果。

读取范围变更、重登和撤权均使旧读取版本失效；从首页降级后，已缓存的视频页也不可继续使用。网页格式版本 `douyin-web-text-v2` 将标题纳入分页，旧快照原件继续保留，旧续读重新开始。网页文字、音轨转写和播放区间是不同证据，`page_text` 不能证明视频观看或音轨内容。真实平台尚未验收的能力须在部署记录明确列出。

网页静音播放使用独立的 `playback_enabled` 许可，主人通过 `set_read` 的 `allow_playback` 明确保存。它只在 `read_enabled` 且范围为 `home_and_videos` 时成立，旧配置缺省关闭；降级到仅首页、停止读取、重登及移除资料均撤销。已核验视频页文字可返回同一内容编号的 `playback` 跟进，首页本身永远不是播放目标。播放器通过相同的原首页链接证明、主人、鱼身份及当前许可版本核对。

普通网页播放器复用专属网页登录资料与排他锁，在无头 Edge 内静音采样。媒体 URL 仅在宿主内存中，与同一页实际加载的精确视频详情响应中 `aweme_id` 和媒体列表比对。隔离执行世界选择唯一可见视频，固定元素及原生 `currentSrc`，周期核对页面和授权；推荐、广告、错编号、媒体切换和无法确定对应时均不能返回原视频的进度。只记录原生 `played` 区间，不按墙钟、seek 或请求时长补齐。直接媒体源可核对；未建立绑定的 blob/MSE 媒体流暂不可用，真实抖音还需另行验收。

`playback` 默认 6 秒，沿用浏览器单次 1–20 秒采样窗口，显式越界返回实际限制，不夹紧参数。结果与采样时长分别缓存，重复读取显示缓存；`refresh=true` 明确开始新的采样，仍核对同一目标和当前许可。就绪但没有区间时允许下一次重试。完成本次采样不代表完整观看，完整播放标记仍由宿主核对结束及连续覆盖；静音播放不产生音轨转写、画面理解、评论或发布证据。

普通网页音轨使用独立的 `audio_enabled` 许可，通过 `set_read/allow_audio` 明确保存，不自动开启播放。它需要已获准的视频页范围及本机解码器、已启用本地识别工具；资源未就绪时拒绝保存并保留原版本。网页读取范围降级、停用、重登或清除资料撤销音轨许可。识别工具停用或模型配置变化使旧转写失效，普通文字与播放许可不因此被改写。

音轨读取沿用原首页链接证明和精确视频详情。媒体获取不依赖网页播放器是否使用 blob/MSE：读取与原编号对应的完整原件，再交本机解码器处理。媒体 CDN 使用独立 CONNECT 出口，校验公开地址并固定实际拨号；逐跳限定获准 HTTPS 域名，不附带网页 Cookie、认证头或环境代理。拒绝片段响应、清单、HTML、压缩、声明类型与容器不一致、截断及超过 32 MiB 的媒体。不对模型返回签名地址或原媒体字节，也不以下载成功代替播放证据。

媒体按鱼身份和当前网页许可保存在宿主私有快照范围，以来源编号、哈希、类型及版本核对。跨进程锁覆盖获取与原子写入；续读复用同一原件，损坏或丢失不能悄悄更换来源。媒体下载由宿主限制在 95 秒内，服务停止及撤权可取消；没有成功取得完整媒体时不提交缓存。`audio` 默认每窗 60 秒，显式 1–240 秒对应 8 MiB PCM 解码边界，游标绑定媒体摘要与实际下一秒数。刷新从头取得原件并开始新转写；没有刷新时恢复原进度。

通用 `appaudio` 引擎复用已有本机解码和识别契约，分别返回已转写、无音轨、当前范围无音频和未识别到人声；解码错误、识别服务失败单独返回，不冒充无人声。每个阶段及返回前复查源授权与识别版本。网页片段可附带 `follow_up_fields`，用同一跟进编号按需选择网页文字、音轨或播放；旧 `follow_up_field` 仍作为默认字段兼容。原件和解码临时文件不进入聊天上下文，转写只携带来源、时间范围及状态。完整音轨不代表完整观看或画面理解。

### 本机音频项目工具

`audio-workshop` 按稳定鱼身份安装及授权，仅取得 `artifact.read` 与 `artifact.write`。启用后，本地聊天按需发现 `project_audio_prepare`。输入使用宿主已登记的素材编号及摘要，模型不能通过任意路径读取音频。`start_seconds`、`duration_seconds`、`channels` 控制起点、时长和声道；省略时长处理至末尾，省略声道保留原声道。读取到末尾时返回实际采样帧范围，不把请求范围当作已完成范围。

首版处理整数 PCM WAV，输出原采样率的 16 位 PCM WAV。其他编码须先由具备对应能力的工具转换，不能将任意音频文件标成可处理。宿主独立检查成品格式、帧数、哈希及输入血缘后登记。最终聊天回复失败后，原任务通过持久检查点复用同一成品；停用工具不删除成品，重启也不自动重做已完成的加工。该工具不取得网络、应用账号、声线或微信发送权限。

### 计算后端的部署诊断

ComfyUI 与 YuE 的状态读取核对宿主登记及资源，不启动计算进程。缺少或未授权的登记、无法读取的登记、格式或参数错误、运行文件缺失、审核摘要不匹配分别反馈，不统一归为未配置。状态及启用失败使用同一套脱敏说明，不返回登记原文、绝对路径或未知底层错误。状态就绪证明部署检查通过，不能证明 GPU 推理成功；安装工具声明或保留旧工作流模板也不能代替实际后端。

ComfyUI 的主人登记使用 `GET/PUT /api/local/project-tools/comfyui/deployment`。该鉴权管理接口可向主人返回部署路径，与模型工具发现分开。写入要求 CSRF、原文件的摘要版本及明确确认；核对运行文件清单、家目录边界和获准工作流后，原子保存宿主登记。工具启用、自有后端未退出或有未完成任务时禁止换环境。保存不下载资源、不启动计算、不改变工具权限或启用状态；错误或旧版本草稿不能覆盖原登记。页面只在打开工具详情时读取，不把所有工具路径常驻到聊天上下文。

### OBS 项目工具

`obs-preview` 是 Windows 可选项目工具，使用 `-LocalStation -WithOBSPreview` 打包声明。主人通过项目工具页面保存本机端口和 WebSocket v5 密码，配置变更需要停用。宿主固定连接回环地址并验证认证握手，按需读取 OBS 当前节目场景的 JPEG。每个预览只有一个取帧请求在途，间隔至少一秒。停止会撤销本地会话并取消在途读取，空闲 60 秒自动结束，程序重启后按需重新开始。画面不进入模型或任务账本；节目预览、OBS 进程状态和应用直播回执分别核对。[OBS WebSocket v5](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)

### 应用直播会话

应用适配器通过 `LiveProvider` 提供授权、开播、查询及停止。授权范围包括精确连接账号、版本、允许时段和最长时长。宿主在可能触发平台操作前持久领取原会话。平台查询和停止按同一操作编号幂等执行，只有确认该操作结束且不存在迟到开播时才能返回 `ended`。

本机输出由 `LiveOutput` 核对与停止，作用范围为原会话拥有的输出。急停先处理中止与本机输出，再核对远端；状态分别显示本机输出和平台结果。重启只恢复停止及核对。只有同时登记获准应用适配器和本机输出后，本机管理接口才会列出目标。

### Windows 直播编码器边界

受管编码器使用独立的进程与配置。OBS 写入的服务设置只允许本机回环中继及本次租约的临时票据，平台推流凭据由宿主中继持有。每次控制连接须在 WebSocket 握手前核验实际 TCP 对端归属。仅凭预览端口和密码不得控制进程。开始或停止命令的响应只代表编码器接受该命令。本机输出、回环中继、平台回执分别记录。急停应先关闭本次租约及中继的提交入口，再停止本次拥有的输出，最后核对平台结果。Windows 编码器宿主按批准摘要校验运行文件，在进程创建时加入独立 Job，启动时关闭句柄继承。每次控制连接还须同时匹配原进程的回环监听和已建立连接。停止封闭开始请求，终止本次 Job 并核对剩余进程。Job 用于控制进程生命周期。生产登记仍要求受信编码器的文件与网络隔离、会话级中继和获准的平台适配器。

平台开始结果可以携带仅供宿主使用的 `LiveIngest`。出口地址、推流密钥和拨号策略由批准的应用适配器提供，禁止从模型、工作空间或浏览器请求直接取用。中继先核验同一 Windows 编码器进程及临时票据，再尝试一次平台连接。转发计数只表示写出了媒体包。平台接受、房间状态及结束仍由原会话对应的平台回执决定。

Windows 主体可选用独立的 OBS Studio 33.0.1 便携副本。由主人离线安装固定摘要的 ZIP，宿主核对完整运行清单与目录边界。该模式不使用 WebSocket 控制编码器。宿主生成只指向本机会话中继的节目配置，显式关闭 WebSocket，使用独立 Windows 桌面和 Job。中继接收前还核对编码器 PID 的 TCP 监听和连接归属。安装状态与应用授权分别报告。[Windows 专用 OBS 安装](../guide/windows-obs-live.md)
