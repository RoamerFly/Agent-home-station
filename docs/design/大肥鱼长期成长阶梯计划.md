# 大肥鱼长期成长阶梯计划

项目名称：**Agent-home-station**。大肥鱼是其中持续成长的 Agent，微信只是她可接入的一个应用。主人在软件聊天框与她相处；接入微信、B 站、抖音后，她才拥有这些应用中获准的能力。她的身份、家目录、记忆和项目工具独立于任何应用账号。

她可以记住与不同人的共同经历，逐渐形成自己的兴趣、心情和相处习惯，自己决定探索、创作、互动或休息。主人可以看见变化的依据，纠正误解，暂停应用或接管其专用浏览器。**取消手机模拟器及专属手机作为实施路线**，后续使用应用 API/MCP 和独立 CDP 浏览器。

本页是长期实施记录。每阶独立交付，在文末更新已完成、验收证据、尚未验证和下一步。仅将有证据的功能标为完成。

执行约定：每次只领一个能单独使用或验证的小步；恢复工作时先读实施记录和最新提交，再决定下一项。可并行分工检查不同模块或编写互不重叠的实现与回放，由同一负责人集成。正在验收的步骤没有结论前，不把后续阶段标作已交付。

## 当前生效的架构决策 · 2026-11-05

本次需求覆盖下文旧阶段的后续安排；历史实施记录保留作证据，不表示手机路线继续执行。

- **主体＋接入应用＋项目工具**。主体提供本地聊天、身份、记忆、家目录、任务与授权；应用包含该平台全部专有工具；ComfyUI、RVC、YuE 等属于项目工具。联网搜索属于通用基础工具，不混入微信。
- **目录权限完全脱离微信账号**。鱼身份与本机主人授权决定家目录的读写执行；微信登录、退出、解绑、移除均不能收回她自己的项目和工具权限。平台账号只决定该应用中的数据与动作范围。现有 `boundFishHome` 仍依赖微信身份，属于待迁移实现，不能描述为已经解耦。
- **零应用可独立相处**。未安装微信包、原生端或手机组件时，仍能启动主体、创建同一条鱼、在软件聊天框对话、管理记忆及使用获准的本地项目工具。默认不主动对外联网；通用搜索需另启用。不能用假微信账号承载本地聊天。
- **微信成为已接入应用**。发行源逐步迁至 `connected-apps/wechat/`，安装到她家目录的 `Connected Apps/wechat/`，收拢微信专有实现、声明、说明与任务入口。登录材料、私密数据和权威回执继续由宿主隔离管理，应用目录只持有引用。
- 已推送的手机 5.1、5.2、5.3a 标为旧路线；5.3b 本地未提交实现暂停，不作为新计划的完成成果，也不随本次文档与更名提交。移除运行依赖及 UI 入口在替代链路可用后分步执行，不清空历史资料。
- 采用用户提供的《大肥鱼 Go 桌面端：后台探索、自主创作、发布与直播总体方案》中的 Go 主控、后台 API/MCP/CDP、ComfyUI/FFmpeg 创作、平台回执与 OBS 管理思路。该文末尾的“手机模拟器备选”不采用；文中的默认联网和逐次审批建议由本次明确应用授权取代。一个应用授权范围内可自主操作，新增应用与扩大权限仍由主人决定。

详细边界见[应用接入与项目工具规范](应用接入与项目工具规范.md)。这轮先落盘新架构与项目更名，运行代码按下列小步逐次迁移，不直接搬动真实登录目录或运行中的程序。

## 阶梯与放行条件

### 0 · 精简现有项目

按运行代码、兼容读取、测试夹具、开发工具、用户文档、部署产物列出归属。检查调用、静态资源路由、动态发现、打包和文档后再删除。第一批合并会话、主动行为和记忆等页面重复的控件，将旧回复诊断的展示放回执行记录。手机旧 SDK 仍被兼容测试使用。分别记录 Git 跟踪文件、桌面包、本地数据和运行时占用，不把模型大小当作代码冗余。

验收：同一机器、工具链、参数下比较生产依赖、程序体积和普通群聊输入；离线回放会话、工具与手机任务。当前聊天流程、表单默认行为与历史记录均应可用。

### 1 · 稳定身份与家目录

由本机主人建立稳定的鱼身份和独立家目录，再将应用账号显式绑定给她使用。家目录可完整读写执行，保存日记、草稿、作品、项目及自编工具；目录权限不依赖微信账号。账号私有来源继续按原范围检查，仅授权共享的成长资料跨应用使用。凭据、其他账号数据和发送账本由宿主管理。现有 1.1–1.3 是微信账号绑定实现，独立本地主人入口仍需按第 5 阶补齐。

验收：在隔离副本迁移，核对消息数量、来源和记忆；重启后能按名重新找到并运行自编工具。群成员请求不能读取私人日记；跨平台同昵称不会合并。

### 2 · 从经历到下一次相处

从现有事实、偏好、事件、经验和来源生成共同经历、人物关系、兴趣、近期心情和未完心愿。让她主动记下、关联、更正或淡化记忆，有值得整理的新经历时异步反思。日记可以描述自己的感受；关于他人的事实须有原始依据。反思继承来源的可见范围。聊天沿用正常模型决策，不增加逐句心情打分。

日常管理保留搜索、看来源、更正、忘记。工程参数移出日常操作。验收采用一个跨天故事：两人约好做一件事，隔天续办，随后一方更正细节。再置换人物、图片上传者和晚安发言者，检查亲属归属。聊天、图谱和反思必须反映更正；取消、遗忘、重启或后台迟到均不能复活失效事实。

### 3 · 生活首页与记忆宫殿

用 GPT Image 生成两套蓝紫色视觉方向与可复用场景资产，以“夜海中的生活手记”为主方向。首页展示她最近做过什么、对什么感兴趣、当下正在做什么。二维记忆宫殿支持按人物、经历、兴趣切换；点开关系能看原话、时间及更正记录。文字与关系由真实数据渲染，同时提供功能等价的列表。随后把会话、活动、工具与设置迁入统一布局。

验收：合成数据逐页检查浅深色、桌面与窄窗、空状态与大量节点；同一跨天故事在图谱与聊天中的解释相符。

### 4 · 通用自主探索

复用冲浪与主动唤醒，分离“产生兴趣、选择来源、观察、深入或创作、核实结果、写入经历”。平台适配器负责发现、读取、执行、查询结果。先用已有网页和分享读取，再接离线模拟平台。同一条鱼可以休息或结束，不要求产生动态。

验收：同一流程能换平台；标题、字幕、画面、音轨分别记录覆盖范围。看到标题不能记为看完视频；仅在有可核对结果时记录评论或发布成功。

### 5 · 应用化重构与后台探索（替代原手机阶段）

按以下顺序执行；每次只完成一个可独立核对的小步。前两步是其余应用接入的前置，不先做真实平台发布或直播。

| 小步 | 交付与边界 | 验收条件 |
| --- | --- | --- |

| 5.H OBS 与应用直播 | OBS 作为项目工具，平台应用负责开播资格与实际直播间状态 | 先本地预览；授权账号/时段/时长内才开播；本机急停不依赖模型；GPU 繁忙和断网可停止；平台未验证不标可用 |
| 5.I 移除手机与旧耦合 | 下线设备观察导航、ADB/模拟器默认依赖和微信专用主体入口；保留必要历史读取 | 无手机环境安装运行；停用旧队列不因重启复活；真实模型/素材/记忆不删除；检查动态发现、打包、文档和旧任务引用后再删代码 |

界面采用“聊天、生活与记忆、应用、项目工具、设置”。应用详情集中账号、权限、当前内容、运行状态和任务结果；创作/发布/直播随能力开放，避免提前添加空页面。具体代码目录与接口见接入规范。

迁移采用带版本的映射，先在隔离副本核对账号、消息数量、来源、哈希和未完成任务。旧账号私密目录不直接合并到公开应用目录；鱼的个人项目迁入独立家目录，应用凭据和权威账本保留受保护边界。接收新写入后不自动回切旧格式。旧手机授权不转换成网页评论或发布授权。

### 6 · 房间约定（预留）

未来房间读取获准共享的生活状态，互动沿用来源、版本与更正机制。合成示例：主人在测试房间将画册放上书架，事件含房间、操作者、物件、动作、发生时间和确认结果；可以记为“有人放置了画册”，不能据此记为“大肥鱼读过画册”。此阶只定义契约和示例。3D 引擎、房间页面和实时渲染另行立项。

预演中发现两个启动问题。缺少素材清单时，旧服务会把缺失解释为空集合，清除已有的素材搜索记录。现在仅显式空数组才会在启动时清索引，缺失、损坏及旧版空值都保留原索引。有完整清单但无元数据要补录时，旧服务仍推进数据库分页版本。现在重复启动保留该版本，实际补录仍会使旧分页失效。恢复时应一并保留素材清单和关联历史；保留搜索记录并不能找回丢失的媒体原件。

### 5.B.5 · 本机请求的工具检查点

本机聊天在现有 SQLite 中为原请求事件及其版本登记工具检查点。文件创建、修改和 Windows 隔离进程启动先登记操作，再派发。检查点只保存参数摘要、必要的作用域及文件结果摘要。进程编号、状态、输出及取消由现有 Jobs 登记管理。启动编号由宿主根据请求、作用域和实际参数生成，模型在重试时更换自拟编号仍能找回原进程。

手动重试会先核对原请求的最近八项操作和总数。文件的已记录结果只代表当时的写入，当前内容可用文件工具读取。进程状态按旧进程编号续查或取消。已登记但缺少可靠结果的操作进入待核对状态。已有操作的请求，以及升级前缺少检查点的未完成请求，重试时允许续查和取消。补做写入或启动需要主人发起新请求。已知从未派发操作的请求仍可在修好模型配置后用同一编号重试。

验收使用合成模型和独立数据目录。正常 HTTP 路径覆盖文件写完后回复失败、进程已登记但聊天结果未提交、旧版未完成请求以及结果不明的写入。真实 Windows LPAC 用脚本写入次数标记，核对重启并更换自拟编号后仍只运行一次，同时验证撤权和保留查询。Windows 预览构建、HTTP/Edge 生命周期、全库 vet 和跨包定向回归通过。companion 和 agenthost 整包回归分别用时 127.446 秒和 3.847 秒。自动唤醒和完成后的后台续办仍待实现。

### 5.C.2 · 按应用连接核对原消息和发送回执

主人可从同一连接查询 `GET /api/apps/{app}/connections/{connection}/events/{message}?conversation=…`。微信适配器按该账号和获准会话从现有 SQLite 找原事件，保留原消息、平台编号、发送者、原时间、来源版本与素材引用。遗忘、来源冲突或范围不符的记录不可读。返回限于来源元数据；引用必须指向同会话内仍可见且版本匹配的原消息。原生接收序列和记忆库记录序列分别呈现，历史缺失原生游标时留空。顺带修复短窗口聚合给后续消息沿用锚点来源的问题，单条、短窗口聚合和未读汇总分别携带各消息的原生序列。

### 5.F.3 · Windows 独立 Edge 页面读取

- **实现**。B 站应用增加单独的浏览器授权，升级后默认为关闭，原来的 BV 清单与稿件接口权限继续可用。主人开启后，`app_observe(field=page_text)` 可读取获准 BV 页面的标题和可用简介。网页观察和稿件接口分别保存。撤权会取消在途浏览器读取，并使旧缓存失效。
- **隔离**。从 Windows 的 Program Files 定位本机 Edge，使用应用连接专属资料目录。进程进入宿主创建的 Windows Job 后才运行，通过私有 CDP 管道通信。该路径没有 TCP 调试监听，也不挂接日常浏览器。页面策略只放行一次匹配的主文档 GET，禁用页面脚本、Service Worker、下载和认证，并阻止子资源及重定向。[Chromium 管道实现](https://chromium.googlesource.com/chromium/src/+/main/chrome/test/chromedriver/net/pipe_builder.cc)
- **验收证据**。Windows 上用真实 Edge 读取本地合成页，确认标题和简介可读，内联脚本未改写内容，测试服务只收到主文档请求。另有模拟协议回归覆盖重定向、撤权、取消和并发关闭。隔离桌面包验证启停、窗口和单例。390 像素无头 Edge 测试经打包程序读取一条真实 B 站公开页，返回 HTTP 200。关闭浏览器授权后同一读取返回 403，稿件接口仍可发现。
- **范围**。本阶交付匿名网页文本和隔离运行边界。平台登录接管、评论、音轨、画面和实际播放区间仍需分别验证。

### 5.F.4 · Windows B 站播放区间取证

- **实现**。主人可另行开启播放验证，原有网页文字权限保持原样。宿主解析清单内 BV 的公开单段 MP4，通过私有 CDP 管道将最多 32 MiB 媒体送入专属 Edge 的本地 Blob。采样从开头开始，默认 6 秒，可指定 1–20 秒。播放器静音，采样结束时暂停。撤权会取消取流或播放，并拒绝旧缓存。
- **证据模型**。采纳播放器报告的 `played` 区间，分别保存就绪、暂停、结束状态。只有实际区间从零连续覆盖整段且播放器已结束才记完整播放。就绪但未推进的状态可重试。相同授权及采样时长复用证据，其他时长独立采样。[HTML 媒体时间区间定义](https://html.spec.whatwg.org/multipage/media.html#time-ranges)
- **验收**。真实 Edge 回放四秒合成色块，覆盖部分播放后暂停、自然结束和取消。Windows 隔离包通过真实公开 BV 验证。请求采样 3 秒，媒体总长约 212.39 秒，实测 `played` 为 0–3.12 秒，状态为已就绪、已暂停、完整播放为 false。重复读取命中缓存，撤销播放授权后返回 403，网页文字仍可发现。无头 Edge 检查了 390 像素应用页和授权流程。
- **范围**。本阶验证播放器时间轴。画面内容、音轨理解、评论和多分 P 分别留给对应能力。

### 5.F.5a · Windows B 站公开一级评论

- **实现**。应用页增加默认关闭的评论授权。宿主从获准 BV 解析准确稿件编号，匿名读取固定 HTTPS 端点，逐条核对稿件、一级评论类型和来源编号。结果保留原文字、评论编号及发布时间。评论不进入标题、简介、音轨或播放证据。

### 5.F.5b · Windows B 站音轨分段与本机转写

- **实现**。为公开 BV 增加独立音轨授权，复用固定公开单段 MP4 解析和 32 MiB 媒体边界。FFmpeg 只在宿主私有临时目录解码，向本地媒体识别工具传入当前窗口的 PCM。识别资源由本机主人登记，通过稳定的大肥鱼身份授权，与微信账号及家目录写入权限独立。
- **证据**。音轨页返回媒体摘要、容器总时长、读取窗口、PCM 实际时长和识别状态。按时间顺序续读，默认窗口 60 秒，可选 1–240 秒；后续窗口可调整。续页核对媒体摘要，来源改变时停止合并。无音轨、空窗口和未识别到词单独记录。音轨证据不推导视频画面或播放情况。
- **验收证据**。真实 FFmpeg 的合成样本覆盖有声和无音轨、重启续读、未识别到词和中途撤权。宿主另测续读时替换来源会被拒绝。Windows 隔离桌面包用公开稿件和本机 SenseVoice，实际转写 0–30 秒和 30–38 秒两页，PCM 时长约 30 秒和 8 秒。停用识别工具后返回 503，关闭 B 站音轨授权后返回 403。管理页在 390 像素宽度验证了授权开关，Windows 启停、窗口与单例另有离线回归。相关 Go 测试、竞态检查、全库 vet、JS 静态检查和仓库扫描通过。
- **验证边界与下一步**。当前使用可下载的公开单段 MP4，暂未接多分 P 或仅有 DASH 的媒体。模型和 SDK 单独准备，Windows 运行验收使用已核验的本地资源。下一阶验证抖音只读入口，分别记录可取得的来源与平台限制。

- **验收证据**。合成传输验证固定地址、令牌头、分页、来源链接匹配及平台错误分类。宿主回放覆盖续读、主动刷新与撤权。390 像素隔离桌面包验收未配置、已配置、过期和停用状态，过期返回 409，停用和未授权关键词返回 403。Windows 构建、启停和单例、相关 Go 测试、竞态、全库 vet、JS 静态检查和仓库扫描通过。
- **下一步**。单独核验已获用户授权的本人作品基础信息，作为后续发布回执核对的来源。真实搜索结果仍待有权限的应用令牌验收。画面、音轨、评论、播放与投稿使用各自的能力。

### 5.F.6b · Windows 抖音本人作品状态读取

- **实现**。抖音应用增加独立的 `own-videos` 连接。主人将用户 OAuth 的 `posting.behavior` 授权及允许查询的作品编号登记到站点私有目录，凭据不进入家目录、管理接口或工具结果。通过固定官方接口核对准确作品编号，每次读取当前状态，不复用旧审核状态。搜索应用令牌与本人作品用户令牌不能互相代用。
- **结果含义**。结果保留作品编号、平台状态和本次观察时间。已知公开状态可附标题及创建时间，创建时间不表示发布时间。审核中、不适宜公开或未知状态不附标题。缺少状态字段、返回其他作品、读取中撤权及授权版本变化均拒绝该次结果。这个读取结果只证明查询时的平台信息，后续发布操作仍按自己的任务和回执对账。[官方作品查询](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/posting-task/video-basic-info)
- **验收证据**。合成传输验证固定 HTTPS 地址、POST 正文、用户令牌头、作品编号及状态字段，覆盖平台忙、限流、参数错误和查询中撤权。宿主验证审核中转公开及重启后重新读取。隔离 Windows 包的管理 API 与 390/1280 像素 Edge 页面验证两种连接独立展示，无令牌泄露或卡片横向溢出。过期返回 409，停用和未授权作品返回 403。Windows 构建通过两次真实服务启停、8 次隔离桌面退出循环、12 次重复启动及本地 WebView 生命周期检查。相关 Go 回归、竞态、全库 vet、JS 静态检查和仓库扫描通过。
- **尚未验证**。没有使用真实用户 OAuth 授权查询本人作品，没有真实上传或发布。本阶由主人手动登记平台返回的授权，尚未提供 OAuth 获取与续期界面。全库测试的既有失败记录见 5.F.1，本阶运行相关范围回归。正式运行实例和微信登录保持原状。
- **下一步 · 5.G.1**。建立跨应用的创作草稿与发布任务，绑定可编辑工程、成品摘要、目标连接和授权版本。先以离线应用验证上传、取消、未知提交及重启对账，再接平台实际支持的上传和发布接口。B 站与抖音未接入的观察字段和真实授权验收继续单独记录。

### 5.G.1 · Windows 创作草稿与应用发布账本

### 5.H.1 · Windows OBS 本地预览

- **实现**。Windows 包可选附带 OBS 预览工具。主人自行启动 OBS Studio，启用带密码的 WebSocket v5，在项目工具登记回环端口与密码并启用。工作台可开始预览当前节目场景、查看最近画面与时间、直接停止预览。宿主只通过 `127.0.0.1` 读取节目场景及 JPEG，不接触 OBS 配置文件。密码存于当前大肥鱼身份的宿主配置，画面只送本机主人页面，内存中的当前帧会随停止、停用或退出页面清除。[OBS WebSocket 协议](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)
- **停止边界**。停止、停用、退出管理登录和关闭程序都会撤销本次预览并中断进行中的读取。旧请求不能重新开启已停止的预览。无取帧请求持续 60 秒也会结束预览。重启保留登记和启用状态，预览需重新开始。首版连接由主人管理的 OBS，停止只作用于工作台的预览。

### 5.H.2 · Windows 应用直播会话与急停

- **实现**。直播宿主将原请求编号、应用安装、连接账号、授权版本和结束时间写入同一会话。只接收落在授权窗口内且未超过授权时长的请求。SQLite 为每个大肥鱼身份保留一个未结算会话；相同请求只返回已有会话，不重复开播。回执须匹配原会话、账号和授权版本才能更新状态。
- **急停与恢复**。本地主人可对原会话急停。宿主拦截后续开播动作，停止本次会话的本地输出，再用原操作编号核对远端。到期、撤权、输出异常、平台失联或应用关闭均进入同一停止流程。本地停止和平台结束分别记录，任一未知时保持待核对。重启先清理原会话，不自动开播。
- **验收证据**。SQLite 跨连接竞争只领取一个活跃会话，同请求重放返回原记录。合成应用和输出回放覆盖授权窗口、错误账号及直播间回执、迟到开播、掉线、撤权、输出异常、到期急停与重启。主人 HTTP 验收检查会话鉴权、CSRF、原会话开播与停止。Windows 隔离构建通过桌面单例、服务启停、WebView 退出，两次实际启动均验证生产直播目标为空。相关 Go 回归、竞态检查、全库 vet 和仓库扫描通过。
- **能力范围**。本阶通过合成应用和本机输出验证宿主契约。生产版尚未登记直播平台适配器或受宿主管理的推流输出，因此不会列出可开播目标。5.H.1 的 OBS 预览仍由主人独立控制。
- **下一步 · 5.H.3**。核对首个平台的账号授权、开播回执和推流协议，接入受宿主管理的 OBS 输出，再逐项验证开播、断线与停止。

### 5.H.3a · Windows OBS 独立编码器控制

- **实现**。在预览所用的认证协议上增加独立编码器控制。每次连接在 WebSocket 握手前由宿主验证本次租约持有的 TCP 对端。编码器只接收发往本机回环中继的地址和临时票据。OBS 会保存推流服务设置，平台推流凭据留在计划中的宿主中继侧。开始请求结果未知时，本次租约不会重复提交。停止可以中断正在配置的连接并封闭后续开始请求；若开始请求已经发出，优雅停止的响应与本地输出状态分别读取。已有节目预览入口继续仅取帧。[OBS 推流控制](https://github.com/obsproject/obs-websocket/blob/master/src/requesthandler/RequestHandler_Stream.cpp) · [OBS 服务配置](https://github.com/obsproject/obs-websocket/blob/master/src/requesthandler/RequestHandler_Config.cpp)
- **平台准入**。B 站一键开播需要单独业务准入、分区和每场直播确认。应用 OAuth 授权不能代替单场开播凭证。B 站将一次性凭证发送到已登记的厂商回调，当前本机回环管理服务无法接收该外部回调。开播响应丢失时不重放一次性凭证；直播间状态只作旁证，不能单凭直播间离线判定原操作已经结算。[准入条件](https://open.bilibili.com/doc/4/2e018d85-a96e-9deb-dcd6-478fb06cb5b2) · [授权回调](https://open.bilibili.com/doc/4/68757db2-f8bf-eab2-0b09-4bafe1d65264) · [开播接口](https://open.bilibili.com/doc/4/cafd6cf4-be34-d2c6-4d43-ca309b7ad346) · [停播接口](https://open.bilibili.com/doc/4/e84cd5ba-68fe-effe-1835-c2a2ff22a72a)
- **验收范围**。Windows 上使用合成 OBS 对端验证连接校验、回环中继配置、开始、状态、停止、停止与配置竞态、开始响应丢失及重连状态。定向 Go 回归、OBS 竞态检查、全库 vet 和仓库扫描通过。Windows 隔离构建通过服务启停、桌面单例及 WebView 退出，发行包仍只附带预览工具。生产直播目标继续为空，实际 OBS 编码、回环中继与平台直播尚未验证。

### 5.H.3b · Windows 专用编码器进程归属

- **实现**。宿主提供受信运行目录、可执行文件摘要和专用控制参数。Windows 在创建进程时将其加入本次会话的 Job，子进程随同管理。启动器使用独立工作目录和少量系统环境，控制密码不由启动器放入参数或环境。停止先封闭本次编码器的开始请求，再终止所属 Job，确认进程树清空后返回。核对超时保留句柄供原会话继续查验。[Windows 进程创建属性](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) · [Windows Job 对象](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
- **控制边界**。每次握手前按操作系统 TCP 表核对回环监听和当前连接的反向四元组，二者都须属于仍存活的本次启动进程。通配地址、同端口 IPv6 监听和其他进程的端口均拒绝。Job 管理生命周期。编码器的文件与网络隔离仍依赖受信运行时及部署边界，监听快照不能替代这些约束。
- **验收证据**。Windows 上用真正的合成编码器进程完成认证取状态、宿主环境隔离、摘要拒绝和控制端口归属检查。正常停止后本次编码器及子进程退出，无关监听仍可用。强制结束合成宿主后，原编码器、子进程及控制端口均退出，重复通过 5 次。Windows 隔离桌面包通过服务启停、单例和 WebView 退出。
- **尚未验证**。正式 OBS 运行时及节目输出、实际中继、平台开播与停播。当前 Windows 包继续提供独立的只读节目预览，生产直播目标仍为空。
- **下一步 · 5.H.3c**。提供会话级本机推流中继，将实际输出、急停与平台回执接入同一会话，并验证断线和宿主重启。生产编码器使用专用、可核验的回环控制配置后才登记。

### 5.H.3c · Windows 会话级 RTMP 推流中继

- **实现**。受管编码器只得到回环端口和本次随机票据。中继先按 Windows TCP 表核对发布连接属于本次编码器，再核对票据。获准平台返回的接收地址、密钥和出口策略只留在宿主内存，不进入 OBS、会话数据库或状态接口。每个会话只接受一次获准发布，且只发起一次到平台接收端的连接。中继转发音视频与必要元数据，只有写出实际媒体包才增加本机计数。[RTMP 库与版本](https://github.com/bluenviron/gortmplib/tree/v1.0.5)
- **会话与急停**。直播宿主先核对原平台回执和授权，再启动本次专用编码器及中继。管理 API 的 `local_output` 单独报告本机等待、连接、转发、断流或停止，平台状态仍来自独立回执。取消时先关闭中继入口和原套接字，再收掉所属编码器。宿主重启仍只核对和停止原会话，媒体计数属于当前进程。
- **依赖**。并行消费下游 RTMP 控制消息并写媒体，使用支持并发读写的 gortmplib v1.0.5。主程序最低 Go 版本更新为 1.26，Windows 构建固定 Go 1.26.10。MIT 许可随 Windows 安装包分发。
- **验收证据**。Windows Job 中启动的真实合成子进程通过原 PID 核验，向回环中继发布 H.264 夹具，模拟平台核对原始字节。另以合成接收端验证 AAC、元数据不计为媒体、错误票据不尝试连接接收端、断流不重连、急停中断握手及启动中取消。会话集成连续通过 5 轮，覆盖私密字段检查、重复请求与重启只结算原任务。Windows 隔离桌面构建通过，管理服务 EXE 较 5.H.3b 增加约 0.91 MiB，差值包含 Go 工具链升级。
- **尚未验证**。实际 OBS 节目编码、B 站授权回调、正式平台接收和观众端播放。生产仍需提供核验通过的专用 OBS 控制配置和平台适配器。
- **下一步 · 5.H.3d**。落实可部署的专用 OBS 配置和生产注册条件。平台能力继续按业务准入、每场授权回调和已绑定操作回执逐项接入。

### 5.F.DY.2a · 从抖音搜索结果核对官方播放器入口

- **实测边界**。Windows 上通过实际适配器对两个公开文档站示例发起匿名 GET。一个返回相同作品编号的官方播放器地址，一个返回非公开视频状态。未使用主人登录资料，也未播放视频。平台响应的标题、播放器地址与已观看区间是不同证据。[官方播放器接口](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/iframe-player/get-iframe-by-video)

- **下一步 · 5.F.DY.2b**。验证专属浏览环境能否在不打开抖音首页和不使用主人浏览器资料的条件下，取得官方播放器实际进度。另接开放平台获准的账号作品列表，保留账号和作品授权边界。

### 5.F.DY.2b · Windows 独立 Edge 静音核对抖音播放区间

- **实现**。在已核对的官方播放器入口上加单独的后台播放授权。模型只用同一作品的跟进编号，默认采样 6 秒，可选 1–20 秒。宿主按原作品重新核对公开状态，再使用新建的独立 Edge 资料和 Windows Job 静音采样。对播放器网页使用回环受限出口，固定官方页面和必要请求，不打开推荐流。返回浏览器的实际播放区间，不写入签名媒体地址，也不把就绪或播放器时长写成已观看。
- **平台边界**。官方嵌入接口公开的是播放器入口，页面加载过程中使用的资源与媒体传输可随抖音调整。只接受当前核验过的请求和官方媒体域名。该能力验证播放器推进，画面识别、音轨与内容理解保留独立证据。
- **验收证据**。从正常观察接口注入合成搜索页，再由实际适配器核对同一公开作品的官方入口，并由 Windows 独立 Edge 通过受限代理静音播放。一次 2 秒请求实际记录 1.90 秒区间，官方播放器报告总长 12.16 秒，未标为完整播放。初测发现新资料的官方详情请求带空 msToken，接受浏览器实际发送的空值并保持作品编号及其他字段校验。合成测试覆盖独立授权、非公开、就绪但未推进、撤权后禁止使用迟到证据、网络越界以及取消后关闭代理。
- **下一步 · 5.F.DY.2c**。核对站点类型当前获准的账号作品列表接口，补上分页、同一账号授权和作品来源验证。随后进入创作发布，不用测试账号发真实作品。

### 5.G.DY.2 · Windows 抖音授权续期与原投稿任务恢复

- **实现**。在 Windows 桌面为本机主人提供「续期授权」。宿主通过官方接口刷新访问令牌，核对原应用、原账号、资料接口及已授予权限。续期保留仍有效的授权编号，已确认的上传分片和作品续读游标可继续使用。重新扫码或解除连接更换授权编号。凭据只保存在宿主，管理页显示到期时间与可用动作。[官方访问令牌续期](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/account-permission/refresh-access-token)
- **失败处理**。权限缩减后关闭对应工具。平台确认续期令牌失效时移除该令牌，主人可在桌面重新扫码。网络结果未知或账号核验失败时保持原本机记录，由主人核对。续期不自动重试。解除连接优先于迟到的续期结果，旧版仅有访问令牌的连接可继续用到原有效期。
- **过期重连**。Windows 桌面在已过期且无法续期时直接展开「重新扫码授权」。合成服务回归验证首次扫码、重启恢复、过期后重新扫码及再次重启。Edge 窄窗回放验证重新扫码入口自动展开及接入成功后的状态更新。
- **验收证据**。合成 Go 回归覆盖表单、凭据不外露、跨账号拒绝、撤权、未知响应、竞争续期和 CSRF。确认分片后续期并重启，原任务使用新令牌从下一片继续。分片回执不明的原任务保持待核对。定向管理测试、抖音适配器与应用宿主竞态、全库 vet、JS 语法和仓库扫描通过。Windows 隔离桌面包通过生命周期测试，Edge 合成回放通过桌面续期、浏览器只展示账号状态及 375 像素布局。
- **平台边界**。当前核实的评论读取及回复能力要求小程序授权。开放平台公开一键开播 SDK 列出 Android 与 iOS。网站 Webhook 的 create_video 是用户通过应用分享的事件，返回 share_id，不能据此认领直传投稿的缺失回执。真实抖音续期、审核及 Windows 开播未验证，正式程序未替换。[评论能力](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/server/basic-abilities/video-id-convert/video-review-data/comment-list) · [开播 SDK](https://developer.open-douyin.com/docs/resource/zh-CN/dop/ability/douyin-live-sdk/douyin-live-sdk/android) · [网站 Webhook 事件](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/webhooks/event-list)
- **下一步**。在平台专有权限和直播回调未获验证前，推进 5.I 的 Windows 成长站隔离与旧手机入口清理，并用零应用及已连接应用回归验证。B 站专属开停播继续暂缓。

### 5.I.4 · Windows 服务去除旧设备执行驱动

- **实现**。共用管理包改用旧设备输入输出契约。Windows 独立站和旧版管理归档服务都没有接入执行驱动。仍使用旧执行路径的其他平台入口显式接入驱动，子账号沿用所属宿主的驱动及退役状态。移入契约的任务与权限回查继续由设备代理在调用边界执行。
- **验收证据**。两个 Windows 服务均通过依赖图与实际 EXE 符号核对，均不包含 `adbserver` 和 `devicebroker`。打包脚本在构建前拒绝重新引入这两个包。使用相同 Windows 编译参数，独立站服务从 37,425,152 字节降至 37,282,304 字节。旧管理服务用合成账本实际启停两轮，两轮均能经鉴权读取旧截图和录屏，原账本字节相同，设备枚举和任务新建入口均关闭。合成竞态测试验证归档、旧调用链和执行中撤权。
- **应用回归**。Windows 微信与抖音组合包通过隔离桌面启停；微信应用的完整合成浏览器回放、抖音授权回放分别通过。修正了前序抖音回归文件的包摘要，以及续期接口的清单断言。其他平台旧入口仅验证 Linux 目标仍链接原驱动并可编译，未运行实际设备。
- **全库边界**。全库 vet 与仓库扫描通过。首次全量 Go 测试发现旧版抖音清单断言，修正后相关包及除管理、记忆外的整包回归通过。管理测试包达到默认十分钟上限，当时正在运行的微信多账号用例单独复跑通过（14.322 秒）；既有旧记忆来源选择断言复跑仍失败。全库尚未放行。
- **尚未验证与下一步**。当前正式程序未替换，未读取真实账号或设备档案。独立站仍共用部分管理包及历史数据契约。下一阶隔离独立站的认证和应用 HTTP 入口，缩小与旧微信专用管理端共用的边界，再审计 Windows 主线切换条件。

### 5.I.5 · 独立站会话和应用 HTTP 接口脱离旧管理服务

- **实现**。两端各持有自己的通用浏览器会话。成长站的路由直接使用本机主人会话，旧管理端的子账号路由仍复用旧端根会话。登录、同源校验、CSRF、到期与退出由通用组件处理，旧端改密仍在保存成功后清空旧端全部会话。应用目录、连接接入、授权范围、原消息和回执的通用 HTTP 路由已移到独立包，由已登记适配器处理，保持原路径与响应。
- **验收证据**。同一浏览器分别登录两端，旧端凭据不能打开成长站应用目录，旧端改密不影响本机主人会话，成长站退出后旧端仍可访问。合成测试覆盖到期拒绝及后续权限回查、子账号共享会话、CSRF、改密写盘失败、接入和原回执。两个新包的编译依赖不包含旧管理、微信原生及设备驱动包。Windows 独立站 EXE 的符号核对没有旧管理服务构造、鉴权和改密入口。Windows 组合包启停、微信与抖音浏览器回放、定向 Go 回归、全库 vet 和仓库扫描通过。
- **尚未验证与下一步**。本阶保留原凭据文件格式与读取优先级，正式程序未替换。独立站命令仍从共用管理包启动并读取密码。本机主人凭据启动入口、站点资产和其他宿主服务继续分步拆分，随后在 Windows 隔离副本核对切换。全库测试沿用 5.I.4 已记录的边界，本阶未整库重跑。

### 5.I.6 · 独立站凭据启动和页面资源

- **实现**。独立站从本机私有目录加载主人凭据，启动命令已不调用旧管理端的密码加载器。已有文件名和优先级沿用原约定，环境变量不落盘，损坏、超限或不可用的优先凭据会拒绝加载。Windows 桌面自动登录遵循相同顺序，成长站管理请求不再附带旧微信账号头。站点页面、脚本和图片由独立包嵌入，旧管理端首页与 `/local-home` 兼容入口分别保留。
- **验收证据**。Windows 真实桌面控制器在隔离目录用环境变量首次自动登录，核对无凭据文件写入，再用旧格式受管密码覆盖环境变量并重启登录。Go 定向竞态覆盖密码优先级、格式、原文件保留、两端首页和旧设备归档。Windows 实际启动拒绝通过目录联接读取凭据。新独立站 EXE 的符号检查不含旧密码加载器、旧管理页面资源和设备驱动，服务体积比 5.I.5 减少约 2.49 MiB。微信与抖音组合构建、桌面启停和两套离线浏览器回放通过。
- **尚未验证与下一步**。普通文件符号链接的 Go 用例因当前 Windows 权限跳过，目录联接拒绝已单独验证。本阶未重跑全库测试，也未替换正式实例。独立站仍从共用管理包构造宿主，下一阶核对剩余构造和运行时依赖，再在 Windows 隔离副本预演主线切换。

### 5.I.7 · Windows 独立运行器与工具启动检查

- **验收证据**。Windows 微信与抖音组合包通过桌面生命周期和合成浏览器回放。实际服务在启动时拒绝指向外部目录的控制目录联接，目标目录没有写入。实际 Windows LPAC 回归通过自编工具持久化、撤权、续办复用原任务编号，以及从本地聊天生成可编辑 DOCX 和 PDF 的流程。定向 Go 竞态测试和全库 vet 通过。运行器包的依赖图不含旧管理、微信原生及设备执行包。

### 5.I.8 · 独立站宿主与应用挂载分离
