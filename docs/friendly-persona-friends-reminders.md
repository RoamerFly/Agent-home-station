# 大肥鱼：朋友式人设、好友私聊与成员提醒

本轮管理端版本：`0.24.0-friendly-reminders-local`。

## 人设与表达

角色档案默认改为活泼、机灵、温暖的鲸鱼娘朋友：轻松时接梗、搞怪和温和吐槽，难过时先回应具体处境，认真问题认真回答。故事、比喻和有出处的名言按语境使用；不把每条回复做成鸡汤，不固定用“哈哈/收到/我懂你”开头，不反复自报名字，不编造经历或引用出处。可以真诚表达不同意见，安慰不等于无条件附和。

设定保存在既有角色/persona、表达/style、相处/relationship字段；已有自定义配置不会在程序升级时被静默覆盖。本机实例按用户要求更新这三项，外观、声线、密钥和群聊规则保留。

参考：[Microsoft 人机交互指南](https://www.microsoft.com/en-us/research/articles/guidelines-for-human-ai-interaction-eighteen-best-practices-for-human-centered-ai-design/)的语境、时机和社会规范原则，以及[Anthropic 关于支持与陪伴的研究](https://www.anthropic.com/research/how-people-use-claude-for-support-advice-and-companionship)对情绪支持和过度迎合的讨论。角色表现仍由实际模型决定，提示词不能保证每轮一致。

## 好友私聊

群聊规则 → 私聊与文件传输助手：启用好友私聊 + 全部微信好友可私聊。启用后无须逐个填ID，也无需私聊前缀；关闭全部好友则保留旧限定联系人列表。文件传输助手保留原触发前缀，群聊授权不变。

接收消息前按原生后台联系人目录核对真实账号ID，昵称不是证明。支持分页与新联系人查询，正缓存5分钟、未找到缓存20秒；查询失败将消息保留在持久队列等待重试，不读取未确认联系人的正文。原生版本对contact表统一返回relation=unknown，当前依据contact目录成员关系（原生另有stranger表），不声称已取得协议级好友位；未来明确返回stranger/blocked/deleted/not_friend等关系时拒绝。开放聊天不授予服务器权限。

## 普通成员的持久提醒

模型可使用`agent_reminder`创建、列出和取消本人在本会话的提醒。支持相对秒数（两小时7200秒）或带时区的绝对时间；默认当前会话，私聊目的地只能是请求者本人且需联系人目录核对。不能填写任意收件人、脚本或文件路径。

每个提醒在`<admin>/reminders/<id>.json`有独立文件，执行状态同时持久化在`agent-state.json`。重启按原到期时刻恢复，创建后不循环推迟。专用调度不消费主动问候次数，不被主动问候开关或安静时段拦住；机器人、文字回复、Agent与任务总开关仍有效。发送前有动态延迟，使用稳定幂等键；只有实际微信accepted且有server_id才完成。排队/超时不等于已送达：保留原发送任务并随机退避核对，明确可重试的失败续办原任务，不换键重复新建；未知结果不会因为本地任务文件存在就假定已发或未发。

提醒正文始终是文字资料，不执行其中的命令。提醒列表和取消按账号、来源会话、真实发送者隔离，普通成员不能借此改写为主人后台任务、读取其他会话或修改项目。原有会话Markdown笔记继续可用，主机读写/执行及跨会话操作仍按真实主人身份授权。

## 验证边界

自动测试覆盖：动态好友准入、无前缀私聊、拒绝伪造昵称/陌生关系、普通成员无主机权限、实际文件持久化、重启恢复、未到期不发、取消竞争、作用域隔离、同请求幂等、排队与接受回执区分。提醒发送使用模拟原生接口；不发送真实微信测试消息。

额外可显式启用`TestLiveFriendlyPersonaAndOrdinaryMemberReminder`，使用本机已配置模型、合成对话、独立临时任务与模拟微信，确认模型自然回复并实际创建7200秒提醒。模型调用、文件执行证据与真实微信手机收件是不同验证层次。
