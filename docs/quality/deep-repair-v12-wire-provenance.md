# V12 审核输入来源编号迁移

V11 的固定候选与实际结果继续保留。本轮只验证审核输入的表示变化，不修改原 44/240 的正文、事实、人物、素材、语义预期或放行阈值。模型与预算维持主 flash/768、工具 4096、审核 pro/32768/high/240秒。

真实来源编号在宿主继续作为权威身份。审核请求将结构化元数据中的来源编号投影为单次调用内的 `S1…`，宿主保存严格的别名到真实编号映射。模型输出的 `source_refs` 仍是字符串数组；宿主只接受本次允许的别名，随后反解为原始真实编号。未知、抄错的别名及直接回传真实哈希均不能通过近似匹配。原文、引用正文、机器观察、候选文字和工具结果的字面内容不因编号投影而改写。

`K1` 是当前已授权请求、任务及素材范围内的宿主知识状态引用，用于区别“本次可见证据里没有接受回执”和“外界没有发生接受”。它不声称覆盖全部外部投递记录，不充当用户原话，不形成长期用户记忆。审计保留真实原始状态、实际审核输入及编号映射，并由宿主摘要关联。

质量包装器记录实际投影后的合成审核输入和实际模型、选项、安全 HTTP 诊断。新增离线 mock 仅检查此接口迁移：普通与嵌套包装器的实际 wire 别名、严格还原的真实来源、宿主审计绑定、未知别名拒绝，以及 K1 不变成用户事件。mock 中用于探测引用协议的 reject 不属于新的语义黄金案例，也不改变已有正确控制的预期。

本轮仍需新统一源码下完整执行一次 44 例。只有在原门槛通过后，才运行完整 240 例、预先固定的五轮核心场景及人工来源核对，不能通过修改旧候选或补抽消除之前的失败记录。
