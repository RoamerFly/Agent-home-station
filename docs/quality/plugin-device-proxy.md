# 手机设备代理、来源绑定与退出回收

日期：2026-11-01。环境：Windows amd64、Go 1.25.3、PowerShell；全部设备与模型资料为安全合成数据。

## 本轮实际行为

mobile-control 0.3.0 提供 `device.plan` 以及 `device.list/observe/act/record/read_artifact`。规划只需 `model.invoke`，设备门面只需另行授予的 `device`；既有 0.2 安装不能自行升级或扩大授权。

`device` 表示调用当前任务绑定的宿主代理，不给隔离插件挂载 ADB、设备或文件，也不授予 socket、私网、进程执行或微信发送权限。插件只转交有来源版本的操作并返回安全回执；原始 PNG 与录屏分块留在宿主私有结果中。每项原生回调预留一次，未知结果不重提。

主体的生产 `Control` 总是配置插件设备工厂。工厂出错、返回空结果或配置失败均不回退旧 MCP 命令。设备工具缺失、插件未授权或运行环境无效时不排新任务；旧任务仍能查看、取消、停止。

受控原生代理固定使用受信部署 Python 和已验证插件快照中的 `bridge.py`。旧参数仅用于识别官方脚本及原 `--config/--storage`；拒绝任意脚本、`-c/-m`、额外环境、HTTP 配置和请求头。ADB 必须位于显式登记的工具根，不能由插件或模型参数指定。工具根不进入插件的 RuntimeRoots。桌面程序仅登记实际存在、去重后的项目内 platform-tools 目录，不下载程序。

原生代理是拥有设备权限的宿主组件；它不是 LPAC 插件进程，也不是任意插件的无限制执行回退。它经受控 stdio 会话启动，环境只有明确的 OS 运行变量，不继承提供商密钥等自定义环境。

## 身份、幂等与回收

- 每次调用固定任务、请求者、设备、步数、观察、设置版本和包身份；策略深拷贝快照，不依赖随后被更新的共享任务对象。排队之后、原生调用之前及结果读取时均重验。
- broker 在启动原生进程前完成配置解析与封印。profile、ADB、固定脚本、派生配置与目录的 Binding 纳入来源版本；文件变动后不能继续调用或把 completed 旧结果当作当前结果读取。
- 延续原始 storage 账本，未知动作状态及原请求键不因插件切换被抹除。重复动作键复用原结果，不能因后续观察或读取改变序号而新建并重发操作。
- 物理设备租约按规范化 serial 共享，不以账号、别名或 ADB 路径区分。同 serial 的另一个账号/别名得到 busy，不同 serial 可并行。全局锁目录及新派生 profile 叶目录有独立私有权限；不递归修改旧数据目录。
- Windows 原生 stdio 会话在首个 RPC 前加入独立 kill-on-close Job Object。终止时确认其进程树为空；Linux 使用进程组，实际运行边界另行说明。清理未确认的会话可显式重试 Close，不能删除后重开 helper 绕过。
- 原生错误后先确认子树清理再放设备锁；清理失败时强引用保留隔离 broker 和租约，GC 也不能提前放锁。后续清理只执行 Close，不重放操作。
- RPC 使用锁内 transport 快照，关闭可中断 I/O，但不会把并发请求的指针清空导致 panic。管理端先停止设备任务拥有者，再关闭插件会话和存储。
- 同插件并发调用可取消地串行等待，获执行权后重新检查授权和幂等；不同插件独立。等待不等于已提交，取消或关闭会唤醒等待者。
