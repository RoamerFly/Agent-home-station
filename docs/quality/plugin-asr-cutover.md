# ASR 插件来源、配置与旧实现清理

日期：2026-11-01。Windows amd64、Go 1.25.3、项目内Python及Edge headless。测试仅使用合成账号、来源、音频、资源登记和提供商回调；付费提供商、真实微信、设备调用均为零。没有替换生产 EXE、登录、配置、记忆、声线或模型，没有创建旧备份或访问待删除目录。

## 已迁出的路径

- 删除 `bailian.Client.Transcribe`、Manager 裸 WAV `transcribeAudio/transcribeLocal`、旧本地 manifest runner，以及 `video_inspect_audio.go` 中的旧音轨识别入口。
- 入站语音在下载前要求已安装、启用且配置有效的媒体插件；未安装不读取录音，不回退旧 key、旧本地解释器或 `local_then_bailian`。
- 视频自动概览、指定音轨范围与续读使用原入站来源。解码、格式整理、真实时长和分页继续由核心处理；未配置识别时不声称已读取音轨。相同静音 WAV 的不同时间窗通过范围后缀保持独立请求身份。
- 管理员合成后校验绑定准确的已完成 Speech 任务及同一登录会话；参考音频识别绑定同会话 asset、原文件与窗口 WAV 哈希、请求者、原任务、来源版本及遗忘边界。二者不伪造原生微信消息。
- 共享同一转写策略、远程/本地协议、单次请求、费用记录和私有完成检查点。提供商候选必须与实际返回一致，未知结果不重试，撤权后不能继续读取或登记歌词。
- 所有旧可选 Live 测试的 ASR 部分改走临时安装插件和隔离运行时；预检在付费 Clone/TTS/ASR 之前，未显式选择时跳过。本轮未执行这些付费场景。

## 本地 profile 与兼容迁移

media-understanding 0.1.3 使用独立 `local_asr_profile_id`。运行时、metadata、选中的公开登记必须精确一致；缺失、无效或 remote 模式均不读取旧 `speech.ASRLocalModel`。模型、SDK 与 VAD 不复制、不重装；宿主只授予已登记的精确只读资源。

旧字段仅用于一次迁移映射。Go 管理端预演用受信任包及账号授权只读核验实际登记，不打开 Store、不启动解释器；成功后资源版本进入来源摘要。真实应用先保留停用，显式启用后 readiness 与 metadata 均从插件配置产生。登记变更使旧批准失效；未登记或失效的资源仍被阻塞。

Python 独立预演不能替代宿主安全资源策略，仍保留待宿主验证状态。旧混合后端 `local_then_bailian` 需要明确选择，不能被静默改成 local 或 remote。

本地结果在执行前后、Validate、完成读取与后续登记前重新核验 profile；SDK/VAD/登记清单变化会阻止继续使用。当前资源版本沿用已登记清单 SHA 与既有 SDK/VAD 校验合同，本轮没有新增模型质量认证，也不声称已验证真实模型/GPU识别。

## 界面及诊断

旧 ASR 开关、共享密钥、模型和后端表单已移除，媒体理解与识别进入真实插件详情，未安装时打开只读迁移预览。兼容本地服务表单只修改 YuE 字段，保留旧数据但不双写插件。Agent 诊断返回实际插件模型与 readiness，不能被旧语音配置误导。

三项能力使用专用等宽自适应网格，宽屏同排、窄屏单列；保存草稿、迟到响应与按钮解锁行为继续保留。截图与日志只在本机 temp 目录，不进入 Git。
