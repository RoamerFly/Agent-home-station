# 回复复核可靠性与诊断修复（2026-11-02）

## 已确认原因及证据边界

本机只读核对确认：相关分享的读取及媒体理解完成，会话偏好进入实际模型输入，首次生成选择回复；随后来源复核在返回校验阶段失败。旧审计仅保留空的核验结果及 `initial_check_failed`，活动记录仅保留 HTTP 200、decode 阶段及请求次数，未记录具体协议校验项。因此不能从现有记录确定当时漏了哪个字段，也不能将它称为一次有效的事实或隐私拒绝。

两处实现缺口可以离线复现：合法 JSON 但不符合逐句复核协议的响应没有受控格式修复；复核停止发送的原因又被主流程改写成 `model_chose_silence`。这与管理员设置的分享偏好未生效不同。

## 行为调整

- 保留普通社交安静、安静时段、权限阻止等原策略；复核异常和事实拒绝不再映射成主动安静。
- JSON 语法错误与宿主协议错误共用最多两轮格式校验，不叠加第三轮。重试保持原模型、思考设置、输出预算、候选、证据及原截止时间；不回传旧响应或隐藏推理。
- 有效的 `reject` / `uncertain` 直接进入原有一次改稿及终核流程，不重新抽取“通过”结论。没有支持、拒绝、来源失效、额度不足与网络错误各自保留原因；不能绕过来源/隐私检查发送。
- 来源或授权变化等宿主错误不会被当成格式问题重试；模型也不能通过输出 `review_failure` 伪造宿主诊断。
- 协议校验可区分缺失句段、句段数量或编号异常、无效文本范围、缺少命题/理由/证据、未知引用、不匹配摘录、无证据支持及覆盖不全等情况。安全诊断只包含固定代码、数字与程序生成的说明。
- 活动记录、执行回合、预演及回复依据区分处理异常与主动安静。记录实际 HTTP 状态、请求尝试、格式校验轮次、结束原因、响应长度和 JSON 状态；只有实际安排重试的事件显示重试中。
- 关闭正文快照时仍保留安全的复核失败元数据。不会补造旧记录未保存的具体失败项。
