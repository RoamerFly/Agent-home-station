# 功能使用流程检查与修复（2026-10-31）

## 本轮目标

按用户操作流程检查新增、编辑、移除、恢复、取消、失败反馈与未保存内容保护。主要采用源码检查、合成 API 测试与浏览器回归；不新增付费模型测试，不发送真实微信消息，不删除真实账号。

## 已修复

1. 附加账号缺少移除、恢复和备注编辑：提供卡片操作；备注优先用于列表显示。主账号是本机服务入口，不允许移除，但仍可暂停或通过已有账号操作退出登录。
2. 原生账号目录会自动导入，简单删除会在刷新后重新出现：在 accounts.json 持久保存移除状态，刷新和重启不会重新启用。恢复沿用原账号身份及资料。
3. 防止移除正在工作的账号：需先暂停 Agent，后台进程、设备或音乐任务繁忙时拒绝移除。账号请求与移除操作互斥，已取得旧路由的请求不能在移除后重启账号。数据库不在请求处理中关闭，保留到服务退出统一释放。
4. 移除仅退出管理列表及阻止 API 路由，不擦除配置、聊天、模型或原生登录资料，也不表示注销微信账号。已移除项提供恢复入口；主账号登录不受影响。
5. 插件虽保留移除记录却没有恢复入口：展示已移除插件，恢复保留独立密钥并保持停用，密钥不回显。
6. 插件刷新、切页会丢草稿：现在保留编辑；切换插件、新建、模板替换或导入文件前仅在存在草稿时确认放弃。
7. 工作区文档在新建、换文档或切换存储范围时会丢草稿：增加必要的放弃确认和关闭页面保护；取消操作后恢复原选择。
8. 切换账号曾直接清除全局未保存标记：删除该行为，沿用浏览器离页保护；插件草稿也纳入离页保护。
9. 账号操作按钮按可用宽度换行，不挤压账号名称。
