# 合成评测的提供商故障与续办边界

余额或鉴权故障属于评测基础设施未完成，不表示模型理解错误，也不能以已尝试数量宣称完整验收通过。

七个实模测试入口共用 runner 内的调用保护。只有 SDK 的结构化诊断同时满足以下条件才停止该 runner：

- HTTP 402，且代码为 `model_insufficient_balance`。
- HTTP 401 或 403，且代码为 `model_authentication_failed`。

普通文本提到这些代码不会触发停止；限流、服务暂时不可用、内容过滤及其他故障沿用原处理。首次明确致命错误之后，该 runner 不再发出评分、编辑或下一案例请求。已经在同一批次其他进程中开始的调用不由这个局部保护冒充已取消；外层调度器应读取 `provider_blocked`，停止安排新 runner。

检查点保存当前真实尝试，保留已生成正文、实际输入、来源及用量。尚未尝试的案例不创建虚假失败记录：

| 字段 | 含义 |
| --- | --- |
| `requested_cases` | 原选取范围，未缩减 gold 或样本量 |
| `attempted_cases` | 已保存的真实尝试，包括本次受阻尝试 |
| `remaining_cases` | 尚未尝试数量，不包括另行保留的受阻尝试 |
| `pending_case_ids` | 尚未尝试的固定案例编号 |
| `provider_block` | 安全诊断代码、状态、案例及发生阶段 |
| `continuation` | 受阻案例、阶段和待处理位置，不代表自动恢复许可 |

受阻检查点标记 `partial=true`、`assessment_complete=false`、`model_quality_gate_passed=null`、`release_gate_passed=false`。原始测试退出码及已完成案例的原判分保留。若正文已生成而评分失败，保存正文并定位到 `rubric` 阶段，不重新生成。不能只凭 HTTP 错误字符串认定“未生成”，须读取阶段和已经保存的结果。普通 `--resume` 拒绝直接重放受阻检查点；恢复后需要明确的分阶段续办安排，不能覆盖已有失败或挑选更好结果。

聚合器也识别保留的旧版安全诊断字段。遇到提供商受阻或未完成检查点时，输出未知的完整质量指标并非零退出，不将 HTTP 错误折算为语义正确率。正常完成的 240 项、95% 及关键归属错误为零的原门槛保持不变。

这次变更仅影响评测控制、检查点和报告，未更改生产模型策略、原案例、固定草稿、gold 或阈值。控制代码纳入评测协议哈希；新控制协议不能悄悄续写旧协议报告。V15 的原始失败、HTTP 402 和未完成证据继续保留。

离线验证使用带明确标记、只能返回失败的进程内 provider fixture，不访问真实模型服务，不使用真实密钥。它实际进入七个 runner 的测试入口，核对首个 402 后调用次数为 1、其余案例待处理；另覆盖生成成功但评分受阻时正文保留。该验证不代表真实模型质量、微信投递或手机播放通过。
