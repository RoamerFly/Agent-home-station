# 手机插件迁移基础与权限修复

日期：2026-11-01。运行环境：Windows amd64、PowerShell、Go 1.25.3。
本轮只处理源码、隔离合成测试和临时构建；没有修改生产账号、模型密钥、微信登录或旧任务。

## 实际改动

- `Manager.mobile` 改为 `deviceService` 接口。旧实现通过惰性适配加载，未配置时读取默认设置、任务列表、繁忙状态、停止和关闭均不创建设备目录，也不启动桥接进程。
- 旧手机配置/任务损坏只令设备服务不可用，不阻止聊天 Manager 构造、读取核心配置或暂停 Agent；原始错误保留在设备层，公开接口返回不含文件正文的 503。修复旧文件后可以重试加载，不自动覆盖损坏配置。
- 将 ADB bridge 实现放到 `plugins/mobile-control/runtime/bridge.py`。原 `scripts/mobile_bridge.py` 保持固定相对路径兼容入口，不接受外部模块路径。
- 设备规划和详细提示整理为 `plugins/mobile-control/backend` 的可注入实现；模型配置、思考控制、用量和诊断继续走宿主原模型路径，没有新建模型客户端或固定另一种模型。
- 修复微信端正常取消被 Admin 标记误拒绝，以及同群其他成员借 Admin 标记取消他人任务的问题。原请求者需匹配账号/会话/发送者并重新通过授权；已鉴权管理页可以在原请求者撤权后取消孤立任务。
- 在首次观察后、规划后、二次观察后和实际动作前重新核验当前任务、取消及权限；录屏逐块读取、最终分块后、分析前和持久化前继续核验。未知动作结果保持待核对，不自动重放。

## 尚未完成

手机插件仍不能通过新宿主启动。当前规划层虽然位于插件目录，仍静态编译进入主体；设备队列、旧配置、管理页面、录屏分析和兼容桥接也仍有主体依赖。新审计把这种编译依赖单独纳入轻主体失败条件，不能仅以文件目录移动宣称完成。

下一步需要宿主受控设备代理、受来源约束的截图/模型交接、独立插件进程和队列/配置/页面迁移。`device` 权限在隔离策略未完成前继续明确拒绝，不以旧命令进程作为隐式隔离替代。

审计当前为 9 类插件、4 类受限就绪包、111 个可选功能源码命中（按插件归属计数，可重复命中同一文件）、4 个内部可选依赖和 1 个静态插件实现依赖。整体重构未完成，生产 EXE 与配置尚未更新。
