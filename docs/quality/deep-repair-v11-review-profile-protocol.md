# V11 显式审核预算及格式恢复验收

V10 的完整 44 例中，42 例取得正确候选判定，两例分别因 8,192 输出 Token 耗尽及最终 JSON 语法无效失败。全部原报告保留，两例不作为通过，不删除或补抽。

本轮明确声明审核配置为 `deepseek-v4-pro / 32768 Token / high / 240秒`；主生成保持 `deepseek-flash / 768`、工具输出保持 `4096`。私有验收配置通过 `review_model`、`review_max_tokens`、`review_timeout_seconds`、`review_reasoning_effort` 四个字段传入真实 `GroundingSettings`、`GroundingOptions` 及 HTTP 请求。未知字段、非法模型名称、实际 SDK 不支持的预算或强度均明确拒绝，不夹回旧默认值。审核预算、超时、强度和模型进入配置指纹及每次实际调用证据。

未设置上述字段时继续保留原默认配置语义；显式不同审核预算采用 `structured-review-explicit-profile-v11`。原 V8、V9、V10 的不同源码、配置及结果不能与本批混合计分。原 37 个候选、七个完整错误候选、240 个场景、V9 审核 policy、逐气泡 schema 和放行阈值不变。

生产客户端本轮增加有界格式恢复：仅在 HTTP 成功、非空最终内容未通过 JSON 语法校验时，允许同一候选和证据再请求一次格式修复；共享原总截止时间，不自动扩充 Token 或时间预算。不对合法 reject、语义结果、length、timeout 或其他错误重试。它是受测生产行为，不能在实验结束后人工补跑失败用例。

报告按真实 HTTP 尝试保存安全诊断事件，包括 finish_reason 枚举、最终内容字节数、JSON 有效性、格式尝试序号及终止阶段；不保存或读取隐藏推理正文。提供商报告的每次用量均计入成本，即使第一次 JSON 错误而第二次恢复。44 个固定候选可能产生超过 44 次 HTTP 调用，报告必须分别给出候选数、HTTP 尝试数、格式恢复次数和每个实际模型的总用量，不能把候选数冒充请求数。

外层截止时间按有效配置推导，单审核为 250 秒，完整回合为 840 秒；不会被旧实验的 130/480 秒隐性截短。合成假模型及本地 TLS 请求验证显式预算、模型、强度、超时和指纹后，仍需在新统一源码和配置下执行一次完整 44 例，再决定是否运行完整 240 例和预先固定的核心重复场景。
