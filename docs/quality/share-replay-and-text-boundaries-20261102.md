# 分享重排与文字边界审计（2026-11-02）

## 实际重排与原因界限

用户授权将先前未发出总结的一条原生分享重新排队。先核对账号、原消息、来源及不存在已接受的总结回执，再通过正常排空流程暂停 Worker，只将目标队列记录重置为待处理，保留原消息和发送幂等身份，随后恢复。聊天模型为 Flash，思考关闭；没有批量回放其他会话。

本次实际复核的两轮 JSON 均有效，但证据摘录无法在相应证据行中核对，明确返回 `review_support_quote_invalid`。这证明本次重排的具体停发原因，不等于找回了更早一轮未保存的原始模型响应；不能从宿主保存的空 `GroundingVerdict` 推断提供商使用过哪种旧协议。

同时核对到只读分享解析的身份冲突：旧请求键与当前旧算法生成的请求键相同，来源版本、插件包和配置不变，但证据 epoch 已变化。宿主的不可变请求指纹因此与既有任务不同，旧日志将这种冲突归为笼统的解析未完成。

## 修复

- 格式合法但引文不存在时，不把该引文算作支持，也不反复抽取格式结论。宿主拒绝原稿，交由原有的一次编辑流程修复，再独立终核；终核仍有无效引文则停止，保留具体原因。
- JSON 结构、缺字段、未知引用等协议错误仍按既有受控格式恢复处理。没有降低精确来源核验标准。
- 后台异步生成与同步生成共用模型事件投影，避免遗漏异步路径后仍把 HTTP 成功响应标记为重试中。
- 只读 `share.resolve_channels` 的键包含不可变读取快照：参数、来源版本、证据 epoch、原生指纹、插件包及配置版本。相同快照去重；合法的新快照可新建读取任务。未知的同一任务不会盲目重提。
- `ErrRequestConflict` 独立显示为 `share_request_conflict`。不改变微信发送及其他副作用能力的幂等键。获取分享链接前和执行前均重新检查授权。

## 文字发送规则

普通文字的一条气泡对应模型输出的一个 `messages` 元素，程序原样排队，不按段落、标点或字数自动拆开。多条之间的延迟只是发送节奏。

- 去掉“默认建议两条”“最多若干条”等条数引导；旧 `max_bubbles` 字段只为兼容读取保留，不约束或引导模型。
- 去掉旧模型路径的超长静默截断；超限明确失败，不把半段正文发出，也不自动拆条。
- 去掉附件送达后对配文的字符串语义替换，保留模型原文。
- 单次原幂等投递的替换复核只接受一条完整文本；多条时明确拒绝，不擅自换行合并。
- 用户明确本次限制只针对文字。长语音仍保留微信时长限制所需的分段和逐段回执。

## 验证界限

离线测试涵盖无效引文拒绝、一次编辑和独立终核、终核无效绝不发送；读取快照相同去重、参数/配置/epoch 变化隔离与未知任务不重放；原文气泡、配文保持和超长不截断。

实际排队重试会产生正常模型费用，不是零费用模拟。本轮没有额外的批量模型质量测试。程序、离线验证和原生服务器接受分别记录；不能把排队、模型生成或校验通过称为微信已接受，也不能把服务器回执称为手机阅读。
