# 本机能力检查边界

此表只记录本轮实际检查，历史 manifest 的 `validated_capabilities` 不自动视为本次执行成功。全部使用合成资料或只读请求；没有真实微信测试消息。

| 能力 | 本轮检查 | 结果与边界 |
| --- | --- | --- |
| Windows 普通执行 | `TestLiveWindowsIsolatedArgv` 使用实际 LPAC 子进程 | 参数、中文、独立 stderr、只读项目与外部文件隔离通过；不使用管理员 shell 回退 |
| Windows 音乐隔离 | `scripts/test_windows_music.py` 启用项目内 Python | 6 项通过，含账户文件/环境隔离、账户管道、超时、子进程和未授权策略拒绝；不执行真实媒体生成 |
| GPU | 已授权音乐策略下的隔离 Python，256 元素 CUDA 张量计算 | 实际识别 NVIDIA GeForce RTX 3060 Laptop GPU，平方和 5,559,680 通过；没有加载用户声线或训练模型 |
| 桌面控制 | `Build-Desktop.ps1 -Test` | 55 项控制断言与 86 项窗口生命周期断言通过；8 次真实 WinForms/WebView 退出，12 个同时启动的重复实例探测；服务是合成的，测试窗口位于私有桌面 |
| 回复依据界面 | `scripts/deep_repair_ui.cjs` | 1440/375 宽度、明暗主题四组，16 张截图；对象、来源、媒体、关系、版本更正、顶部保存通过，无页面错误和横向溢出 |
| 记忆源修复 | 从在线库取得一致只读副本，在隔离库修复并重复执行 | 7 个已核实冲突被隔离，原文保留；7 条核实来源与 1 条管理员更正建立；930→938 事件，35→36 记忆，重复执行不增长，integrity_check=ok |
| GPT/RVC 命名声线 | 单元与集成合成结果 | 请求、任务、产物、缓存、复用、显式发送和恢复时绑定声线；RVC 检查后端配方及配置哈希；这不等于本轮实际音频试听 |
| 任务与微信投递 | 假原生后端、故障注入和持久队列回归 | 检查撤权、遗忘、重启、幂等键、迟到回执及取消；微信服务器接受和手机播放仍分别记录 |
| 登记能力 | `GET /api/agent/runtime-capabilities` | 只读检查登记、受管路径及资源存在，始终返回 execution_verified=false，不用文件存在冒充推理、训练或交付成功 |

实际配置模型的合成理解测试、Token 与存储性能结果另见 [质量协议](deep-repair-validation.md)。未配置真实 Embeddings 时，词法、向量适配器测试与真实语义向量召回分别报告。

当前一个逻辑任务保存一个命名声线约束。同一请求需要多声线或说话/唱歌两种模型时，使用各自有来源与声线绑定的子任务；不能将默认声线作为另一种指定声线的替代。该约束是任务一致性约束，不是模型能力上限。
