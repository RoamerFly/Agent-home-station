# V10 独立审核模型验收

V8/V9 的报告、固定候选及默认模型实验记录继续保留。V10 不修改审核 policy、逐气泡协议、原 37 个候选、七个完整回归候选、240 个场景或任何放行阈值；仅声明独立审核模型这一配置变量。不同审核模型的结果不能合并计分，也不能测试一个模型后部署另一个模型。

验收私有配置新增明确的 `review_model` 字段。本批声明主生成模型为 `deepseek-flash`，审核模型为 `deepseek-v4-pro`，审核预算仍为 8,192 Token、120 秒、high、thinking 和 JSON。未声明 `review_model` 时保留默认模型协议，由原聊天模型审核；显式声明时使用独立的 `structured-review-explicit-model-v10` 配置协议。两种配置的指纹不同。

V10 另按只读核对的实际运行配置，明确设置 `max_tokens=768`、`tool_max_tokens=4096`；这两个字段均进入真实 `deepseek.New` 和配置指纹，不再沿用旧实验的 1,024。缺省值仍保留旧协议初值，显式超出 SDK 真实边界会报错，不夹值。本地合成 TLS 请求测试已核对普通 Chat 为 flash/768、函数调用为 flash/4096、独立审核为 pro/8192，并确认审核不会修改主客户端。由于本批还对齐了真实生成预算，不能把 V8/V9 与 V10 的差异全部因果归于审核模型本身。

所有验收入口将 `review_model` 写入实际 `companion.GroundingSettings.Model`。公共及嵌套录制包装器原样透传 `deepseek.GroundingOptions.Model`。每次审核记录 `actual_review_model` 和实际审核选项；配置报告的主模型与 `grounding.model` 分开保存。普通生成与质量判分仍使用主模型，不能把它们的用量误报成审核模型调用。

如果私有配置也含 `grounding.model`，它必须与明确的 `review_model` 相同；只写未被消费的嵌套模型或不兼容预算会报错。模型名称验证、预算验证及取消由真实生产接口执行，验收不伪造模型切换，也不降级回普通 Chat。

离线假模型已经验证：通过生产审核入口、包含嵌套来源包装器，实际选项、记录的审核模型、送入审核器的 `review_settings.model` 都为独立模型；主模型保持原值。默认和显式模型的配置摘要不同。真实结果仍须等待新统一生产摘要下的一次 44 例专项、完整 240 例、预先固定的核心重复用例及人工来源审核，不能用离线接线检查代替。
