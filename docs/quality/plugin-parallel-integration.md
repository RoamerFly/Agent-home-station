# 并行插件迁移集成记录

日期：2026-10-31。

本次按管理员要求使用五个子 Agent，分别负责 ASR 宿主、媒体包、依赖生命周期、搜索兼容迁移和主体残留审计；主 Agent 复核集成与验证。没有调用真实模型、搜索站点或微信发送，也没有替换生产程序。

## 集成结果

- 收到微信语音的 ASR 接通实际插件协议：原消息、发送者、会话、遗忘边界、WAV 字节摘要和版本贯穿调用与私有结果恢复。模型/引用/参数更改均拒绝。控制器重启后读取原结果，不重新调用提供商。
- 插件使用独立 ASR 配置，不再依赖旧全局识别开关；未安装账号继续原配置。通用视频/训练音频和本地 ASR 尚未迁移，不能据此开放完整媒体包。
- WAV 当前验证 RIFF/WAVE 头、大小和摘要，不声称完整格式解码。费用只采信宿主实际响应；未适配的百炼用量字段保持未知，仅统计请求数。
- 依赖兼容旧字符串声明并支持版本范围。启动前核对完整依赖图，调用前重新核验；升级为不兼容版本后，在分派进程调用前拒绝。审查修复了空白约束、带正号版本和 `^0.x` 范围的边界错误。
- 最终复核补齐兼容版本替换：控制器保存实际启动时的包摘要、安装/配置修订及描述；依赖变更即要求停止并重启，不因版本仍兼容而向旧进程分派调用。兼容和不兼容替换回归及宿主/运行时测试、vet 通过。
- 旧官方搜索协议迁到显式兼容包，保留现有服务商、密钥门槛、公共回退与诊断行为。该兼容包仍属于迁移遗留，不算从核心彻底移除。
- 增加可执行的主体残留审计和九插件剩余工作清单，不以已有模板或少量测试宣称轻主体完成。

## 验证与边界

实际 Windows LPAC 加合成响应验证 ASR、视觉调用及重启恢复通过。16 项 Python 媒体协议测试、3 项残留审计测试、Go vet、Windows/Linux amd64 管理程序构建及插件管理 JavaScript 语法检查通过。付费模型评测明确跳过。

完整测试首轮其余包通过，admin 累计超过 300 秒时限；堆栈处于合成测试数据库创建。单独 `go test ./internal/admin -count=1 -timeout 600s` 重跑通过，耗时约 202 秒。证据在本轮 `temp/plugin-parallel-validation/go-test.log` 和 `admin-test.log`，构建和日志不提交。

正式媒体包继续 migration-pending，安装器拒绝它；仅测试副本启用，不能描述为现有用户已经获得 ASR 插件功能。该限制继续保护尚未迁移的视频/训练/本地识别入口，避免用户安装半成品后失去旧能力。配置仍要求视觉接口，ASR 单独就绪选择与非入站音频适配均未完成。尚需迁移本地识别、解码、其他服务、配置与运行环境，清理旧路径，完成最终逐页界面与生产迁移验收。
