# 前序八条视频重试修复（2026-11-02）

## 授权与范围

本轮用户授权启动应用、重试指定群内的原请求并修复途中错误，直到完成。范围为引用视频之前、同群分享的八条视频，不含引用视频本身或视频号作者作品列表。实际内容、群成员、原生编号、素材及诊断快照不进入仓库。

沿用 Flash、关闭思考及额外模型复核。离线验证使用合成资料；真实调用仅用于本次已授权任务，不新增泛化模型评测。发送以原请求和原幂等身份核对，已接受或结果未知时不盲目重发。

## 修复

1. 历史分享身份解析错误地要求保存的原文为空，导致身份完全吻合但正文非空的记录也无法读取。查找身份时移除此正文约束；实际读取、版本、会话授权和遗忘校验保留。
2. 旧导入无数据集身份，与当前原生记录发生本地编号碰撞。仅在实际原生消息的账号、会话、服务器编号、发送者、时间均吻合，并确认是未知旧数据集引发的自动冲突时，恢复当前来源。更新来源版本并使旧派生解释失效，保留原文及修订；不解除人工隔离、遗忘、正文冲突或当前数据集内的真实身份冲突。
3. 对只有未绑定旧记录的来源，管理端在 Agent 暂停且原生身份与旧记录时间、人物相符时，可以从实际原生正文另建当前数据集来源。不会用旧包装文字替代原文，也不会越过遗忘屏蔽。
4. 人工隔离覆盖已有自动冲突原因，避免人工决定被旧自动标记掩盖。来源恢复只读原生数据，不执行发送。
5. 原生消息编号可以直接交给 `memory_read`，仅映射当前授权会话和数据集的唯一有效原始事件，不再误查长期条目。重复编号、隔离和遗忘不能绕过校验。
6. 历史阅读进度支持素材读取返回的核实原消息编号，以及原生编号解析后的实际事件编号；补读提示只列出尚未读取的确切来源。不会因为参数使用素材编号而把已完成的读取全部当成未读，也不将少读一条当成全部完成。
7. 桌面增加同一 Windows 会话内的 `--start-services`、`--stop-services`、`--exit-services` 命令，通过现有桌面实例执行正常生命周期操作。命令自身不创建管理窗口；后续停止、更新和重启可自行完成，不需要用户重复操作托盘。

- 来源接口：身份匹配的非空原文、管理鉴权、暂停要求和跨会话拒绝均通过相关回归。

- 桌面控制器 60 项断言、窗口生命周期 86 项断言通过，包括隔离桌面的退出循环与重复实例探测；本机已使用新增正常停止、启动命令更新服务，保留原生登录。

安装程序时保护文件哈希一致；真实来源修复是有意进行的窄范围元数据更正与来源补建，不宣称数据库完全未变化。没有清空真实记忆或复制模型。

## 实际任务记录

八条目标的原生身份均已核实，三条当前来源的误标冲突恢复，一条缺少当前身份的旧记录补建来源。第一次实际重试未发送：七条已有成功的音轨结果，历史读取进度检查未正确完成，回合以独立的未完成原因结束；随后补齐编号读取、素材来源统计和具体补读位置，再继续原请求。

第二次实际重试取得微信接受回执，但内容范围验收未通过：引用锚点混入目标集合，一条真正前序素材被漏掉。这不算任务完成。新增按原发生时间和持久接收序列排列的模型资料包，将“倒序选最近条目”与“正序呈现”分开，保留原分页游标及工具执行配对，排除锚点正文。各条正文按来源归位，不按读取完成先后编号；正文只移动一次，不增加额外模型复核。

排序定向回归覆盖混合时区、同秒序列、乱序工具结果、来源版本重序列化、锚点观察排除和引用内文字不改变检索意图。最终发送结果以本机私有验收记录和微信服务器回执为准。发送回执不等同于用户已在手机阅读，也不证明全部视频已逐帧分析。
