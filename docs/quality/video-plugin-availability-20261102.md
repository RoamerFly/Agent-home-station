# 视频读取与插件中心修复验收（2026-11-02）

## 结论与范围

本轮修复分享读取迁移后的响应兼容回归，完善失败诊断和插件中心入口。没有付费模型调用，没有真实微信测试发送，没有重提既有未知结果任务。真实消息和媒体只在本机受限只读检查，原始响应、图片、签名链接及身份资料留在被忽略的 temp 目录，不进入仓库。

## 故障原因

视频号链路是原消息 → 原生短链 → parse → feed → 解析结果核验 → 媒体观察。当前实际 parse 返回 HTTP 200/code 0，feed 返回 HTTP 201/errCode 0，但新版 feed 不再包含 numeric objectId 和 decodeKey。插件迁移后的 Python 解析器与 Go 宿主校验同时强制要求 objectId，因而拒绝成功响应；旧 SDK 对字段为可选读取。失败发生在媒体观察之前，不能归因于聊天模型、视觉模型或余额。

share-reader 0.1.7 在 objectId 字段完全缺失时，只接受宿主本次 parse 得到的 export 与 feed.sceneInfo.dynamicExportId 精确一致，并延续已经绑定的合法原生对象身份。显式错误或 null 的 objectId、错误或缺失 export、跨来源响应继续拒绝。可变的标题和作者描述不作为身份凭据，不覆盖原始消息。缺失 decodeKey 保持空；媒体仍须通过容器和解码校验。

## 实际只读证据

目标群原生 API 返回 HTTP 200，共 94 条。入站包含文本 16、图片 2、表情 1、普通分享 1、视频号分享 12、引用回复 1。出站及系统记录合计 61 条。两张入站 JPEG（309410/256186 字节）和一张 PNG 表情（78079 字节）通过消息归属绑定的 transfer 读取及文件签名检查。

对实际失败来源绑定后，执行一次 parse 初步检查及一次完整 parse/feed 诊断；没有创建或重放插件任务。另仅读取视频 64 KiB 范围，HTTP 206、video/mp4、ftyp 签名成立。原始响应在本机经修复后的 Python 与 Go 生产解析、结果核验离线重放通过；含真实非空原生标题和作者，无额外网络请求。此证据证明解析兼容和媒体头可读，不等于整段视频解码或模型语义总结完成。

目标群没有入站语音、原生视频和文件样本，这些类型使用合成回归。未对实际图片、声音或视频调用付费识别模型。

## 其他修复

- 表情下载、解码、识别失败改为结构化未完成状态，避免后台误标已观察。
- 插件任务独立保存固定失败阶段：调用、权限复核、结果核验、结果格式；不保存任意异常或插件原文，不改变未知提交不重放规则。
- 分享日志保存经白名单处理的解析阶段、HTTP 状态及数值提供方错误码；后续通用错误不覆盖最先发生的具体原因。
- 左栏增加独立“插件”，插件中心按语音音乐、媒体分享、创作、开发设备、连接分组，展示实际安装/启用/运行状态和配置任务入口；HTTP/MCP 连接直接可达。顶部保存、窄窗口、账号隔离与草稿保护保留。

## 本机更新与恢复

本次无数据库结构迁移。旧任务和配置继续兼容；不会将历史 needs_review 强制改为成功或自动重新提交。当前桌面由私有 stdin 持有服务生命周期，没有独立的安全 Web 热重启 API。更新需先准备并验证程序和插件目录，再通过桌面正常停止服务，确认进程退出后替换程序/插件目录并正常启动。不得强杀进程或同时开启第二个真实数据 Web 实例。

真实登录、配置、消息、模型、生成媒体和任务不参与替换；停止会短暂断开原生连接，但保留登录资料。本轮不新增备份、不导出 Docker、不发布 Release。
