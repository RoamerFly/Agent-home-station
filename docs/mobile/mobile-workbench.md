# 手机探索工作台

当前入口为管理端 **工具 → 设备控制**。本页先说明当前工作台，后文保留 2026-10-26、`0.18.1-device-capture-local` 的设备验收记录。

## 查看她的手机

在设备控制详情里打开「手机观察」，选择已授权的设备并点击「观察一次」。系统通过已安装的设备工具取得一张截图，同时显示上次观察的应用和观察时间。此操作无需调用聊天模型。页面打开和刷新只读取保存的状态。

连接状态旁的时间是最近一次检查时间，画面下的时间是取得该张截图的时间。连接失败时仍可查看此前的画面。旧任务没有可靠的观察时间时，界面显示时间待核对。

「暂停观察」会停止该设备的在途任务并阻止后续设备步骤。「接管设备」同时记录主人正在使用设备。暂停或接管状态会保存，重启后仍生效。点击「恢复观察」后可以重新观察或发起任务；已经取消的任务需要重新发起。

手机工具需要先安装、启用并授权设备。截图和任务按当前管理账号保存。各应用的浏览、评论、制作与发布另按已实现动作及应用授权开放。

## 将设备交给大肥鱼

先在微信账号页绑定大肥鱼身份，再在「手机观察」中选择设备，点击「设为大肥鱼的设备」。这只建立当前账号与设备的明确归属，不会登录应用、复制凭据或启动观察。没有绑定身份的旧账号继续保留原有的管理操作；绑定身份之后，需要为设备建立归属才能开始新的观察或任务。

工作台展示设备桥当前允许的应用包名与动作。它们来自已有设备授权配置，不是另一套权限开关。无法读取授权配置时显示尚未取得授权范围，不能据此认为所有应用都可操作。应用内的评论、发布及其账号授权仍需后续单独接入。

「解除绑定」使原绑定下的任务失效，保留历史截图和任务记录。再次绑定产生新的绑定编号，旧任务不能借此恢复。暂停和接管独立保存，重新绑定不会解除暂停或接管。任务执行每一步仍会核对当前身份、设备归属、应用与动作范围。

更新主体时也需使用兼容的设备工具。若旧工具不能保留任务的身份与绑定信息，宿主拒绝执行，不会降低校验或直接操作设备。

## 已交付链路

微信接收、群规则和发送仍由现有后台处理。可信用户可让角色调用 `device_task_start` 创建独立的设备任务；手机执行模型只获得当前任务、当前真实屏幕、界面节点和最近四个检查点，通过原生 function call 选择下一步。每步之后重新截图核对。模型和视觉服务复用已有服务商配置及用量记录，没有为每个群另建人格或完整聊天历史。

管理端可登记允许的设备 ID、启停执行端、设置动作范围与任务预算、查看实际 ADB 在线状态、任务、最近截图、检查点、失败原因，以及取消单个或全部任务。表单轮询不覆盖输入，任务行原位更新；切换页面按用户要求放弃未保存更改，不弹确认。配置含 revision，过期保存会被拒绝。

角色侧沿用“权限与服务器”的可信用户和授权会话，不再重复配置身份白名单。预演和自主冲浪不能取得设备动作工具。管理端手动任务独立授权；当前本机仅开放独立实验设备的观察权限。动作须同时通过后台动作设置和桥接私有配置中的设备/应用/动作限制。撤销可信身份或会话后，执行前再次校验。全局暂停也会取消正在运行的设备任务。

手机任务与微信接收循环分开运行，每台设备由一个后台任务占用，其余请求按接收先后进入持久队列，每台最多8个在途任务。队列中可取消指定请求；全停会先持久取消整批任务，避免前一项结束时启动刚要取消的下一项。任务时限从实际开始执行时计算。桥接层另有跨进程单步租约及动作幂等账本。单后台实例内完整任务独占已实现；不声称多个独立管理服务能共享完整任务租约。重启将未完成任务改为“需要检查”，不自动重放点击；需要继续时提交新目标，第一步重新观察。取消不能撤销已经提交给 ADB 的动作。连接不确定停止并保留事实。

来自微信的任务完成后，以既有持久会话续办机制把真实结果交给角色复核，沿用发送权限、节奏、引用和回执。取消后的任务不再唤醒会话。观察记忆关联原账号/会话、设备任务、设备和截图 ID，并明确是本地工具证据，不能伪装为已经发出的消息或媒体。管理端创建的实验任务没有微信收件人，不会自动发送到群。

## 执行端配置

使用 [mobile-bridge.md](mobile-bridge.md) 和 `examples/mobile-bridge.json` 配置设备桥私有文件。页面填写 stdio 桥接命令、参数数组与设备别名；不填账号 Cookie、API Key 或 ADB 私钥。命令以管理端用户权限运行，只使用本人信任的程序。

Linux 服务可直接调用 Linux Python/ADB；本机验证使用 WSL 管理端 → Windows Python → Windows ADB → 独立 Android API31 模拟器。真机替换只需在桥接私有文件登记明确序列号和应用，不需要更改微信消息协议。具体平台应用安装、登录和播放兼容性需另验收。

- 已运行的管理端调用真实视觉/决策模型，只读设置页，正确描述实际可见栏目，0 次设备动作。
- 第二个真实模型任务先回桌面，再打开系统设置，2 次动作后以新画面确认。没有修改设置、登录或安装应用。测试后恢复仅观察权限。
- 网页读取并展示上述真实截图；375/768/1440 宽度没有横向溢出，任务轮询保持滚动位置，编辑内容不会被轮询覆盖，导航放弃未保存草稿；没有页面脚本异常。
- Go 测试覆盖动作前后观察、取消、设备占用、幂等启动、断线不重放、重启转检查、权限撤销、错误 PNG、跨任务截图访问、登录阻塞状态、API 身份/CSRF 和旧版配置拒绝。Python 测试另覆盖 ADB 执行契约。

## 尚未证明的能力

当前设备只允许桌面和设置等实验应用，没有登录抖音、快手或微信。手机执行端已经具备真实截图、节点与单步操作循环，但新增2–12秒无音轨短录屏、分块回传/哈希核对、真实抽帧理解和受保护回放；也支持允许浏览器打开登记域名的HTTPS公开链接。尚未交付 App 视频全程观看、系统音轨采集、自动下载原文件或自动接受协议/验证码。中文输入仍缺输入法适配。点赞、关注、评论、发布、支付、账号和系统配置变更均没有业务授权工具；模型遇到这类步骤标为需要本人处理，不标为成功。

分享读取优先走现有 [真实内容观察](../media/share-observation.md)。网站要求登录、App 或访问受限时记录具体失败，不按标题假装已看过；公开链接入口只允许明确登记的浏览器包名和域名，校验首个地址的DNS为公网，并引用shell参数；这是初始URL边界，浏览器重定向和网页自身资源请求仍按浏览器机制执行，不构成完整网络沙箱。本版本不保证任意分享链接都能取得内容，也不会自动把受限分享转成点击未知应用的任务。目标应用的授权接入、播放观察和媒体回传属于后续扩展验收。


## 短录屏与回传

独立“短录屏观察”权限，同时受桥接文件 capture 动作限制。每次录制2–12秒，固定480×800、256kbps、最多2MiB。原文件由设备桥缓存，管理端按8KiB分块读取，逐块核对偏移、长度与结束标记，并核对整文件SHA-256；设备、任务请求键和素材ID必须一致。没有任意设备文件读取入口。录屏通过已认证管理端地址回放，关联来源会话和可用素材；绝不标为原视频或带有音轨。

Android静止页面可能只输出时间戳为零的单帧、没有时长。此时只提取实际第一帧并标明“无可验证时长”，不拿请求的几秒钟冒充实际观看覆盖。动态页面的被动录屏允许画面变化；点击、滑动等操作仍需模型观察与动作前的新观察一致。

本机已取得静止设置页的真实MP4，完成跨Windows/WSL分块回传与实际单帧视觉理解。公网浏览测试进入自带WebView并实际显示DNS错误，模型选择阻塞而非声称已观看；这不能算公网视频播放通过。测试数据和页面证据仍只留在私有忽略目录。

动态场景的真实验证也已通过：在自带WebView中显示明确标注的本地合成动画，真实模型只录制一次指定4秒（媒体实际4.45秒），成功解出5帧并描述变化。已把具体采样时刻和最后采样失败事实传给模型。这证明设备录屏/传输/解码/视觉链路，不能当作互联网视频已打开。
