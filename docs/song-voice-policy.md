# 歌曲默认声线与本地桥接恢复

做歌和翻唱继续经过 YuE。默认参数为 `singing_voice=native`、`vocal_gender=female`，风格中明确女声条件；用户明确要求男声时可使用 `male`。这是生成条件，音色和演唱质量仍须试听。

已保存角色 RVC 模型不代表每首歌都使用它。仅用户明确要求机器人自己的专用声线或 RVC 换声时，模型才可提出 `singing_voice=character`，并由独立的短上下文模型核对当前用户意图；无法确认时拒绝该换声调用，让模型改回原生 YuE。普通“你唱一首”、翻唱、人设和以前的默认配置不构成这次换声要求。桥接默认不读取、不要求 RVC 资源，新任务将实际声线选择写进私有配方，原任务配方保留不变。

Windows 桥接任务文件由 UTF-8 写入，此前启动时按系统默认 GBK 读取，含中文的新任务会导致 `UnicodeDecodeError`，端口 6188 不再监听。改用 JSON 字节解码读取，保留原任务和音频，重启不重新提交已有生成。桥接版本升至 4，网页端发现仍配置自动换声的旧桥接时拒绝默默使用它。

仅给主题的“唱下班的歌”“适合下班听的歌”可以按主题创作，不擅自认定为同名已有歌曲而持续搜索。明确命名的已有歌曲仍按参考翻唱处理，必须取得真实参考音频及歌词依据，不用新词冒充原曲。补办使用原收件消息的会话、发送者、引用和确定性任务 ID；已存在生成操作先查原任务，不盲目重复提交。

验证覆盖默认原生女声的真实 HTTP 参数、已配置但损坏的 RVC 资源不会影响原生任务、明确换声意图的允许/拒绝路径、原有参考音频/歌词/种子工作流。实际生成与微信接受回执单独核实，不把工具提交当作已经收到或试听合格。
