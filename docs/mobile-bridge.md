# 手机执行端：ADB stdio MCP

状态：持续目标的执行端基础阶段，尚未接入网页设备管理或角色自主任务。

`scripts/mobile_bridge.py` 只用 Python 标准库，调用已有 Android SDK 的 ADB，不安装设备应用、获取 root、不创建公网监听。模拟器与真机复用同一工具协议；每台设备必须由管理员配置明确的序列号、允许应用和动作。示例见 `examples/mobile-bridge.json`，默认不启用设备。

启动方式：

```text
python scripts/mobile_bridge.py --config <private-config.json> --storage <private-mobile-storage>
```

可作为 stdio MCP 接入，提供 `devices`、`observe`、`act` 三个工具。建议由管理后台的专用设备层调用，不直接把全部手机动作无差别提供给所有群友。

## 已实现

- 列出已登记设备的实际 ADB 状态。
- 校验前台应用后获取实际截图、屏幕尺寸与最多100个界面节点，保留快照ID和哈希。密码节点文字被替换为占位，截图仍是当前实际页面，需按本地私有数据处理。
- 独立授权的启动允许应用、点击、滑动、返回、回桌面和有限ASCII输入；没有任意ADB shell或任意命令入口。
- 每个动作要求45秒内、同一设备的观察；应用或控件变化要求重新观察。播放画面改变但控件相同可以执行下一步。
- SQLite租约让多个MCP进程不能同时占用同一设备。动作提交前保存唯一请求键与参数哈希；回执丢失保持unknown，不自动重放。相同键但不同参数被拒绝。
- ADB命令、截图、XML、节点、输入、坐标、超时和MCP响应均有界。截图超过650KiB目前明确失败，后续可接入管理员配置的缩放编码器；不能声称支持任意分辨率。
- 观察文件保留最多约200条或7天，保留最近两分钟快照供在途任务使用。仅清理本存储目录中生成的快照，不清理用户设备、配置或任务账本。

动作返回submitted只表示已提交ADB操作，随后必须重新观察确认。它不代表已完成页面任务，更不代表观看了视频、拿到文件或微信送达。

## 当前真实验证

2026-10-26，在本机新建的隔离API31模拟器，保留原Pixel AVD不变。取得480×800桌面与设置页截图、实际控件；执行一次启动系统设置操作并用新的前台应用/控件观察确认。Windows Go→Python→ADB和WSL Linux Go→Windows Python→ADB的MCP只读链路均通过。没有登录任何新应用，没有向微信发送消息。

运行文件、设备数据和截图仅保存在忽略目录。环境曾遇到旧模拟器无法读取含中文用户目录的ADB密钥：通过独立测试环境目录解决，未修改系统虚拟化、证书、代理或原用户AVD。

## 后续阶段

专用后台设备配置与任务API、模型按原生function_call选择动作、按设备的完整任务独占/取消、网页观察与状态、素材回传及来源记忆，以及浏览器/应用接管后的真实媒体读取仍需交付。当前桥接的短租约只覆盖单次观察或动作，不能当作完整任务调度。

中文输入尚未接入输入法；支付、发布、关注等业务动作没有专用授权模型。不要将系统设置页测试描述为抖音自主浏览已验收。
