# 会话与记忆工作区

版本：`0.28.0-node-workbench-local`。节点工作台设计与取舍参见 [管理后台优化路径](node-workbench.md)。

## 使用方式

侧栏保留工作台、会话、执行回合、角色、能力、系统六个入口。会话首页每行是一个群聊或私信，按最近活动排序。点击会话打开大弹窗；消息按新到旧排列，集中查看消息、上下文摘要和备注。执行步骤在独立的“执行回合”中查看，避免聊天内容被技术记录打断。备注、原始事件、历史消息、归档使用弹窗，不撑开主列表。

系统运行事件在“执行回合”的更多筛选中查看。原来的 `#overview`、`#memory`、`#catalog`、`#logs` 等地址仍有效；已有执行回合归并和回执证据不会删除。

## 压缩修复

0.28 进一步修复实际模型请求：普通聊天的 768 Token 输出上限会截断结构化摘要。压缩现在独立使用 4096 Token 输出预算，并请求 JSON；不改变普通聊天输出上限。兼容服务不支持 JSON 模式时可退回普通文本请求；摘要仍必须通过结构校验，不能保存半截结果。

如果模型返回的摘要结构不合要求，尝试一次格式修复；如果压缩期间旧消息的实际内容发生变化，重新读取后尝试一次。只更新昵称这类展示信息不再造成误冲突。存储仍按快照校验后原子写入，原始消息始终保留。网页和执行记录会区分输出截断、格式无效、网络/模型失败、并发冲突与存储/配置问题，而不是统一提示“压缩未保存”。

旧网页复用了一个禁用按钮；A 会话压缩期间，切换 B 会话仍沿用 A 的按钮状态，A 完成后还会重新加载当前选中的 B。压缩摘要实际已经保存，但记忆 GET 没有返回它，网页一直显示旧原文。

现在每个会话独立维护压缩请求、状态和结果。A 完成只更新 A；不同会话可同时压缩。同一会话的重复压缩由共享 Store 的短锁登记拒绝，不会持锁等待模型，也不限制其他会话。

记忆 GET 默认返回摘要、压缩覆盖数、展示边界以及该次快照之后新增的消息。压缩前的记录通过单独的只读 history 接口，点击后才分页加载；页内按新到旧排列，分页校验版本并核验账号范围。

## 展示与模型上下文不同

压缩器仍按原策略增量摘要，并保留必要的近期原文供模型理解，不会把尚未摘要的近期消息丢掉。`summary_boundary` 记录压缩请求所使用的消息快照长度，仅用于把压缩前聊天在网页里收起；`compressed_count` 仍是模型已摘要的前缀边界。

因此弹窗会明确显示“已压缩 X 条，另有 Y 条仍保留为近期上下文”。压缩期间新收到的消息在快照之后，继续正常显示，即使它带的是旧时间。旧摘要缺少快照长度时使用已有摘要时间兼容投影，不删除或重写历史正文。按时间过期时根据各条原来的位置调整边界，避免迟到的旧消息过期后错误移动摘要前缀。

## 验证

- 合成模型同时进入两个会话的压缩；同会话冲突拒绝；保留模型近期原文；迟到消息和过期边界；通过针对性 race 检查。
- HTTP 默认响应不包含收起的原文；显式历史接口分页、新到旧、版本冲突与跨账号隔离。
- Playwright 合成会话检查摘要展示、历史按需读取、大弹窗及焦点返回、两个并行请求、A 完成不覆盖 B、压缩后收起原文和窄屏适配。
- 全站浅色/深色、375/768/1440 宽度回归；不发送真实微信验证消息。
- 在本机私有临时副本中，使用已配置模型复现 768 Token 导致的 `model_output_token_limit`，修复后的相同路径压缩成功；不写入活跃群聊的记忆，不将副本或正文提交 Git。该实测补充合成回归，不替代合成测试。

原始消息、只读归档、角色与权限配置、原生微信登录都保留。不生成 Docker 镜像。
