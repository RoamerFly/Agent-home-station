# 工具迁移剩余工作清单

本清单由 `python scripts/audit_plugin_boundaries.py` 的范围约束而来，不是
完成声明。每一项必须先迁移运行时、配置、来源/权限、任务恢复和结果验证，
再删掉主体中的同类实现。测试、账号数据、模型、运行环境及待删除目录不参与扫描。

## 主体保留范围

主体保留微信登录、收发与回执、账号与认证、记忆与上下文、素材身份与投递、
媒体编码/暂存和工具宿主。`发送已有音频` 与 `生成音频` 的边界保持分开。

## 当前收尾状态

以下只列仍在生产调用链中执行主体专用业务的项目；不把模板、核心授权/素材适配或尚未执行的真实环境验收当作迁移实现缺口。

最后发现的直接调用已删除：视频精读帧分析通过已安装 `media-understanding` 的 `media.observe` 执行，缺包时明确失败；音轨同样走媒体工具。手机队列决策已迁入 `mobile-control` 0.6.0 的纯状态转换，宿主只保存和核对执行事实、权限与持久状态。旧设备实现仅供兼容回归，不进入生产命令依赖闭包。

音乐协议协商、恢复配方和生成风格已进入 music 0.5.0，专用 repair 验收已退出生产路由。公开视频读取和精读均经安装包；旧分享解析、旧手机控制与旧语音 SDK 均不在生产依赖图内。旧语音/视频号设置没有第二写入口，损坏旧语音文件只影响显式迁移预览。

Windows 与 Linux 的 `--require-light` 现在通过：它核对真实编译图、已知直连服务执行回归、完整九类声明、文件哈希、能力及权限契约。名称命中仍保留作审查线索，不作为业务残留数量；`agenthost` 是明确保留的隔离/执行权威。静态审计不能代替模型、提供商、设备或投递验证，完整证据见 `../quality/plugin-completion-20261101.md`。

## 本批已完成、但不应误报为阻塞

- `external-tools` 0.6.0 的 `external.http_request`、`external.job_request`、`external.poll_request`、`external.mcp_request` 已由安装控制器、`wechat/external_request` / `wechat/external_mcp` 服务白名单和 `internal/plugins/bridge.go` 接通。旧 `Runtime.Call`、`invoke`、循环 `poll` 及主体输出解释已删除；宿主保存来源、密钥、原始参数、初始响应和持久状态。其仍需真实管理员配置/账号迁移，但没有待迁移的外部 HTTP/MCP 执行业务链。
- `share-reader`：`resolveReceivedChannels` 在已安装时调用 `share.resolve_channels`；未安装时现明确返回 `share_plugin_migration_required`，不再复活旧 resolver、对象桥接或凭据网络请求。卡片元数据和已保存绑定仅作只读归档/界面数据。
- `speech`、`music` 与本地 YuE/RVC 请求均经已安装包的受控调用；主体保留声线/来源约束、结果校验、素材暂存和微信投递。训练与 SDK 已随相应受管包/资源登记迁出，不以同名主体适配文件推定仍有直连推理。
- `visual-generation` 当前只有未发现的模板/规划边界，不是可调用的生产实现；在具备 ready 包、持久任务和结果校验前不能宣传该能力，但它不阻塞已迁出的能力交付。
- 物理设备、Linux 受控进程、真实 GPU/CUDA、真实模型、真实生成与微信投递在本批均未操作或验收；这是必须单列的真实环境证据边界，不是静态迁移实现缺口。
- 训练/GPU：受管训练入口、包哈希、隔离授权和合成回归存在；本批没有运行真实 GPU、CUDA 训练、第三方模型或听感验收。它只阻塞交付“训练/推理效果”能力，不是 external-tools 迁移缺口。
- SDK：本地 ASR/音乐等 SDK 的登记、完整性和合成边界属于安装资源/运行环境工作；未在本批重新安装或用真实模型验收，不能据静态代码宣称目标平台 SDK 可用。
- SQLite：工具配置和持久任务的 SQLite 记录是宿主权威状态，不是应迁入隔离工具的业务实现；迁移时仍需对真实管理员配置做一次预演。
- 工作流：已安装包可保存配方、参数和恢复语义；本批未提交真实生成工作流、未操作物理设备、未发送微信，故不构成模型质量、费用、手机播放或设备通过证据。

## 每项服务的删除门槛

1. 正式包状态为 `ready`，可发现能力只包含已完整实现的能力。
2. 配置、密钥、旧配置迁移和权限界面有单一权威存储。
3. 受控来源/素材、异步任务、取消、恢复、结果校验和实际费用语义通过合成测试。
4. 已安装账号不可回退旧实现；未安装账号的兼容路径和迁移预演有明确期限。
5. `audit_plugin_boundaries.py` 中该能力的主体实现引用归零，或有记录的核心保留豁免。
6. 删除旧路由、设置页、提示词和无引用脚本后，执行完整回归和 Windows/Linux 构建。

## 验收命令

```powershell
python scripts/audit_plugin_boundaries.py
python scripts/audit_plugin_boundaries.py --require-light
```

第一条输出名称线索与实际阻断项；第二条在真实边界和声明校验全部通过时返回成功。隐藏且未绑定运行时的生成模板允许保留，但不能据此声称有九类可执行能力；八类已实现能力不得通过隐藏或降级为模板绕过检查。注入回归验证旧依赖、直连服务、缺包/缺能力、非法权限、摘要错误和不安全模板都会失败。

审计还会列出 `static_plugin_implementation_dependencies`：主体若静态引用 `wechat-bot/plugins/<工具>/...` 的 Go 实现，同样阻止轻主体放行。仅提供声明的 `wechat-bot/plugins` 根 catalog 不属于实现依赖。
