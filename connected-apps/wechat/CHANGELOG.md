# 变更记录

## 0.1.9

- 独立 Windows 桌面按连接和会话单独授权取得入站图片、语音、视频与文件原件。宿主核验来源、字节数与 SHA-256；Agent 获得素材编号和校验信息。

## 0.1.8

- 主人可从隔离的旧宿主快照预演并导入账号的回复范围建议及只读发送记录。目标工作器保持暂停，旧任务不会自动补发。

## 0.1.7

- 独立桌面为指定微信连接保存文字回复范围，可独立启动或暂停 Agent，并用原幂等键核对回执。
- 工作循环请求限定在所属账号和已核验的原生服务。正式账号数据的兼容启用另行验证。

## 0.1.6

- Windows 独立桌面支持主人登记新账号及发起扫码。状态和二维码绑定到原连接及原操作，重复请求沿用原编号。
- 已登录或正在恢复的账号保留原会话。登记和扫码不启动账号 Agent 工作循环。

## 0.1.5

- 独立 Windows 桌面可选启动随包原生进程，验证归属后向主人只读展示该实例的账号和登录状态。
- 源码安装、原生服务可用及账号工作进程分别记录。旧账号数据仍留在原宿主。

## 0.1.4

- 迁入微信分享卡片、来源选择、视频号读取回退及短链、解析、回执内容核验。
- 自动观察和按消息编号精读共用同一来源检查；旧卡的消息或媒体身份不符时拒绝读取。
- 发布者描述单独标记。短链解析只取得定位资料，媒体观察仍由宿主核实。

## 0.1.3

- 迁入微信原附件取得、文件转发、媒体投递及状态、操作查询编排。
- 继续使用原投递编号、分段幂等键及回执。退避结束后重查原任务、来源和授权，再续办该任务。
- 原键恢复的文字回执只证明发送状态。再次查询时保留正文未经核验的标记。
- 仍通过旧宿主接入原生运行时，独立连接界面继续分阶迁移。

## 0.1.2

- 迁入文字发送、通用账号动作和专用撤回的协议编排。
- 宿主保持原幂等键、授权版本、任务取消与实际回执入账，并核对应用调用未改变原请求。
- 媒体发送、原生运行时与独立连接界面继续分阶迁移。

## 0.1.1

- 迁入微信工具声明、目录读取与来源投影；读取后重新核对宿主授权。
- 原发送、取消与回执保持宿主管理，独立运行组件仍待迁移。

## 0.1.0

建立微信发行源、迁移应用身份构造、提供家目录安装入口。
