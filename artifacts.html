实战：附件转 PDF 与私人声线

把群里一张图重建为 Word，只发送 PDF

准备。 微信文件收发随主体提供。先安装并启用文档工坊，给会话开放文件发送，确认本机文档运行环境可用。Windows 的可选运行包需要项目内 Python 文档依赖、可嵌入中文字体；要识别中文图片还需要 Tesseract 和中文语言数据。制作新便携包时可以给构建脚本传入 -DocumentPythonPackagesDirectory、-DocumentFontsDirectory 和 -DocumentTesseractDirectory。这些参数指向已准备好的依赖目录。

操作。 在授权测试群发送一张清晰的表格图片。引用该图片说：“按图片做成可编辑 Word，保留标题和表格，只把 PDF 发到这个群。” 如果仅需原图封装为 PDF，可以直接说明“保持原图，不重排”。两种请求产生的成品不同。

验收。 在执行回合中依次核对以下结果。

  1. 原件已取得。 来源属于当前账号和目标群，素材有自己的编号。看到缩略图还不足以证明已拿到可加工的原件。
  2. 识别结果可用。 核对关键列、数字和日期。OCR 会把形近字混淆；如果金额所在格无法辨认，引用图片指出“第二行金额为 128.50”，再继续生成。
  3. Word 可以编辑。 标题和正文是文字，表格是单元格。导出器从这份 DOCX 生成 PDF，支持标题、段落、简单表格及受支持的嵌图编码。正式 Windows 沙箱使用 Python 离线导出，不弹出办公软件确认窗口。复杂排版、加密文件及需要整页渲染的扫描 PDF 以实际能力提示为准。
  4. 只交付指定格式。 Word 和 PDF 分别有素材编号。查看发往原群的附件是否为 PDF、投递是否已被微信接受。需要修改时，引用任务说“把标题改为 20 磅，再发 PDF”；要编辑源文件时再要求发送 Word。

已有 DOCX 可直接作为导出输入。已有文字型 PDF 可检查页数和提取文本。收到“文件尚未取得”先查下载；收到“缺少文档运行环境”先查插件依赖。这两种故障的解决方法不同。文档工坊的格式与依赖

用自己的录音建立私人说话声线

  1. 配置身份和运行环境。 在当前账号配置中核对主人的微信身份及可用会话。语音插件需安装并启用，注册本机 GPT-SoVITS 项目、受管 Python 和通过校验的公共基座；正式训练还需要可用的训练依赖与 GPU。仅有云端 TTS 密钥不能启动本机训练。
  2. 明确指定录音。 主人发送自己的微信语音，再引用原语音说“这是我自己的单人录音，用它建立名为‘朗读’的声线，先私聊给我试听”。普通语音的转写不会自动成为训练样本。若实际混有别人说话或背景噪声，换一段干净录音。
  3. 先试听新句。 让它念一句样本中没有的话。核对来源录音、参考文本和实际生成的试听文件，并在私聊中确认是否收到。此时的结果是参考声线试听。
  4. 需要正式训练时再发起。 明确说“用选好的样本正式训练‘朗读’的新版本”。保留任务编号；查询同一任务的阶段、设备、样本和权重。只有出现新权重且这些权重成功合成试听，才把该版本视为训练完成。
  5. 检查复用。 新开一轮对话，指定该声线念另一段短文，回听是否匹配。要唱歌时单独检查音乐插件里的唱歌模型；同名说话声线不会自动产生 RVC 唱歌权重。
