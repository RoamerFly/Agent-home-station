# 可安装的 Python MCP stdio 示例

这个目录本身是一个可导入插件包：它声明一个同步、只读的 `echo` 能力。它用于验证后装插件的安装、授权、启动、发现、调用和同一请求键的恢复；不会联网、写入工作区、创建后台任务或发送微信消息。

## 安装前检查

1. 复制整个目录到一个新目录；不要只复制 `main.py`。
2. 若修改任何文件，必须重新计算 `plugin.json` 的 `files` 中对应 SHA-256。未索引文件、符号链接和摘要不匹配都会被宿主拒绝。
3. 如需改插件 ID、版本、权限、能力或运行入口，先同步改声明和文档，再重新计算所有文件摘要。
4. 在插件中心导入目录，核对摘要、授予声明的最小权限、完成配置（本示例无配置）并启用。安装和启用不等于获得微信发送权。

## 当前宿主支持范围

- `mcp-stdio`：已支持。Windows 通过宿主已配置的受管 LPAC broker 隔离运行；Linux 需要 `bwrap`。该 broker 是宿主部署条件，不是本插件的 Python 依赖。
- 通用发现/调用：仅同步且无写入副作用的已就绪能力进入动态工具目录；`side_effect: "read"` 用于读取，未声明副作用可表示纯计算。插件返回的 JSON 仍是不可信结果，宿主不会据此直接发送微信或登记素材。
- 后台任务、写入、设备、工作区、媒体成品和发送：必须由对应的宿主适配器实现来源、取消和交付校验；不能仅把 capability 改成 `async` 或 `write`。
- `mcp-http` 和 `http-adapter` 目前只可被包格式校验，通用本地执行器尚不能调用，不能标成可用。

`main.py` 还保留离线 MCP 的 `health`、`job_*` 协议示例，方便开发调试；它们没有写入 `capabilities.json`，不会由动态宿主暴露。
