# 媒体理解

0.2.0 提供独立 Python MCP stdio 的三项就绪能力：**入站图片/贴纸观察**、**入站语音转写**与**WAV 音频内容观察**。工具负责请求构造和结果解析；宿主负责账号、会话、来源版本、素材字节和发送边界，并通过 `wechat/model_request` 或受控本地 ASR 代理执行。密钥不进入工具进程。

支持 OpenAI 兼容视觉接口及现有 DeepSeek 思考协议。默认输出额度可配置，调用可显式设置输出额度、时间和思考选项；不支持的思考协议明确报错。输出区分完整与截断，保留来源、仅所提供图片的覆盖范围、提供商实际 Token 与未知用量；隐藏推理和工具调用不作为观察返回。

语音识别已声明独立的可选接口、密钥与模型。未填写这些字段时，视觉观察配置和调用不受影响；选择“远程接口”后，`media.transcribe` 只能通过宿主的 `transcription` 模型路由使用该密钥。选择“本地识别”后，必须设置 `local_asr_profile_id`，且它必须与宿主签发的已登记 profile 完全一致；工具只发送来源绑定的 WAV 引用给 `wechat/local_transcription`，不读取或接收路径、字节、模型、解释器或命令参数。宿主在隔离环境中以本包固定 `local_asr.py` 和已登记运行环境执行。缺少或不匹配 profile 时明确不可用，绝不回退到其他声线、模型或远程接口。

视觉、远程 ASR 与本地 ASR 的配置互不依赖：只配视觉可以保存并使用视觉能力；只配远程 ASR 或登记本地 ASR 可以保存并使用转写能力。未配的能力在宿主发现阶段显示为不可用，而不是要求补齐无关的密钥或地址。

`media.listen` 使用独立的 `audio_review_endpoint`、宿主持有的 `audio_review_key` 与 `audio_review_model`。它仅接受宿主绑定的 WAV 引用和明确观察提示，并通过 `audio-review` 路由请求已规范化的流式模型结果。结果仅表示模型对给定音频的观察，可能不完整；它不是人工试听、声纹识别、说话人身份确认或微信投递。工具不下载音频、不接收原始字节、路径或声线 ID。

当前就绪范围严格限定为宿主已核验的入站图片、贴纸、语音与来源绑定的 WAV 音频。视频号/视频分享的自动处理，以及视频音轨的分页读取，仍沿用主体的自动处理与 `video_inspect` 续读路径；本包不直接解码视频，也不把视频帧或音轨当作新的通用输入能力。模型质量、服务可用性和手机端投递仍需分别验证。

离线协议测试：`python -B -m unittest discover -s plugins/media-understanding/tests`。不得使用生产配置运行付费测试。

范围：入站图片/贴纸观察与入站语音转写。它不发送微信，不读取其他账号，不直接联网或执行任意命令。

宿主协议见 ../../docs/plugins/PROTOCOL.md。不得绕过宿主直接发送微信；生成结果与投递回执分别记录。
