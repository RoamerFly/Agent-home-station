# 变更

## 0.5.0（单进程原生协议）

- 原生五项操作在隔离 main.py 内运行包内高层逻辑，通过固定 wechat/device_io 请求宿主 IO，删除整单 receipt 中转和第二个 native 进程登记入口。
- 保留宿主原物理锁、原 SQLite 操作账本和 unknown 不重放语义；未确认清理继续保留锁。
- 大截图和录屏采用宿主私有引用与 SHA-256，素材支持明确 offset / bytes 分页，超资源上限报错而不截断。
- 单进程 Windows LPAC 配合合成硬件协议验证不代表真实设备验收；连接登记、队列和录屏分析尚在宿主。

## 0.4.0（声明式管理页）

- 将管理页明确为宿主渲染的执行设置、设备任务、任务素材和状态说明四个区域。
- 设置保留在唯一宿主配置仓库；只声明固定受控操作，不暴露 bridge 任意命令、ADB 参数、脚本或 URL。

## 0.3.1（共享 ADB 生命周期）

- 兼容 bridge 固定连接宿主拥有的 `127.0.0.1:5037`，拒绝其它 host/port 及 ADB 环境变量覆盖。
- 每次 ADB 调用前以只读 `host:version` 探测要求协议 41（响应 `0029`）；端点缺失、坏握手或版本不符不启动 ADB 客户端。
- 端点失败直接返回受控不可用状态，不自动启动、停止或回退到默认 ADB server。
- 宿主状态迁移采用私有 SQLite 的只读核验、差异记录和 CAS；不双写旧 JSON，不搬迁截图、录屏或原有操作 ledger。

## 0.3.0（受控设备代理已接通）

- 添加五项来源绑定设备操作门面；每次请求只允许一次宿主 `wechat/device_request` 回调。
- 门面只保留安全回执元数据，原始截图、录屏和分块 bytes 保持宿主私有。
- 五项设备能力通过宿主受控代理开放；不因存在门面而允许插件自行访问 ADB、网络、设备文件或扩张权限。旧队列、配置和 UI 的完整迁移及真实设备验收仍未完成。

## 0.2.0（分阶段就绪）

- 新增隔离 Python MCP planner，仅开放无副作用的 `device.plan`。
- 模型请求由宿主当前聊天模型代理；输入、来源版本和动作建议均保持来源绑定，格式错误最多修复一次。
- 包权限收敛为 `model.invoke`；设备观察、动作、录屏和现有 broker/队列仍未迁入可用插件能力。

## 0.1.1（仍在迁移）

- 整理插件自有 ADB 桥接源码与可注入的动作规划层，保留固定旧脚本入口。
- 主体设备服务改为惰性加载；设备存储故障不再阻止聊天管理端启动。
