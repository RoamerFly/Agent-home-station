# 迁移

0.2.0 已将动作规划迁入独立 Python MCP 进程。宿主只向它交付 `task_id`、`observation_id`、不透明的 `source_version`、受限任务摘要、UI 节点摘要和允许动作；路径、PNG、账号、设备序列号与 ADB 参数都不是协议字段。

规划进程先请求一次宿主绑定的屏幕描述，随后最多请求两次原生 `device_step` 格式输出。格式或本地动作校验失败时只增加一次修复提示；提供方错误直接返回。结果带回原任务、观察和来源版本，宿主仍须独立复核后才能交给设备 broker。

旧 Go planner 已删除，没有静态编译或自动回退路径。新建任务须先安装并启用规划插件；模型设置和费用继续沿用宿主唯一配置，不复制密钥。已有任务仍可查看、取消和停止，未知结果不因迁移而重放。

桥接、设备队列和录屏素材链路暂时仍由主体的兼容服务负责，整体迁移尚未完成。官方规划包已通过 Windows 隔离进程与本地假模型契约测试；这不代表真实设备或真实模型质量验收。尚未执行生产账号迁移或更新生产程序，后续实际切换仍需隔离预演。

0.3.0 添加 `device.list`、`device.observe`、`device.act`、`device.record` 与 `device.read_artifact` 的隔离门面，并接入宿主受控代理。它们只接受来源版本与闭合请求对象，一次转交给宿主设备代理，再原样返回受限回执元数据；门面不导入旧 bridge、不读取 ADB、文件、网络或截图/录屏 bytes。宿主独立完成授权、账本和回执比对；旧队列、配置和 UI 尚未完整迁出，本轮也未验证真实设备或自动迁移旧账本。
