# 运行时

`main.py` 与 `planner.py` 是当前唯一就绪的 MCP 运行时：只规划下一步，不操作设备。它们通过宿主绑定的 `wechat/model_request` 调用当前聊天模型，且不取得本机私有路径、原始 PNG、账号凭据或设备连接资料。逻辑账号/会话等审计身份仍按宿主协议通过调用元数据绑定。

`bridge.py` 是保留的 Android ADB 实现：只接受已登记设备和有限动作，保留观察快照核验、请求键去重、未知回执不重放以及受限录屏素材读取。它不提供任意命令、任意路径、设备安装、登录、代理或网络回退，也不由 `main.py` 启动。

旧 `scripts/mobile_bridge.py` 只保留固定相对路径兼容入口，加载本目录的 `bridge.py`；它不是第二份实现，也不接受外部模块或运行时路径。独立插件入口只声明 `model.invoke`，没有设备、网络、ADB 或私有文件资源权限；包内桥接源码的存在不会授予这些能力。

0.2.0 的 `ready` 仅覆盖 `device.plan`。设备观察、操作、录屏、队列与旧配置仍需后续受控代理迁移，不能将规划器验收视为手机操作验收。
