# 音乐执行与双格式交付（2026-10-25）

本轮修复最初请求只回复“我写首……这就安排”却没有调用本地生成的漏洞。原来的执行承诺检查只匹配有限表达，漏掉了这句话。现在保留快速检查，并由配置的语言模型补做语义核验；确认承诺但无真实任务时，将执行缺口交还主模型重新决策，最多纠正两次。核验服务失败时不擅自创建歌曲，而是明确记录失败。

生成工具新增 title，模型按用户语义自拟具体歌名，拒绝通用占位名称。新生成原音频命名为 `大肥鱼原创歌曲-{歌曲名}.{实际扩展名}`。历史任务没有 title 时使用兼容名称，不修改已发出的微信消息。

交付支持 voice / file / both。默认完整拆分语音；明确只要文件则文件；既要演唱又要文件则 both。后者将语音与原文件关联同一素材，并以实际已准备附件列表保留全部交付顺序。未提交的同会话媒体等待前一媒体结束，再按已配置随机间隔发送；抽取的等待截止时间持久化，重启后不重抽。已提交原生任务仍按原任务查询回执。

真实模型语义验证通过三个请求：两分钟下班中文歌→120秒/voice/《下班的风》；演唱并发文件→60秒/both/《下班就去看海》；只要文件→60秒/file/《夜风慢慢》。该验证使用模拟生成服务和微信传输，只证明真实模型选参、提交和任务落盘，不产生新歌，不向微信发测试消息。
